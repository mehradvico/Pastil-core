# «آنلاینم» برای مشاوره آنلاین — راهنمای کامل اپ فلاتر (نماینده + کاربر) — ۱۴۰۵/۰۷/۰۶

این سند فقط طرف اپ فلاتر است (هم بخش نماینده/دکتر، هم بخش کاربر خریدار). طرف وب‌اپ در `webapp/docs/CONSULTATION_ONLINE_FA.md` است. کد بک‌اند در `Application/Services/CompanionSrvs/ConsultationOnlineSrv/*`.

## ۱. چرا این ویژگی ساخته شد

کاربر هر ساعتی (مثلاً ۲ بامداد) وارد صفحه‌ی خرید مشاوره می‌شد و هیچ نشانه‌ای نبود که الان کسی از کلینیک پاسخگوی چت/تماس است یا نه. پکیج را می‌خرید و بعد می‌دید ساعت‌ها منتظر مانده. راه‌حل: دکتر/اپراتور یک دکمه دارد که با زدنش «الان من آنلاینم» را اعلام می‌کند و کاربر قبل از خرید یک چراغ سبز/خاکستری می‌بیند.

## ۲. مدل ذهنی که باید در اپ رعایت شود

- وضعیت آنلاین **شخصی** است، نه مال کل کلینیک. هر عضو تیم (دکتر/اپراتور) که در کلینیک عضویت فعال و تأییدشده دارد، خودش را روشن/خاموش می‌کند.
- نمایش به کاربر **تجمیعی** است: «کلینیک آنلاین است» یعنی **حداقل یک نفر** از اعضای فعال آن کلینیک الان روشن است.
- روشن‌کردن **همیشگی نیست**. هر بار که کاربر (نماینده) دکمه را می‌زند، سرور یک `expiresAt` سه‌ساعته می‌دهد. بعد از آن لحظه، حتی اگر کسی دستی خاموش نکرده باشد، سرور خودش آن را «آفلاین» حساب می‌کند. **این یعنی اپ نباید فرض کند وضعیتی که یک‌بار خوانده تا ابد معتبر است** — هر بار که صفحه باز می‌شود یا کاربر آن را می‌بیند، باید دوباره از سرور بخواند، نه از حافظه‌ی محلی.
- خاموش‌کردن دستی فوری است (بدون تأخیر).

## ۳. مسیرهای API

### ۳.۱ نماینده (دکتر/اپراتور) — Area: Companion، نیاز به لاگین
هر عضو فعال کلینیک (نه فقط مالک) مجاز است، برخلاف مسیر پکیج‌های مشاوره که فقط مالک است.

**خواندن وضعیت خودم**
```
GET /api/Companion/ConsultationOnline
GET /api/Companion/ConsultationOnline?companionId=123
```
`companionId` اختیاری است؛ فقط وقتی لازم می‌شود که همین کاربر عضو فعال **بیش از یک** کلینیک باشد (نادر، ولی ممکن). اگر نفرستید و کاربر چند عضویت دارد، سرور وضعیت را از **همه‌ی** عضویت‌هایش با هم حساب می‌کند (اگر حتی یکی آنلاین باشد، `online:true`).

پاسخ موفق:
```json
{
  "isSuccess": true,
  "code": 0,
  "messages": [],
  "data": { "online": true, "expiresAt": "2026-09-27T05:00:00" }
}
```
وقتی آفلاین است یا هرگز روشن نکرده:
```json
{ "isSuccess": true, "data": { "online": false, "expiresAt": null } }
```
وقتی کاربر اصلاً عضو فعال/تأییدشده‌ی هیچ کلینیکی نیست (مثلاً حساب پزشک هنوز تأیید عضویت نشده یا از کلینیک اخراج شده):
```json
{ "isSuccess": false, "messages": [{"item1": "شما به این بخش دسترسی ندارید", "item2": ""}], "data": null }
```
این حالت را در UI به‌صورت «شما هنوز عضو فعال هیچ کلینیکی نیستید» نشان دهید، نه خطای عمومی.

**روشن/خاموش‌کردن**
```
PUT /api/Companion/ConsultationOnline
Content-Type: application/json

{ "online": true, "companionId": null }
```
- `online`: الزامی، `true` یا `false`.
- `companionId`: اختیاری؛ همان قاعده‌ی بالا. اگر بدهید، فقط همان یک عضویت را عوض می‌کند؛ اگر ندهید، **همه‌ی عضویت‌های فعال کاربر** را با هم عوض می‌کند (برای اکثر دکترها که فقط یک کلینیک دارند فرقی ندارد).
- پاسخ دقیقاً هم‌شکل `GET` است و همان لحظه `expiresAt` جدید (یا `null` اگر خاموش کردید) برمی‌گرداند. **UI را از همین پاسخ به‌روزرسانی کنید**، نیازی به `GET` دوباره نیست.
- خطای احتمالی: همان پیام «دسترسی ندارید» اگر کاربر عضو فعال نباشد یا عضویتش بین درخواست خواندن و نوشتن غیرفعال شده باشد.

### ۳.۲ کاربر (خریدار) — Area: EndUser، نیاز به لاگین
```
GET /api/EndUser/ConsultationOnline?companionId=123
```
```json
{ "isSuccess": true, "data": { "online": true, "onlineStaffCount": 2, "expiresAt": null } }
```
- `expiresAt` در این پاسخ همیشه `null` است (فقط در پاسخ نماینده معنی دارد؛ در پاسخ عمومی از آن استفاده نکنید).
- `onlineStaffCount`: تعداد نفراتی که همین الان آنلاین‌اند. می‌توانید نادیده بگیرید یا برای متنی مثل «۲ نفر پاسخگو» استفاده کنید.

### ۳.۳ میان‌بر — از قبل موجود، فقط یک فیلد جدید
```
GET /api/EndUser/ConsultationPackage?companionId=123
```
همین مسیر قدیمی (لیست پکیج‌های مشاوره) حالا هر آیتمش یک فیلد اضافه دارد:
```json
{
  "isSuccess": true,
  "data": [
    { "id": 9, "companionId": 123, "channelId": 3, "durationMinutes": 45, "price": 200000,
      "name": "مشاوره فوری", "description": "...", "picture": null, "sortOrder": 0,
      "companionOnline": true }
  ]
}
```
`companionOnline` برای همه‌ی آیتم‌های یک کلینیک یک مقدار یکسان دارد (چون به کلینیک مربوط است، نه به پکیج). **اگر صفحه‌ی خرید همین حالا این مسیر را صدا می‌زند، دیگر لازم نیست مسیر ۳.۲ را جدا صدا بزنید** — کافی است از اولین آیتم لیست بخوانید. اگر لیست خالی بود (کلینیک پکیج فعالی ندارد)، اصلاً بحث آنلاین‌بودن مطرح نیست.

## ۴. فلوی کامل — نماینده (دکتر/اپراتور)

1. صفحه‌ی پروفایل نماینده باز می‌شود ← `GET /api/Companion/ConsultationOnline` بزنید (نه فرض بر آخرین حالت محلی).
2. اگر `online:true`، سوییچ روشن و کنارش «تا ساعت HH:mm آنلاین» (از `expiresAt`، به وقت محلی تبدیل کنید) نشان دهید.
3. کاربر سوییچ را می‌زند:
   - روشن‌کردن: `PUT {online:true}` ← فوراً UI را با `expiresAt` پاسخ آپدیت کنید؛ toast «برای ۳ ساعت آینده آنلاین شدید».
   - خاموش‌کردن: `PUT {online:false}` ← toast «آفلاین شدید».
4. **مهم:** اگر صفحه باز می‌ماند (کاربر اپ را می‌بندد نه، ولی صفحه در فورگراند است)، هر چند دقیقه یک‌بار `GET` را دوباره بزنید یا حداقل یک تایمر محلی بگذارید که وقتی `now >= expiresAt` رسید، سوییچ را خودش خاموش نشان دهد (فقط نمایشی؛ سرور خودش همان لحظه واقعی را حساب می‌کند، شما فقط UI را هماهنگ نگه می‌دارید).
5. اگر نماینده می‌خواهد بیشتر از ۳ ساعت آنلاین بماند، باید دوباره دکمه را بزند. **auto-renew خودکار در بک‌اند وجود ندارد.** اگر محصول تصمیم بگیرد اپ خودش هر ۲ ساعت یک‌بار (پیش از انقضا) بی‌صدا `PUT {online:true}` را برای تمدید بزند، این تصمیم فقط سمت اپ است؛ بک‌اند تغییری لازم ندارد.
6. اگر نماینده عضو دو کلینیک است (نادر): دکمه باید مشخص کند برای کدام کلینیک است؛ `companionId` را بفرستید. اگر این حالت را در فاز اول پشتیبانی نمی‌کنید، همیشه بدون `companionId` بفرستید (هر دو کلینیک با هم روشن/خاموش می‌شوند) و در طراحی توضیح ندهید (چون اکثریت قریب‌به‌اتفاق تک‌کلینیکی‌اند).

### پیشنهاد UI (نماینده)
- محل: پروفایل نماینده یا بالای داشبورد، کنار نام کلینیک.
- عنصر: سوییچ + نقطه‌ی رنگی (سبز روشن / خاکستری) + برچسب «من آنلاینم برای مشاوره».
- زیرنویس وقتی روشن است: «تا ⏰ HH:mm».
- اختیاری: بج کوچک روی آیکن مشاوره در ناوبری وقتی آنلاین است.

## ۵. فلوی کامل — کاربر (خریدار)

1. کاربر وارد صفحه‌ی خرید مشاوره‌ی یک کلینیک می‌شود.
2. لیست پکیج‌ها را همان‌طور که قبلاً می‌گرفتید بگیرید؛ از پاسخ همان مسیر (`companionOnline` روی هر آیتم) وضعیت را بخوانید.
3. بالای لیست یا کنار نام کلینیک:
   - `companionOnline:true` → نقطه‌ی سبز + «هم‌اکنون پاسخگو» (یا «۲ نفر آنلاین» با `onlineStaffCount` اگر مسیر ۳.۲ را جدا زدید).
   - `companionOnline:false` → نقطه‌ی خاکستری + «هم‌اکنون آفلاین — ممکن است دیرتر پاسخ داده شود».
4. **این وضعیت مانع خرید نیست.** کاربر همچنان می‌تواند وقتی آفلاین است هم بخرد (چون شاید بخواهد صبح جواب بگیرد)؛ فقط شفافیت می‌دهد. قفل‌کردن خرید هنگام آفلاین‌بودن یک تصمیم محصول جداست که فعلاً پیاده نشده — اگر خواستید، جدا مطرح کنید.
5. این وضعیت **زنده نیست** (وب‌سوکت/پوش ندارد)؛ فقط لحظه‌ی باز کردن صفحه خوانده می‌شود. اگر کاربر مدتی روی صفحه بماند، تا رفرش نکند وضعیت به‌روز نمی‌شود؛ اگر می‌خواهید زنده باشد باید pull-to-refresh یا تایمر دوره‌ای در اپ بگذارید (بک‌اند push جدیدی برای این ندارد).

## ۶. حالت‌های لبه و اشتباهات رایج

| حالت | رفتار درست |
|---|---|
| نماینده هیچ‌وقت دکمه را نزده | `GET` می‌دهد `online:false, expiresAt:null` — این حالت پیش‌فرض طبیعی بعد از دیپلوی است، خطا نیست. |
| نماینده روشن کرده و ۳ ساعت گذشته، دکمه را نزده | سرور خودش `false` حساب می‌کند؛ در `GET` بعدی `online:false` می‌آید حتی اگر دیتابیس هنوز فلگ قدیمی را نگه داشته (محاسبه‌ی انقضا سمت سرور است، نیازی به cron نیست). |
| دو دکتر یک کلینیک، یکی روشن یکی خاموش | برای کاربر `companionOnline:true` (کافی است یکی آنلاین باشد). برای هر دکتر، `GET` خودش فقط وضعیت **خودش** را می‌دهد، نه وضعیت همکارش. |
| نماینده عضویتش در کلینیک غیرفعال/لغو شده بعد از اینکه آنلاین بود | دیگر در `GET`/`PUT` شمرده نمی‌شود (سرور فقط عضویت فعال و تأییدشده را می‌بیند)؛ برای کاربر هم دیگر حساب نمی‌شود. |
| کلینیک اصلاً پکیج مشاوره‌ی فعال ندارد | بحث آنلاین‌بودن بی‌ربط است؛ اصلاً UI مشاوره را نشان ندهید (رفتار قبلی). |
| کاربر کلینیکی را باز می‌کند که هیچ عضوی ندارد | `companionOnline:false`, `onlineStaffCount:0`. |

## ۷. چک‌لیست تست دستی

1. حساب دکتر: پروفایل باز کن ← سوییچ خاموش.
2. سوییچ را روشن کن ← toast + زیرنویس زمان.
3. با حساب کاربر همان کلینیک را باز کن ← نقطه‌ی سبز.
4. دکتر سوییچ را خاموش کند ← کاربر صفحه را رفرش کند ← نقطه‌ی خاکستری.
5. (تست انقضا، نیاز به صبر یا تغییر ساعت تست سرور) بعد از ۳ ساعت بدون خاموش‌کردن دستی ← هم برای دکتر و هم برای کاربر خودکار آفلاین.
6. کلینیکی با دو دکتر: یکی روشن کند، کاربر باید سبز ببیند؛ آن یکی هم خاموش کند وقتی دیگری هنوز روشن است، باید همچنان سبز بماند.
7. حساب کاربری که عضو هیچ کلینیکی نیست ← باز کردن صفحه‌ی سوییچ باید پیام «عضو فعال نیستید» بدهد، نه کرش.
