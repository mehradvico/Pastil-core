# لیست عمومی «اعضای مرکز» (کلینیک / مربی) — راهنمای اپ

**مخاطب:** توسعه‌دهنده‌ی اپ (کارت «اعضای مرکز» در صفحه‌ی پروفایل کلینیک و مربی)
**تاریخ:** ۱۴۰۵/۰۸/۰۳ (2026-10-25)
**وضعیت بک‌اند:** کد و تست آماده است، **هنوز دیپلوی نشده**. مایگریشن و تغییر دیتابیس **ندارد**؛ فقط دیپلوی Api لازم است.
**در جواب:** `Pastil-Center-Members-Backend-Request.md`

---

## ۱) اندپوینت‌ها (نام مسیر همان پیشنهاد شما)

| متد | مسیر |
|---|---|
| GET | `/api/Clinic/{id}/Members?page=&pageSize=` |
| GET | `/api/Coach/{id}/Members?page=&pageSize=` |

- **دسترسی:** عمومی، بدون توکن؛ دقیقاً مثل `GET /api/Clinic/{id}`.
- `id` همان شناسه‌ی `Clinic` / `Coach` است، **نه** `legacyCompanionId`.
- `page` از ۱ شروع می‌شود (پیش‌فرض ۱). `pageSize` پیش‌فرض و حداکثرش ۵۰ است؛ عدد بزرگ‌تر به ۵۰ محدود می‌شود و صفر یا منفی یعنی پیش‌فرض.
- **cache:** لیست هر مرکز ۶۰ ثانیه روی سرور cache می‌شود. پس عضوی که تازه اضافه یا حذف شده، تا حداکثر یک دقیقه بعد در لیست دیده می‌شود.

## ۲) پاسخ
HTTP 200 با قالب همیشگی `{ isSuccess, code, messages, data }`:

```json
{
  "isSuccess": true,
  "code": 0,
  "messages": [],
  "data": [
    {
      "id": 1001,
      "fullName": "علی رضایی",
      "picture": { "id": 55, "url": "...", "guidName": "...", "extension": ".jpg", "orginalName": "...", "baseUrl": null },
      "roleId": 1,
      "roleTitle": "مدیر مرکز",
      "sortOrder": 1
    },
    {
      "id": 1042,
      "fullName": "سارا محمدی",
      "picture": null,
      "roleId": 2,
      "roleTitle": "واکسیناسیون، جراحی",
      "sortOrder": 2
    }
  ]
}
```

| فیلد | نوع | توضیح |
|---|---|---|
| `id` | number | شناسه‌ی **کاربرِ** عضو |
| `fullName` | string | نام و نام خانوادگی؛ اگر خالی بود «عضو تیم» |
| `picture` | object / null | عکس پروفایل کاربر، با همان ساختار `picture` بقیه‌ی موجودیت‌ها (برای ساختن آدرس، `url` را مثل جاهای دیگر اپ استفاده کنید)؛ اگر عکس نداشت `null` |
| `roleId` | number | `1` = مالک / مدیر مرکز، `2` = عضو تیم |
| `roleTitle` | string | عنوان نقش به فارسی (بند ۳) |
| `sortOrder` | number | ترتیب نمایش (۱، ۲، ۳، …)؛ لیست از قبل به همین ترتیب مرتب است |

- اگر مرکز عضوی نداشت: `isSuccess: true` و `data: []` (خطا نیست). در عمل همیشه دست‌کم مالک در لیست هست.
- مرکزی که وجود ندارد، فعال نیست یا تأیید نشده: **HTTP 404** با `isSuccess: false`، دقیقاً مثل `{id}/Pictures` و `{id}/Zones`.

## ۳) جواب سؤال‌های شما
**نام مسیر:** همان `Members`.

**مالک در لیست هست؟** بله. مالک همیشه **اولین** آیتم است، با `roleId = 1` و `roleTitle = «مدیر مرکز»`.

**`roleTitle` از کجا می‌آید؟** در سیستم فعلاً «نقش» جداگانه برای پرسنل ثبت نمی‌شود. برای همین عنوان نقش این‌طور ساخته می‌شود:
- مالک: «مدیر مرکز».
- پرسنل: نام خدمات مرکز که این عضو به آن‌ها وصل شده (حداکثر ۲ خدمت، جدا با «، »)؛ مثلاً «واکسیناسیون، جراحی».
- پرسنلی که به هیچ خدمتی وصل نشده: «عضو تیم».

اگر بعداً نقش ثابت (مثل «دامپزشک»، «پذیرش») لازم شد، باید ستون جدیدی اضافه شود و مالک هم بتواند آن را تنظیم کند. این کار جداگانه است. قالب پاسخ همین می‌ماند و فقط متن `roleTitle` عوض می‌شود.

## ۴) چه کسانی در لیست هستند
- مالک مرکز.
- پرسنلی که دعوت را **پذیرفته‌اند**، **فعال‌اند** و **حذف نشده‌اند**. دعوت‌های در انتظار، ردشده، غیرفعال یا حذف‌شده نمی‌آیند.
- کاربری که حسابش حذف یا غیرفعال شده نمی‌آید.
- ترتیب: اول مالک، بعد پرسنل به ترتیب زمان دعوت.

## ۵) حریم خصوصی
فقط نام، عکس و عنوان نقش برگردانده می‌شود. موبایل، ایمیل، کد ملی و هیچ اطلاعات دیگری در پاسخ **نیست**.

## ۶) کار سمت اپ
- `useClinicApi().pub.members(id)` ← `GET /api/Clinic/{id}/Members`، و برای مربی همین با `Coach`.
- اگر `data` خالی بود یا پاسخ 404 گرفتید، کارت را مخفی کنید.
- برای کارت فقط `fullName`، `picture` و `roleTitle` لازم است. وقتی `picture` برابر `null` است، آواتار پیش‌فرض نشان دهید.
