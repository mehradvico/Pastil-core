# راهنمای فنی — کدهای قلاده‌ی QR (PetTag) برای وب‌اپ

این مستند برای فرانت‌کار وب‌اپ نوشته شده تا بخش اسکن قلاده‌ی هوشمند رو پیاده کنه. هرچی لازمه — منطق، endpointها، نمونه‌ی JSON، خطاها — اینجا هست.

**آدرس پایه:** `https://api.pastil.pet`

همه‌ی پاسخ‌ها با همین ساختار برمی‌گردن (همیشه HTTP 200، موفقیت واقعی رو از `isSuccess` بخون):

```json
{ "isSuccess": true, "code": 0, "messages": [], "data": { ... } }
```

---

## ۱. تصویر کلی — دو حالت

روی هر قلاده یک QR چاپ شده که به یک URL مثل `https://app.pastil.pet/tag/{code}` اشاره می‌کنه (`code` یک رشته‌ی یکتای ۲۴ کاراکتری انگلیسیه، مثلاً `A2K9XQZ7...`).

وقتی کسی این QR رو اسکن می‌کنه و وارد صفحه‌ی `tag/{code}` وب‌اپ می‌شه، **همیشه اولین کار** اینه:

```
GET /api/PetTagPublic/{code}
```

(این endpoint عمومیه، نیازی به توکن/لاگین نداره — هرکسی، حتی بدون اکانت پاستیل، می‌تونه بزنه.)

پاسخ دو حالت داره:

### حالت الف) کد هنوز به هیچ پتی وصل نشده

```json
{
  "isSuccess": true,
  "data": { "claimed": false, "pet": null }
}
```

→ یعنی این قلاده هنوز فعال نشده. باید کاربر رو ببری سراغ **فلوی اتصال** (بخش ۲).

### حالت ب) کد قبلاً به یک پت وصل شده

```json
{
  "isSuccess": true,
  "data": {
    "claimed": true,
    "pet": {
      "name": "لوکی",
      "breedName": "پامرینین",
      "isMale": true,
      "pictureUrl": "https://file.pastil.pet/...",
      "ownerFirstName": "علی",
      "ownerLastName": "رضایی",
      "ownerMobile": "09123456789"
    }
  }
}
```

→ یعنی این قلاده مال یک پت گم‌شده‌ست. باید **مستقیم صفحه‌ی پروفایل عمومی پت** رو نشون بدی (بخش ۳) — این صفحه برای هرکسی که QR رو اسکن کرده باز می‌شه، چه اکانت پاستیل داشته باشه چه نه.

### خطای کد نامعتبر

اگه کد اصلاً وجود نداشته باشه یا غیرفعال شده باشه:

```json
{ "isSuccess": false, "messages": ["کد قلاده معتبر نیست."], "data": null }
```

---

## ۲. فلوی اتصال کد به پت (وقتی `claimed: false`)

این فلو خودش دو زیرحالت داره، بسته به اینکه کاربر از قبل توی پاستیل لاگینه یا نه.

### ۲.۱ کاربر لاگین نیست

مسیر معمولی ثبت‌نام/ورود پاستیل رو نشونش بده. **نکته‌ی مهم:** باید `code` رو جایی نگه‌داری (مثلاً query param یا `sessionStorage`) تا بعد از لاگین موفق، کاربر رو دوباره برگردونی به همین صفحه‌ی `tag/{code}` تا فلوی اتصال ادامه پیدا کنه — وگرنه کدی که اسکن کرده بود گم می‌شه.

### ۲.۲ کاربر لاگین است (یا تازه لاگین کرد و برگشته)

حالا باید ازش بپرسی «این کد رو به کدوم پتت وصل کنم؟». برای این کار:

**قدم ۱ — لیست پت‌های کاربر رو بگیر:**

```
GET /api/EndUser/UserPet
Authorization: Bearer <توکن کاربر>
```

پاسخ لیستی از پت‌های کاربره (`data.list`، هرکدوم حداقل `id` و `name` داره که برای ساخت لیست انتخاب لازمه).

**قدم ۲ — لیست پت‌هایی که از قبل کد دارن رو هم بگیر:**

```
GET /api/EndUser/PetTag/mine
Authorization: Bearer <توکن کاربر>
```

```json
{
  "isSuccess": true,
  "data": [
    { "userPetId": 41, "code": "B7K2...", "claimedDate": "2026-08-20T10:00:00" }
  ]
}
```

⚠️ **قانون مهم کسب‌وکار:** هر پت فقط و فقط **یک‌بار، برای همیشه** می‌تونه به یک کد قلاده وصل بشه — دیگه هیچ‌وقت نمی‌شه کد دومی رو به همون پت وصل کرد (حتی اگه کد اولی گم شده باشه). پس توی فرم انتخاب پت، هر پتی که `id`ش توی نتیجه‌ی این endpoint باشه رو **غیرفعال کن یا با یک نشان «قبلاً کد داره» جدا کن** — تا کاربر روش کلیک نکنه و با خطا مواجه نشه. (بک‌اند این قانون رو هم مستقل بررسی می‌کنه، پس حتی اگه فرانت این چک رو نداشته باشه، سرور اجازه‌ی دوباره‌وصل‌شدن رو نمی‌ده — ولی تجربه‌ی کاربری بهتره اگه از همون اول غیرفعال باشه.)

**قدم ۳ — بعد از انتخاب پت، وصلش کن:**

```
POST /api/EndUser/PetTag/claim
Authorization: Bearer <توکن کاربر>
Content-Type: application/json

{ "code": "A2K9XQZ7...", "userPetId": 41 }
```

پاسخ موفق:

```json
{ "isSuccess": true, "data": null }
```

بعد از این، این کد برای همیشه مال همین پته — یک پیام موفقیت نشون بده (مثلاً «قلاده با موفقیت برای لوکی فعال شد») و کاربر رو ببر به پروفایل پتش.

---

## ۳. نمایش پروفایل عمومی پت (وقتی `claimed: true`)

همون داده‌ای که از `GET /api/PetTagPublic/{code}` (بخش ۱) گرفتی رو مستقیم نشون بده — نیازی به هیچ درخواست یا لاگین دیگه‌ای نیست. طراحی پیشنهادی صفحه:

- عکس + اسم پت، نژاد، جنسیت
- یک باکس واضح «صاحب این پت: {ownerFirstName} {ownerLastName}» + شماره‌ی `ownerMobile` (با دکمه‌ی تماس مستقیم `tel:`)
- این صفحه باید **بدون نیاز به لاگین** برای همه باز بشه — چون کسی که پت گم‌شده رو پیدا کرده، لزوماً کاربر پاستیل نیست.

اگه `ownerMobile`/`ownerFirstName` خالی بود (یعنی مالک پروفایلش رو کامل پر نکرده)، یک حالت جایگزین ملایم نشون بده (مثلاً فقط اسم پت، بدون بخش تماس).

---

## ۴. جدول خطاهای رایج

| کجا | پیام خطا | یعنی چی |
|---|---|---|
| هر سه endpoint | `کد قلاده معتبر نیست.` | کد وجود نداره، غلط تایپ شده، یا غیرفعال شده |
| `claim` | `این کد قلاده قبلاً به یک پت متصل شده است.` | یکی دیگه (یا خود کاربر با درخواست تکراری) قبلاً همین کد رو claim کرده |
| `claim` | `این پت قبلاً به یک کد قلاده متصل شده و امکان اتصال کد جدید به آن وجود ندارد.` | پتی که انتخاب شده از قبل کد داره — دقیقاً همون چیزی که با چک قدم ۲ باید از قبل جلوش رو بگیری |
| `claim` | `AccessDenied` | `userPetId` فرستاده‌شده مال یک کاربر دیگه‌ست (نباید توی حالت عادی پیش بیاد، فقط دفاعیه) |

---

## ۵. خلاصه‌ی کل مسیر (فلوچارت متنی)

```
اسکن QR → GET /api/PetTagPublic/{code}
│
├─ claimed = true
│   └─ نمایش مستقیم پروفایل عمومی پت (بخش ۳) — بدون لاگین
│
└─ claimed = false
    ├─ کاربر لاگین نیست
    │   └─ مسیر ورود/ثبت‌نام → بعد از موفقیت برگرد به همین tag/{code}
    │
    └─ کاربر لاگین است
        ├─ GET /api/EndUser/UserPet          (لیست پت‌ها)
        ├─ GET /api/EndUser/PetTag/mine      (پت‌های قبلاً کد‌دار — غیرفعال کن)
        ├─ کاربر یک پت بدون‌کد انتخاب می‌کند
        └─ POST /api/EndUser/PetTag/claim → موفقیت → نمایش پروفایل پت
```
