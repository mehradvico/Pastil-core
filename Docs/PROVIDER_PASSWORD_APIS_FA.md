# API رمز عبور ارائه‌دهنده (تغییر رمز و فراموشی رمز) — مستند اپ نماینده

این سه API **فقط برای ارائه‌دهنده‌ها** (کاربری که در پاستیل «ارائه‌دهنده» ثبت شده) کار می‌کنند. برای هر کاربر دیگری (مشتری، ادمین، نماینده‌ای که ارائه‌دهنده نیست) و برای شماره‌ی ثبت‌نشده، **همان پاسخ خطای یکسان** برمی‌گردد؛ پس اپ نمی‌تواند و نباید بفهمد شماره وجود دارد یا نه، و پیام عمومی نشان بدهد (مثلاً «شماره یا اطلاعات واردشده معتبر نیست»).

آدرس پایه: `https://<api-host>/api/Account` — هیچ‌کدام توکن نمی‌خواهند (ورود نشده هم کار می‌کنند)، ولی **rate limit** دارند.

## قالب پاسخ همه‌ی endpointها
HTTP همیشه ۲۰۰ است؛ موفقیت را از `isSuccess` بخوانید (نه از status code).
```json
{ "isSuccess": false, "code": 0, "messages": [ { "item1": "متن فارسی خطا", "item2": "نام فیلد مرتبط" } ], "data": null }
```
`messages[0].item1` را مستقیم به کاربر نشان دهید؛ `item2` نام فیلد برای نمایش خطا کنار ورودی است (مثلاً `NewPassword`، `Code`). اگر HTTP ‎429 آمد یعنی rate limit (پایین).

## ۱) تغییر رمز (کاربر رمز فعلی را می‌داند)
`POST /api/Account/changepassword`
```json
{ "mobile": "09123456789", "oldPassword": "رمز فعلی", "newPassword": "رمز جدید" }
```
- `mobile`: موبایل یا ایمیل حساب. ارقام فارسی/عربی قبول می‌شود (سرور به انگلیسی تبدیل می‌کند).
- هر سه فیلد الزامی‌اند. رمز جدید نباید با رمز فعلی یکی باشد و باید قانون رمز سرور را رعایت کند (خطا با `item2 = "NewPassword"` و پیام «رمز وارد شده صحیح نیست»).
- شمارش تلاش ناموفق رمز فعلی: بعد از **۵ بار اشتباه، ۱۵ دقیقه** قفل می‌شود (پیام «تلاش زیاد، N دقیقه دیگر»).

**موفق:** `isSuccess: true` و در `data` **توکن جدید** (مثل خروجی signin):
```json
{ "isSuccess": true, "data": { "token": "...", "refreshToken": "...", "tokenExp": "...", "refreshTokenExp": "...", "userId": 12, "firstName": "...", "lastName": "..." } }
```
مهم: **همه‌ی نشست‌های قبلی این کاربر باطل می‌شوند** (روی سایر دستگاه‌ها هم)؛ اپ باید توکن قبلی را دور بریزد و توکن جدید را ذخیره کند (همین‌جا دوباره ورود لازم نیست).

خطاها (همه `isSuccess:false`): ورودی ناقص/رمز جدید برابر قدیمی/رمز قدیمی اشتباه/غیرارائه‌دهنده/کاربر پیدا نشد ← «دیتا اشتباه است»؛ رمز جدید ضعیف ← «رمز وارد شده صحیح نیست».

## ۲) فراموشی رمز (۳ مرحله)

### مرحله ۱ — درخواست کد: `POST /api/Account/forgetpassword`
```json
{ "mobile": "09123456789" }
```
یا `{ "email": "a@b.com" }` — **دقیقاً یکی** از موبایل/ایمیل؛ اگر هر دو یا هیچ‌کدام فرستاده شود خطا می‌گیرید. کد فقط به همان شناسه‌ی واردشده ارسال می‌شود (پیامک یا ایمیل).

موفق: `isSuccess: true` با پیام «کد بازیابی پیامک شد/ایمیل شد». طول کد (۴ تا ۸ رقم؛ معمولاً ۴) را برای تعداد کادرها از **پاسخ ارسال OTP** نمی‌گیرید (این endpoint آن را برنمی‌گرداند) — کادر ورود را قابل تنظیم یا ۴ تا ۸ رقمی بگیرید.
خطا: غیرارائه‌دهنده/ناشناس/ورودی نامعتبر ← «دیتا اشتباه است». محدودیت ارسال کد برای هر گیرنده: **۱ کد در ۲ دقیقه و ۵ کد در ساعت**؛ بعد از ۳ درخواست پشت‌سرهم ۱۰ دقیقه صبر لازم است (پیام آماده در `messages`). دکمه‌ی «ارسال دوباره» را حداقل ۲ دقیقه غیرفعال کنید.

### مرحله ۲ — تأیید کد: `POST /api/Account/CheckOtp`
```json
{ "mobile": "09123456789", "code": "1234" }
```
(یا با `email`). کد **۳ دقیقه** اعتبار دارد؛ **۴ بار اشتباه ← ۱۰ دقیقه قفل**. اشتباه‌زدن، کد را عوض می‌کند (باید دوباره درخواست کد بدهید). موفق: `isSuccess: true`. فقط بعد از این مرحله reset کار می‌کند و تأیید **۵ دقیقه** اعتبار دارد.

### مرحله ۳ — رمز جدید: `POST /api/Account/resetpassword`
```json
{ "mobile": "09123456789", "code": "1234", "password": "رمز جدید" }
```
- `mobile` (یا `email`) **همان شناسه‌ای** باشد که کد برایش فرستاده و تأیید شد؛ **دقیقاً یکی** فرستاده شود (فرستادن هر دو رد می‌شود).
- `code` همان کدی که در مرحله ۲ تأیید شد. **یک‌بار مصرف است**: بعد از reset موفق همان کد دیگر کار نمی‌کند.
- موفق: مثل changepassword، `data` = توکن جدید و **همه‌ی نشست‌های قبلی باطل** می‌شوند؛ اپ مستقیم با توکن جدید وارد شود. قفل «تلاش زیاد رمز» حساب هم باز می‌شود.
- خطاها: کد تأییدنشده/منقضی/اشتباه ← «کد وارد شده اشتباه است» (`item2 = "Code"`)؛ رمز ضعیف ← «رمز وارد شده صحیح نیست» (`item2 = "Password"`)؛ غیرارائه‌دهنده ← «دیتا اشتباه است».

نمودار: `forgetpassword` → کاربر کد را وارد می‌کند → `CheckOtp` → فرم رمز جدید → `resetpassword` → ورود با توکن برگشتی.

## محدودیت تعداد درخواست (HTTP 429)
- `changepassword` / `forgetpassword` / `resetpassword`: مجموعاً **۵ درخواست در ۱۰ دقیقه برای هر IP**.
- `CheckOtp`: limiter جدا (`OtpVerify`).
با ۴۲۹ پیام «کمی بعد دوباره تلاش کنید» نشان دهید و دکمه را موقتاً غیرفعال کنید؛ حلقه‌ی تلاش مجدد خودکار نزنید.

## قانون رمز
قانون قدرت رمز را سرور از تنظیم `PasswordRegix` می‌گیرد؛ اپ حداقل‌های ساده (خالی نبودن، ≥ ۸ نویسه، ترکیب حرف و عدد) را پیش‌اعتبارسنجی کند ولی قضاوت نهایی با سرور است و پیامش را همان‌طور نمایش دهید.

## چه چیزی عوض شده (برای اطلاع)
این endpointها قبلاً برای همه‌ی کاربران باز بودند. حالا: فقط ارائه‌دهنده؛ فقط یک شناسه در forget/reset؛ کد reset یک‌بار مصرف؛ در reset، شناسه‌ی OTP و حساب هدف باید یکی باشد (قبلاً می‌شد موبایل خود را با ایمیل دیگری ترکیب کرد)؛ ورودی تهی در changepassword دیگر کاربر دیگری را پیدا نمی‌کند. تست: `ProviderPasswordTests`.
