# ورود به پنل/اپ نماینده — چه کسی اجازه دارد؟ (مستند اپ نماینده)

**قانون سرور:** همه‌ی endpointهای `api/Companion/*` فقط برای کاربری باز است که **حداقل یکی** از این‌ها را دارد:

| شرط | توضیح |
|---|---|
| ارائه‌دهنده (Provider) | روی کاربر یک ارائه‌دهنده‌ی حذف‌نشده ثبت شده است |
| مالک یک مرکز | نمایندگی، کلینیک، مربی یا آرایشگاهِ حذف‌نشده — **حتی اگر هنوز «در حال بررسی» (تأییدنشده) باشد** (باید بتواند وضعیت درخواستش را ببیند و ویرایش کند) |
| عضو تیم یک مرکز | عضو **فعال** و **پذیرفته‌شده** (`userAccept = true`) تیم نمایندگی/کلینیک/مربی/آرایشگاه. دعوت‌نامه‌ی هنوز قبول‌نشده یا عضو غیرفعال‌شده حساب نمی‌شود |

ادمین سیستم همیشه مجاز است. **مشتری عادی** که هیچ‌کدام را ندارد روی هر endpoint ناحیه‌ی Companion پاسخ **HTTP 403** می‌گیرد:
```json
{ "isSuccess": false, "messages": [ { "item1": "دسترسی ندارید", "item2": "" } ] }
```
(بقیه‌ی endpointها مثل همیشه HTTP 200 با `isSuccess`؛ ۴۰۳ فقط برای همین ورودِ غیرمجاز است.)

## کاری که اپ نماینده باید بکند
۱. کاربر مثل همیشه وارد شود (`signin`) و توکن بگیرد. **ورود موفق = اجازه‌ی ورود به پنل نیست.**
۲. فوراً بپرسید (توکن لازم است، همیشه HTTP 200):
```
GET /api/EndUser/CompanionPanelAccess
```
```json
{ "isSuccess": true, "data": { "canEnter": true, "isProvider": true, "ownsCenter": false, "isStaff": false } }
```
۳. اگر `canEnter = false`: **پنل نماینده را باز نکنید**؛ توکن را نگه دارید ولی کاربر را به اپ مشتری برگردانید (یا پیام «این حساب نمایندگی یا ارائه‌دهنده ندارد؛ برای ثبت‌نام به قسمت درخواست نمایندگی بروید» نشان دهید). هیچ صفحه‌ی نمایندگی‌ای نباید برایش بالا بیاید.
۴. اگر `canEnter = true` پنل را باز کنید. از فیلدهای دیگر برای نمایش استفاده کنید: `isProvider` (منوی ارائه‌دهنده/تسویه)، `ownsCenter` (مدیریت مرکز)، `isStaff` (عضو تیم، دید محدودتر).
۵. هر بار هر endpoint ناحیه‌ی Companion ۴۰۳ داد (مثلاً دسترسی کاربر بعداً غیرفعال شد)، به جای نمایش خطای خام، دوباره `CompanionPanelAccess` را بپرسید و در صورت `canEnter=false` از پنل خارج کنید.

## نکته‌های رفتاری
- بعد از اینکه ادمین مرکز یا ارائه‌دهنده را تأیید/ثبت کرد یا عضو دعوت را پذیرفت، دسترسی **حداکثر ~۶۰ ثانیه** بعد فعال می‌شود (نتیجه‌ی مثبت کوتاه کش می‌شود) و **نیازی به خروج/ورود دوباره نیست** — فیلتر از دیتابیس می‌خواند، نه از توکن. `canEnter=false` هیچ‌وقت کش نمی‌شود.
- عضو غیرفعال‌شده/حذف‌شده: تا ~۶۰ ثانیه ممکن است هنوز بتواند وارد شود، بعد از آن ۴۰۳ می‌گیرد.
- پذیرفتن دعوت عضویت و ثبت درخواست نمایندگی مسیرهای `EndUser` هستند و برای کاربر عادی باز می‌مانند (جزو ناحیه‌ی Companion نیستند).
- این قانون جدا از «ارائه‌دهنده بودن برای تغییر/فراموشی رمز» است (`PROVIDER_PASSWORD_APIS_FA.md`: فقط Provider).
- لایه‌ی قدیمی «عضویت ناحیه» (`AreaMembership` در حالت Audit) برای Companion دیگر هیچ‌وقت رد نمی‌کند؛ اجرای قاعده با این فیلتر است. اگر روزی `Security:AreaPolicyMode=Enforce` شد، Companion را تحت تأثیر قرار نمی‌دهد.
