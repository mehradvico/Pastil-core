# پانسیون آموزشی مربی — سند اپ مشتری (وب‌اپ و اپ کاربر) — ۱۴۰۵/۰۸/۱۴

> مخاطب: تیم وب‌اپ / اپ کاربر. بک‌اند و پنل ادمین ساخته شده‌اند؛ این سند همه‌ی چیزی است که سمت مشتری باید پیاده شود.
> همه‌ی پاسخ‌ها HTTP 200 با قالب `{ isSuccess, code, messages, data }` هستند. موفقیت را فقط با `isSuccess` بسنجید و در خطا `messages[0]` را نشان دهید.
> مبلغ‌ها **تومان** هستند. تاریخ‌ها به وقت محلی سرور (ایران) و بدون timezone هستند: `"2026-11-10T10:00:00"`.

---

## ۱. خلاصه

مربی فقط **سه** نحوه‌ی ارائه دارد:

| `mode` | `modeName` | عنوان در UI |
|---|---|---|
| **38** | `in-person` | **پانسیون آموزشی (در مرکز)** |
| **39** | `in-place` | **در محل مشتری** |
| **37** | `online` | **آنلاین** |

«در محل مربی» یا «حضوری» دیگر نباید جایی دیده شود.

**پانسیون آموزشی:** مربی همه‌چیز را از قبل تعیین کرده است: هزینه‌ی دوره، پیش‌پرداخت، **تعداد روز پانسیون** و **هزینه‌ی پانسیون روزانه**.
کاربر فقط **دوره را انتخاب می‌کند و روزی که پت را تحویل می‌دهد** (داخل ساعت کاری مربی). تعداد روز را کاربر انتخاب **نمی‌کند**.

| | فرمول |
|---|---|
| مبلغ کل | هزینه‌ی دوره + (پانسیون روزانه × تعداد روز) |
| **پرداخت آنلاین** | **فقط پیش‌پرداختی که مربی تعیین کرده** |
| پرداخت در مرکز | مبلغ کل − پیش‌پرداخت (باقی‌مانده‌ی دوره + کل پانسیون روزانه) |
| تحویل گرفتن پت | روز تحویل دادن + تعداد روز (همان ساعت) |

> مثال: دوره ۱۰٬۰۰۰٬۰۰۰، پیش‌پرداخت ۲٬۰۰۰٬۰۰۰، پانسیون ۶۰ روز × ۵۰۰٬۰۰۰
> → کل ۱۰٬۰۰۰٬۰۰۰ + ۳۰٬۰۰۰٬۰۰۰ = **۴۰٬۰۰۰٬۰۰۰**؛ آنلاین **۲٬۰۰۰٬۰۰۰**؛ در مرکز **۳۸٬۰۰۰٬۰۰۰**.
> اگر تحویل ۱۰ آبان ساعت ۱۰ باشد، تحویل گرفتن ۹ دی ساعت ۱۰ است.

## ۲. صفحه‌ی پروفایل مربی

### ۲-۱. اطلاعات مربی
`GET /api/Coach/{id}`

| فیلد | معنی | UI |
|---|---|---|
| `serviceInPerson` | پانسیون آموزشی دارد | نشان «پانسیون آموزشی (در مرکز)» |
| `serviceAtHome` | در محل مشتری | نشان «در محل مشتری» |
| `serviceOnline` | آنلاین | نشان «آنلاین» |
| `boardingCapacity` | تعداد پت مقیم هم‌زمان؛ **۰ = بدون سقف** | اختیاری: «ظرفیت پانسیون: ۳ پت». اگر ۰ است چیزی ننویسید |

### ۲-۲. دوره‌ها (خدمت‌ها و بسته‌ها)
`GET /api/Coach/{id}/Services` → `data[].packages[].types[]`

ردیف پانسیون آموزشی:
```json
{ "id": 91, "mode": 38, "modeName": "in-person",
  "price": 10000000, "prePaymentPrice": 2000000,
  "stayDays": 60, "dailyPrice": 500000, "sessionCount": null }
```

| فیلد | معنی |
|---|---|
| `price` | **هزینه‌ی دوره** |
| `prePaymentPrice` | **پیش‌پرداخت** = تنها مبلغی که آنلاین گرفته می‌شود؛ ۰ یعنی کل مبلغ (دوره + پانسیون) آنلاین پرداخت می‌شود |
| `stayDays` | **تعداد روز پانسیون** که مربی تعیین کرده |
| `dailyPrice` | **هزینه‌ی پانسیون روزانه**؛ `null` = پانسیون رایگان (فقط دوره) |
| `sessionCount` | فقط برای ۳۹ |

**ردیف ۳۸ با `stayDays`** یعنی پانسیون واقعی (اقامت چندروزه). ردیف ۳۸ **بدون** `stayDays` یک بسته‌ی قدیمی است و مثل یک نوبت ساعتی رزرو می‌شود (بخش ۷).

**متن پیشنهادی کارت دوره:**
```
آموزش اطاعت پایه — پانسیون آموزشی ۶۰ روزه
هزینه‌ی دوره ۱۰٬۰۰۰٬۰۰۰ تومان
پانسیون: ۶۰ روز × ۵۰۰٬۰۰۰ = ۳۰٬۰۰۰٬۰۰۰ تومان
مبلغ کل: ۴۰٬۰۰۰٬۰۰۰ تومان — پیش‌پرداخت آنلاین: ۲٬۰۰۰٬۰۰۰ تومان — باقی در مرکز
```

قواعد:
1. اگر `packages[].types` خالی است، بسته «یک قیمت برای همه» است: در هر سه حالت با `price` خودِ بسته عرضه می‌شود و پانسیون (روز و روزانه) ندارد.
2. اگر `types` پر است، بسته فقط در حالت‌هایی عرضه می‌شود که ردیف دارند.
3. قیمت «از …» روی کارت (`packages[].price`) پانسیون را شامل نمی‌شود. برای پانسیون از ردیف ۳۸ حساب کنید یا از Quote بگیرید.

## ۳. فلو رزرو (قدم به قدم)

```
«پانسیون آموزشی» → انتخاب دوره → انتخاب پت → انتخاب روز تحویل پت (تقویم) → انتخاب ساعت تحویل
→ پیش‌فاکتور → توضیحات → ثبت → کد تخفیف/کیف پول → پرداخت
```

### قدم ۱: حالت
کاربر «پانسیون آموزشی (در مرکز)» را می‌زند: `mode = 38`. فقط دوره‌هایی را نشان دهید که ردیف ۳۸ دارند (یا `types` خالی).

### قدم ۲: دوره
کاربر یک دوره (بسته) انتخاب می‌کند. **برای پانسیون، یک دوره در هر رزرو** را پیشنهاد می‌کنیم (UI چندبسته‌ای را برای این حالت نشان ندهید).

### قدم ۳: پت
مثل قبل: پت‌های خود کاربر، با سایز سازگار با دوره. اگر `petSizes` دوره خالی است برای همه‌ی سایزهاست، وگرنه سایز پت باید در آن باشد (سند `VENUE_PACKAGE_PET_SIZES_FA.md`).

### قدم ۴: تقویم (روز تحویل پت)
`GET /api/EndUser/CoachReserve/BoardingAvailability?coachId={coachId}&packageId={packageId}&from=2026-11-10&days=60`

| پارامتر | توضیح |
|---|---|
| `coachId`، `packageId` | مربی و دوره |
| `from` | اولین روز تقویم؛ اگر قبل از امروز باشد از امروز حساب می‌شود |
| `days` | چند روز تقویم (۱ تا ۹۰). ماه بعد را با `from` جدید بگیرید |

پاسخ:
```json
{
  "capacity": 3,
  "stayDays": 60,
  "days": [
    { "date": "2026-11-10T00:00:00", "canStart": true,  "endDate": "2027-01-09T00:00:00", "available": 2,
      "windows": [ { "start": "9:00", "end": "13:00" }, { "start": "16:00", "end": "20:00" } ] },
    { "date": "2026-11-13T00:00:00", "canStart": false, "endDate": "2027-01-12T00:00:00", "available": 3, "windows": [] }
  ]
}
```

| فیلد | قاعده‌ی UI |
|---|---|
| `stayDays` | تعداد روز پانسیون دوره؛ در متن نمایش دهید («پانسیون ۶۰ روزه») |
| `days[].canStart` | **فقط روزهای `true` قابل انتخاب‌اند.** سرور چک کرده که مربی آن روز کار می‌کند و در **کل ۶۰ روز** بعدش جا هست |
| `days[].endDate` | اگر این روز انتخاب شود، تاریخ تحویل گرفتن پت. بعد از انتخاب نشان دهید: «تحویل گرفتن: ۹ دی» |
| `days[].available` | جای خالی همان روز (برای نمایش؛ تصمیم با `canStart` است). `null` = بدون سقف |
| `days[].windows` | ساعت‌های کاری آن روز برای قدم ۵ |

### قدم ۵: ساعت تحویل پت
- از `windows` روز انتخاب‌شده، با گام پیشنهادی ۳۰ دقیقه: مثلاً ۹:۰۰، ۹:۳۰، …، ۱۳:۰۰، ۱۶:۰۰، …، ۲۰:۰۰.
- زمان باید دست‌کم **۱ ساعت بعد از الان** باشد. برای امروز، ساعت‌های گذشته را حذف کنید.
- ساعت تحویل گرفتن همان ساعت در `endDate` است و کاربر آن را انتخاب نمی‌کند. متن: «تحویل گرفتن: ۹ دی، حدود ساعت ۱۰ (هماهنگی با مربی)».

### قدم ۶: پیش‌فاکتور
`GET /api/EndUser/CoachReserve/Quote?mode=38&packageIds={packageId}`
```json
{
  "coachServicePackageId": 12, "packageIds": [12], "mode": 38,
  "basePrice": 10000000, "coursePrePayment": 2000000,
  "stayDays": 60, "dailyPrice": 500000, "boardingFee": 30000000,
  "price": 40000000, "onlineAmount": 2000000, "payAtVenue": 38000000,
  "packagePrice": 40000000, "durationMinutes": 0, "sessionCount": null
}
```

| خط پیش‌فاکتور | فیلد |
|---|---|
| هزینه‌ی دوره | `basePrice` |
| پانسیون: ۶۰ روز × ۵۰۰٬۰۰۰ | `stayDays` × `dailyPrice` = `boardingFee` (اگر ۰ است نشان ندهید) |
| **مبلغ کل** | `price` |
| **پرداخت آنلاین الان (پیش‌پرداخت)** | `onlineAmount` (قبل از کد تخفیف؛ برابر `coursePrePayment`) |
| پرداخت در مرکز (باقی‌مانده‌ی دوره + پانسیون) | `payAtVenue` |

`durationMinutes` را نمایش ندهید. مبلغ را خودتان حساب نکنید؛ عدد سرور مرجع است.

### قدم ۷: توضیحات
`bookerNote` آزاد است. placeholder پیشنهادی: «غذا و وعده‌ها، داروها، وضعیت واکسن، نکات رفتاری پت».

### قدم ۸: ثبت رزرو
`POST /api/EndUser/CoachReserve`
```json
{
  "coachId": 5,
  "coachServicePackageId": 12,
  "extraPackageIds": [],
  "userPetId": 7,
  "mode": 38,
  "doDate": "2026-11-10T10:00:00",
  "assigneeUserId": null,
  "addressId": null,
  "bookerNote": "روزی دو وعده غذای خشک، واکسن کامل"
}
```

| فیلد | قاعده |
|---|---|
| `doDate` | روز و ساعت **تحویل دادن** پت (روز از قدم ۴ و ساعت از قدم ۵) |
| تعداد روز | **فرستاده نمی‌شود**؛ از دوره خوانده می‌شود |
| `addressId` | `null` (فقط برای در محل مشتری) |
| `assigneeUserId` | اختیاری، مثل قبل |

- پاسخ همان شیء رزرو است (بخش ۴): `endDate` = `doDate` + ۶۰ روز.
- رزرو پرداخت‌نشده تا **۱۵ دقیقه** جا را نگه می‌دارد. ثبت دوباره برای همان پت و همان بازه، رزرو قبلی را جایگزین می‌کند.

### قدم ۹: تخفیف، کیف پول و پرداخت (بدون تغییر)
- کد تخفیف: `PUT /api/EndUser/CoachReservePayment/Rebate` با `{ id, rebateCode }`. حذف: `DELETE /api/EndUser/CoachReservePayment/Rebate?id=`. تخفیف از **مبلغ آنلاین** کم می‌شود.
- کیف پول: `PUT /api/EndUser/CoachReservePayment/Wallet` با `{ id, fromWallet }`.
- پرداخت: `POST /api/EndUser/CoachReservePayment`، همان بدنه‌ی فعلی. مبلغ درگاه `paymentPrice` رزرو است، یعنی پیش‌پرداخت منهای تخفیف.

## ۴. لیست و جزئیات رزرو
- لیست: `GET /api/EndUser/CoachReserve`
- جزئیات: `GET /api/EndUser/CoachReserve/{id}`

**تشخیص رزرو پانسیون:** `dailyPrice != null` (حتی ۰).

| فیلد | نمایش |
|---|---|
| `mode` | ۳۸ → «پانسیون آموزشی» |
| `doDate` | «تحویل دادن: ۱۰ آبان، ساعت ۱۰:۰۰» |
| `endDate` | «تحویل گرفتن: ۹ دی» |
| `stayDays` | «۶۰ روز» |
| `dailyPrice` | «پانسیون روزانه ۵۰۰٬۰۰۰» (اگر ۰ است نشان ندهید) |
| `price` | مبلغ کل |
| `paymentPrice` | پرداخت‌شده‌ی آنلاین (بعد از تخفیف) |
| `payAtVenue` | باقی‌مانده (دوره + پانسیون) که در مرکز پرداخت می‌شود |
| `durationMinutes` | **نمایش ندهید** |
| `finalAmount`، `receivedAtVenue`، `debtAmount` | بعد از تکمیل؛ اگر پت زودتر تحویل گرفته شده، `finalAmount` ممکن است کمتر از `price` باشد |

وضعیت‌ها مثل قبل‌اند:
- `status`: ۰ ثبت‌شده، ۱ پرداخت‌شده، ۲ تکمیل‌شده.
- `ownerDecision`: ۱ منتظر تأیید مربی، ۲ تأیید، ۳ رد، ۴ بی‌پاسخ. رد و بی‌پاسخی یعنی لغو و برگشت کل مبلغ به کیف پول.

## ۵. لغو
`PUT /api/EndUser/CoachReserve/Cancel?id={id}`

| شرط | نتیجه |
|---|---|
| پرداخت‌نشده | فقط لغو |
| پرداخت‌شده و منتظر تأیید مربی | لغو + برگشت **کل** مبلغ به کیف پول |
| تأییدشده و دست‌کم **۴۸ ساعت** تا تحویل پت مانده | لغو + برگشت کل مبلغ |
| تأییدشده و کمتر از ۴۸ ساعت مانده | لغو **بدون** برگشت وجه |
| زمان تحویل گذشته یا رزرو تکمیل‌شده | لغو مجاز نیست |

- `freeCancelAvailable` در پاسخ رزرو همین را می‌گوید.
- متن پیشنهادی: «لغو رایگان تا ۴۸ ساعت قبل از تحویل پت».
- در محل مشتری و آنلاین همان ۱۲ ساعت قبلی را دارند.

## ۶. خطاها (`messages[0]`)

| پیام | چه وقت | کار UI |
|---|---|---|
| ظرفیت پانسیون آموزشی مربی در این تاریخ‌ها تکمیل است؛ تاریخ دیگری انتخاب کنید. | بین گرفتن تقویم و ثبت، جا پر شده | تقویم را دوباره بگیرید |
| (پیام فعلی «خارج از ساعت کاری») | ساعت تحویل داخل `windows` نیست | ساعت را عوض کنید |
| (پیام فعلی «پت در این زمان نوبت دیگری دارد») | پت در این ۶۰ روز رزرو پرداخت‌شده‌ی دیگری دارد | پت یا تاریخ دیگر |
| (پیام فعلی «زمان گذشته») | تحویل کمتر از ۱ ساعت بعد از الان | ساعت دیرتر |
| (پیام فعلی «این بسته در این حالت ارائه نمی‌شود») | دوره ردیف ۳۸ ندارد، یا برای `BoardingAvailability` تعداد روز پانسیون ندارد | دوره را در این حالت نشان ندهید |

## ۷. سازگاری با نسخه‌ی فعلی اپ
- نسخه‌ی فعلی که `mode = 38` را با `doDate` می‌فرستد **بدون تغییر کار می‌کند**. اگر دوره تعداد روز داشته باشد، سرور خودش اقامت را می‌سازد (پایان = +روز) و مبلغ را با پانسیون حساب می‌کند. نسخه‌ی قدیمی فقط تقویم و پیش‌فاکتور درستی نشان نمی‌دهد.
- دوره‌ی ۳۸ **بدون** `stayDays` (بسته‌های قدیمی) مثل قبل یک نوبت ساعتی است: برای آن از `GET /api/EndUser/CoachReserve/Availability` (زمان‌های آزاد ساعتی) استفاده کنید، نه از تقویم پانسیون.
- فیلدهای `dayCount` و `pickupDate` که در نسخه‌ی پیش‌نویس قبلی این سند بودند **حذف شده‌اند**؛ نفرستید.

## ۸. چک‌لیست تست
- [ ] پروفایل مربی سه حالت را با عنوان‌های جدید نشان می‌دهد.
- [ ] کارت دوره‌ی پانسیون: هزینه‌ی دوره، «۶۰ روز × ۵۰۰٬۰۰۰»، مبلغ کل ۴۰٬۰۰۰٬۰۰۰ و پیش‌پرداخت ۲٬۰۰۰٬۰۰۰.
- [ ] در تقویم فقط روزهای `canStart = true` انتخاب‌پذیرند و بعد از انتخاب `endDate` نمایش داده می‌شود.
- [ ] ساعت‌ها فقط از `windows` آن روز و دست‌کم یک ساعت بعد از الان‌اند.
- [ ] پیش‌فاکتور: کل ۴۰ میلیون، آنلاین ۲ میلیون، در مرکز ۳۸ میلیون.
- [ ] ثبت فقط با `doDate`، و `endDate` در پاسخ = +۶۰ روز.
- [ ] جزئیات رزرو بازه‌ی اقامت را نشان می‌دهد و `durationMinutes` را نه.
- [ ] لغو ۳ روز قبل از تحویل با برگشت کامل؛ لغو ۱ روز قبل (بعد از تأیید) بدون برگشت.
- [ ] رزرو دیگر برای همان پت وسط اقامت رد می‌شود.
