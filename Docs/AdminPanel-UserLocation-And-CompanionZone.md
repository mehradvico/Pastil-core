# راهنمای فرانت پنل ادمین؛ لوکیشن کاربران و محدوده خدمات Companion

این مستند قراردادهای فعلی بک‌اند برای دو قابلیت زیر را توضیح می‌دهد:

- نمایش آخرین لوکیشن ثبت‌شده کاربر در بخش کاربران پنل ادمین
- مشاهده و مدیریت محدوده‌هایی که هر Companion در آن‌ها خدمات ارائه می‌دهد

## نکات مشترک API

- تمام endpointهای این مستند به توکن ادمین نیاز دارند.
- هدر `Authorization` باید به شکل `Bearer {token}` ارسال شود.
- پاسخ عملیات‌ها معمولاً داخل ساختار زیر است:

```json
{
  "data": {},
  "code": 0,
  "isSuccess": true,
  "messages": []
}
```

- برای تشخیص موفقیت عملیات فقط به HTTP Status اکتفا نکنید؛ مقدار `isSuccess` را نیز بررسی کنید. خطاهای business ممکن است با HTTP 200 و `isSuccess: false` برگردند.
- مختصات در تمام APIها با استاندارد زیر است:

| فیلد | معنی |
|---|---|
| `x` | Longitude یا طول جغرافیایی |
| `y` | Latitude یا عرض جغرافیایی |

نمونه مختصات مرکز تهران:

```json
{
  "x": 51.389,
  "y": 35.6892
}
```

## نمایش لوکیشن کاربر در پنل ادمین

### دریافت لیست کاربران

```http
GET /api/Admin/User
```

پارامترهای جستجو و صفحه‌بندی همان پارامترهای قبلی بخش User هستند. در هر آیتم از `list` که از نوع `UserVDto` است، فیلد جدید زیر وجود دارد:

```json
{
  "id": 123,
  "firstName": "...",
  "lastName": "...",
  "userCurrentLocation": {
    "id": 18,
    "userId": 123,
    "location": {
      "x": 51.389,
      "y": 35.6892
    },
    "cityId": 87,
    "neighborhoodId": 14,
    "lastUpdateDate": "2026-07-21T18:28:07Z",
    "city": {
      "id": 87,
      "name": "تهران"
    },
    "neighborhood": {
      "id": 14,
      "name": "..."
    }
  }
}
```

نکته: اگر کاربر هنوز لوکیشن خود را از سایت ثبت نکرده باشد، `userCurrentLocation` برابر `null` است.

در پیاده‌سازی فعلی، لوکیشن به `UserVDto` یعنی آیتم‌های endpoint لیست/جستجوی کاربران اضافه شده است. endpoint جزئیات `GET /api/Admin/User/{id}` همچنان `UserDto` برمی‌گرداند؛ بنابراین برای نمایش لوکیشن فعلاً از داده لیست کاربران استفاده کنید.

### پیشنهاد UI

در جدول کاربران این موارد نمایش داده شوند:

- شهر
- محله؛ در صورت `null` بودن با عبارت «نامشخص»
- زمان آخرین به‌روزرسانی
- دکمه «نمایش روی نقشه» فقط زمانی که `location` وجود دارد

برای marker نقشه:

```ts
const longitude = user.userCurrentLocation.location.x;
const latitude = user.userCurrentLocation.location.y;
```

تاریخ `lastUpdateDate` بر اساس UTC است و باید در UI به ساعت محلی تبدیل شود.

## مدیریت محدوده خدمات Companion

هر Companion می‌تواند یک یا چند محدوده خدمات داشته باشد. دو نوع محدوده وجود دارد:

| حالت | `cityId` | `neighborhoodId` | معنی |
|---|---:|---:|---|
| کل شهر | مقدار دارد | `null` | Companion در تمام شهر خدمات می‌دهد |
| محله مشخص | مقدار دارد | مقدار دارد | Companion فقط در همان محله خدمات می‌دهد |

`stateId` توسط بک‌اند از روی شهر محاسبه می‌شود و فرانت نباید آن را ارسال کند.

### دریافت محدوده‌های یک Companion

```http
GET /api/Admin/CompanionZone?companionId=25&pageIndex=1&pageSize=50
```

این endpoint برخلاف عملیات ثبت و ویرایش، خروجی جستجو را مستقیماً برمی‌گرداند:

```json
{
  "totalCount": 2,
  "list": [
    {
      "id": 101,
      "companionId": 25,
      "stateId": 8,
      "cityId": 87,
      "neighborhoodId": null,
      "coversWholeCity": true,
      "state": {
        "id": 8,
        "name": "تهران"
      },
      "city": {
        "id": 87,
        "name": "تهران"
      },
      "neighborhood": null
    }
  ]
}
```

مقدار `coversWholeCity` از روی خالی بودن `neighborhoodId` محاسبه می‌شود و برای نمایش badge مناسب است.

ترتیب خروجی بک‌اند:

1. نام شهر
2. محدوده کل شهر قبل از محله‌ها
3. نام محله

### دریافت یک محدوده

```http
GET /api/Admin/CompanionZone/101
```

خروجی داخل `BaseResult` است و `data` شامل شناسه‌های محدوده خواهد بود.

### ثبت محدوده جدید

محدوده کل شهر:

```http
POST /api/Admin/CompanionZone
Content-Type: application/json
```

```json
{
  "companionId": 25,
  "cityId": 87,
  "neighborhoodId": null
}
```

محدوده یک محله:

```json
{
  "companionId": 25,
  "cityId": 87,
  "neighborhoodId": 14
}
```

### ویرایش محدوده

```http
PUT /api/Admin/CompanionZone
Content-Type: application/json
```

```json
{
  "id": 101,
  "companionId": 25,
  "cityId": 87,
  "neighborhoodId": null
}
```

### حذف محدوده

```http
DELETE /api/Admin/CompanionZone?id=101
```

حذف در بک‌اند به‌صورت soft delete انجام می‌شود. پس از موفقیت، لیست محدوده‌ها دوباره دریافت شود.

## قوانین اعتبارسنجی CompanionZone

بک‌اند قوانین زیر را اعمال می‌کند و UI نیز بهتر است قبل از ارسال آن‌ها را منعکس کند:

- Companion و City باید معتبر باشند.
- اگر محله انتخاب شده، باید متعلق به همان شهر باشد.
- ثبت دقیقاً تکراری یک محدوده مجاز نیست.
- وقتی برای یک Companion محدوده «کل شهر» وجود دارد، نمی‌توان یک محله از همان شهر را جداگانه اضافه کرد.
- وقتی محدوده «کل شهر» ثبت یا به آن تبدیل شود، محدوده‌های محله‌ای قبلی همان Companion در همان شهر به‌صورت خودکار غیرفعال می‌شوند.
- یک Companion می‌تواند در چند شهر مختلف محدوده خدمات داشته باشد.

## پیشنهاد فرم مدیریت محدوده

1. Companion را مشخص کنید.
2. شهر را انتخاب کنید.
3. یک سوییچ با عنوان «خدمات در کل شهر» نمایش دهید.
4. اگر سوییچ روشن است، `neighborhoodId: null` ارسال کنید.
5. اگر سوییچ خاموش است، انتخاب محله را اجباری کنید و فقط محله‌های همان شهر را نشان دهید.
6. پس از ثبت، ویرایش یا حذف موفق، لیست را refresh کنید.
7. در صورت `isSuccess: false` پیام موجود در `messages` را به کاربر نمایش دهید.
