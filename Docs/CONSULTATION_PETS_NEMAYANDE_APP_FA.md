# پت‌ها و سابقه‌ی پزشکی در مشاوره‌ی آنلاین — راهنمای اپ نماینده

**مخاطب:** توسعه‌دهنده‌ی اپ نماینده (کلینیک، مربی و نمایندگی؛ صفحه‌های «مشاوره‌های من» و «برنامه‌ی روز»)
**تاریخ:** ۱۴۰۵/۰۸/۰۵ (2026-10-27)
**وضعیت بک‌اند:** کد و تست آماده است، ولی **هنوز روی سرور دیپلوی نشده** (مایگریشن `ConsultationPurchasePets` اجرا نشده). تا اعلام دیپلوی، اندپوینت جدید ۴۰۴ می‌دهد و فیلد `hasSelectedPets` نمی‌آید؛ اپ باید هر دو را تحمل کند (بند ۶).

---

## ۱) چه چیزی عوض شد
تا امروز خرید مشاوره به هیچ پتی وصل نبود و اپ نماینده فهرست **همه‌ی** پت‌های مشتری را نشان می‌داد تا نماینده حدس بزند مشاوره درباره‌ی کدام است.

از این نسخه:
1. مشتری هنگام خرید **۱ تا ۵ پت** از پت‌های خودش را انتخاب می‌کند (الزامی).
2. در فهرست مشاوره‌ها و برنامه‌ی روز، **فقط پت‌های انتخاب‌شده‌ی همان خرید** می‌آید.
3. یک اندپوینت جدید، **پروفایل کامل و سابقه‌ی پزشکی** همین پت‌ها را برمی‌گرداند تا نماینده قبل و حین مشاوره ببیند.
4. خریدهای **قبل از این نسخه** پت انتخاب‌شده ندارند؛ برای آن‌ها مثل قبل همه‌ی پت‌های مشتری برمی‌گردد.

اپ نماینده **چیزی نمی‌فرستد** که عوض شده باشد؛ فقط پاسخ‌ها تغییر کرده‌اند و یک اندپوینت خواندنی اضافه شده است.

---

## ۲) تغییر در فهرست «مشاوره‌های من»

**اندپوینت (بدون تغییر):** `GET /api/Companion/ConsultationSession`

| فیلد | نوع | تغییر | توضیح |
|---|---|---|---|
| `customerPets` | `array` | **معنا عوض شد** | اگر `hasSelectedPets = true`: فقط پت(های) انتخاب‌شده‌ی این خرید. اگر `false`: همه‌ی پت‌های فعال مشتری (خرید قدیمی). شکل هر آیتم همان قبلی است: `userPetId`، `name`، `petName`، `picture`. |
| `hasSelectedPets` | `bool` | **جدید** | `true` = مشتری هنگام خرید پت انتخاب کرده. `false` = خرید قدیمی؛ پت مشخصی ندارد. |

نمونه‌ی یک آیتم:

```json
{
  "id": 9252,
  "purchaseCode": "CNS-20261026-1253-9252",
  "packageName": "مشاوره رفتاری",
  "userFullName": "آرمان تاجیک",
  "hasSelectedPets": true,
  "customerPets": [
    { "userPetId": 1017, "name": "رکس", "petName": "سگ", "picture": { "url": "Pictures/2026/10/abc.jpg" } }
  ]
}
```

### نمایش پیشنهادی
- روی کارت هر مشاوره، عکس و اسم پت(ها) با عنوان «برای: رکس، میلو» نمایش داده شود.
- اگر `hasSelectedPets = false`، عنوان را «پت‌های مشتری» بگذارید و یک برچسب کوچک «پت مشخص نشده» نشان دهید.
- با زدن روی پت یا دکمه‌ی «پروفایل پت»، صفحه‌ی پروفایل (بند ۴) باز شود.

---

## ۳) تغییر در «برنامه‌ی روز»

**اندپوینت (بدون تغییر):** همان اندپوینت برنامه‌ی روز (`Companion/CompanionDaySchedule`). این صفحه فعلاً فقط مشاوره‌های **نمایندگی (Companion)** را نشان می‌دهد؛ کلینیک و مربی مشاوره‌هایشان را از «مشاوره‌های من» (بند ۲) می‌بینند.

برای آیتم‌های نوع مشاوره (`kind = Consultation`)، فیلد `pets` از این نسخه:
- اگر خرید پت انتخاب‌شده دارد: **فقط همان پت(ها)**،
- وگرنه (خرید قدیمی): مثل قبل، پت‌های فعال مشتری.

شکل هر پت (`DayPetVDto`) **تغییری نکرده است** (نام، نوع، نژاد، سن، جنسیت، وزن، بیماری/داروی خاص، میکروچیپ، عکس).

---

## ۴) اندپوینت جدید: پروفایل و سابقه‌ی پزشکی پت‌های مشاوره

`GET /api/Companion/ConsultationSession/{purchaseId}/Pets`

- **دسترسی:** فقط نماینده‌ی مجاز همان کلینیک/مربی/نمایندگی (مالک یا عضو فعال و تأییدشده‌ی تیم). برای بقیه `isSuccess = false` و پیام «موردی یافت نشد».
- **وضعیت خرید:** در همه‌ی وضعیت‌ها کار می‌کند (منتظر شروع، در جریان، پایان‌یافته، …) تا نماینده بعد از مشاوره هم سابقه را ببیند.
- **پاسخ:** `BaseResultDto<List<ConsultationPetProfileVDto>>` — یک آیتم برای هر پت.

### فیلدهای هر پت

| فیلد | نوع | توضیح |
|---|---|---|
| `userPetId` | `long` | شناسه‌ی پت؛ برای ثبت سابقه‌ی جدید همین را بفرستید (بند ۵) |
| `name` | `string` | اسم پت |
| `petName` | `string` | نوع حیوان (سگ، گربه، …) |
| `breedName` / `breed2Name` | `string` | نژاد؛ `breed2Name` فقط وقتی `isMixBreed = true` معنا دارد |
| `isMixBreed` | `bool` | دورگه |
| `isMale` | `bool` | `true` نر، `false` ماده |
| `isSterile` | `bool` | عقیم‌شده |
| `birthday` | `datetime` | تاریخ تولد |
| `ageMonths` | `int` | سن به ماه (۰ = نامعلوم). متن «۲ سال و ۳ ماه» را اپ بسازد |
| `size` / `weight` | `string` | سایز و وزن ثبت‌شده توسط صاحب پت |
| `microChipCode` | `string` | کد میکروچیپ (ممکن است خالی باشد) |
| `specificDisease` | `string` | بیماری خاصی که صاحب پت ثبت کرده |
| `specificMedicine` | `string` | داروی خاصی که صاحب پت ثبت کرده |
| `picture` | `PictureVDto \| null` | عکس پت |
| `records` | `array` | **سوابق ثبت‌شده توسط کلینیک‌ها/اپراتورها**، جدیدترین اول، حداکثر ۲۰ مورد |
| `records[].id` | `long` | |
| `records[].text` | `string` | متن سابقه |
| `records[].operatorName` | `string` | نام ثبت‌کننده |
| `records[].createDate` | `datetime` | |
| `clinicVisits` | `array` | **مراجعات تکمیل‌شده‌ی کلینیک** (هر کلینیکی در پاستیل)، جدیدترین اول، حداکثر ۲۰ |
| `clinicVisits[].id` | `long` | شناسه‌ی رزرو کلینیک |
| `clinicVisits[].date` | `datetime` | تاریخ نوبت |
| `clinicVisits[].venueName` | `string` | نام کلینیک |
| `clinicVisits[].title` | `string` | نام خدمت (مثلاً «چکاپ، واکسن و پیشگیری») |
| `clinicVisits[].note` | `string \| null` | یادداشت تکمیل کلینیک |
| `pastConsultations` | `array` | **مشاوره‌های آنلاین پایان‌یافته‌ی قبلی** همین پت (به‌جز همین خرید)، جدیدترین اول، حداکثر ۲۰ |
| `pastConsultations[].id` | `long` | شناسه‌ی خرید مشاوره |
| `pastConsultations[].date` | `datetime` | زمان شروع (یا ثبت) |
| `pastConsultations[].venueName` | `string` | نام کلینیک/مربی/نمایندگی |
| `pastConsultations[].title` | `string` | نام پکیج |

نمونه‌ی پاسخ:

```json
{
  "isSuccess": true,
  "data": [
    {
      "userPetId": 1017,
      "name": "رکس",
      "petName": "سگ",
      "breedName": "ژرمن شپرد",
      "breed2Name": null,
      "isMixBreed": false,
      "isMale": true,
      "isSterile": false,
      "birthday": "2024-08-01T00:00:00",
      "ageMonths": 26,
      "size": "Large",
      "weight": "32",
      "microChipCode": "985112003456789",
      "specificDisease": "حساسیت پوستی",
      "specificMedicine": null,
      "picture": { "url": "Pictures/2026/10/abc.jpg" },
      "records": [
        { "id": 55, "text": "واکسن هاری تزریق شد", "operatorName": "دکتر احمدی", "createDate": "2026-09-10T11:20:00" }
      ],
      "clinicVisits": [
        { "id": 310, "date": "2026-10-23T12:59:00", "venueName": "کلینیک دامپزشکی استلا", "title": "چکاپ، واکسن و پیشگیری", "note": null }
      ],
      "pastConsultations": [
        { "id": 9100, "date": "2026-09-01T18:00:00", "venueName": "مربی امیر", "title": "مشاوره رفتاری" }
      ]
    }
  ]

```

### صفحه‌ی پیشنهادی «پروفایل پت»
1. **سربرگ:** عکس، اسم، نوع و نژاد، جنسیت، عقیم/غیرعقیم.
2. **مشخصات:** سن، وزن، سایز، میکروچیپ در چند کاشی کوچک.
3. **هشدار پزشکی:** اگر `specificDisease` یا `specificMedicine` پر بود، یک کادر قرمز واضح بالای صفحه («بیماری خاص: …»، «داروی خاص: …»).
4. **سابقه‌ی پزشکی:** یک خط زمانی ادغام‌شده از `records`، `clinicVisits` و `pastConsultations` بر اساس تاریخ، هرکدام با برچسب رنگی («سابقه»، «مراجعه‌ی کلینیک»، «مشاوره‌ی قبلی»).
5. اگر خرید چند پت دارد، بالای صفحه تب برای هر پت.
6. این صفحه هم از کارت مشاوره در فهرست و هم **از داخل صفحه‌ی چت/تماس** (دکمه‌ی «پروفایل پت» در نوار بالا) باز شود تا نماینده حین گفتگو ببیند.

---

## ۵) ثبت سابقه‌ی جدید بعد از مشاوره
اندپوینت تغییری نکرده است: `POST /api/Operator/UserPetRecord` با `userPetId` یکی از پت‌های همین مشاوره.
بعد از ثبت، دوباره `GET …/{purchaseId}/Pets` را صدا بزنید؛ سابقه‌ی جدید اول `records` می‌آید.

---

## ۶) سازگاری
- تا دیپلوی بک‌اند، `GET …/{purchaseId}/Pets` پاسخ ۴۰۴ می‌دهد؛ دکمه‌ی «پروفایل پت» را در این حالت پنهان کنید یا پیام «به‌زودی» نشان دهید.
- نبودن `hasSelectedPets` را مثل `false` در نظر بگیرید.
- فیلدهای موجود حذف یا تغییر نوع نداده‌اند؛ نسخه‌ی فعلی اپ بعد از دیپلوی **خراب نمی‌شود**، فقط به‌جای همه‌ی پت‌ها، پت(های) انتخاب‌شده را می‌بیند.

---

## ۷) چک‌لیست تست
- [ ] خرید جدید با یک پت ← در فهرست فقط همان پت و `hasSelectedPets = true`.
- [ ] خرید قدیمی ← همه‌ی پت‌های مشتری و `hasSelectedPets = false`.
- [ ] باز کردن پروفایل ← مشخصات، هشدار بیماری/دارو، سوابق، مراجعات و مشاوره‌های قبلی درست نمایش داده شوند.
- [ ] عضو تیم کلینیک دیگر ← پروفایل پت این خرید خطای «موردی یافت نشد» می‌دهد.
- [ ] ثبت سابقه با `POST /api/Operator/UserPetRecord` ← بعد از تازه‌سازی در `records` دیده شود.
- [ ] باز کردن پروفایل از داخل صفحه‌ی چت.
