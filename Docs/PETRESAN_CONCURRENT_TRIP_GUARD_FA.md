# پت‌رسان: قفل «یک سفر فعال» + لغو خودکار سفر متصل — راهنمای فرانت‌ها

**مخاطب:** وب‌اپ (Arman) و اپ فلاتر — هر دو از مسیرهای زیر برای ثبت پت‌رسان استفاده می‌کنند.

## ۱. چه چیزی عوض شد

کاربر دیگر نمی‌تواند هم‌زمان چند سفر پت‌رسان باز داشته باشد — نه ترکیب فوری+رزرویی، نه دو رزرویی مختلف. این روی هر چهار مسیر ثبت سفر پیاده شد:

| مسیر بک‌اند | BFF وب‌اپ | حالت |
|---|---|---|
| `POST /api/EndUser/TripCurrent` | `trip/submit` | فوری (از قبل هم این قفل را داشت) |
| `POST /api/EndUser/TripReservation` | `petresan/reservation` | متصل به رزرو خدمت |
| `POST /api/EndUser/TripPansionReservation` | `petresan/pansionReservation` | متصل به رزرو پانسیون |
| `POST /api/EndUser/TripSchoolReservation` | `petresan/schoolReservation` | متصل به ثبت‌نام مدرسه |
| `POST /api/EndUser/TripScheduled` | *(فعلاً در وب‌اپ سیم‌کشی‌شده پیدا نشد)* | تاریخ‌دار آزاد |

## ۲. خطای جدید

اگر کاربر یک سفر پت‌رسانِ باز (وضعیت «درخواست‌شده» یا «پذیرفته‌شده») داشته باشد، هر چهار مسیر بالا (غیر از فوری که از قبل همین بود) حالا هم همین خطا را می‌دهند:

```json
{ "isSuccess": false, "messages": [{ "item1": "شما هم‌اکنون یک سفر آنلاین فعال دارید.", "item2": "" }] }
```

**قاعده‌ی دقیق «سفر باز»:** سفر فوری همیشه حساب می‌شود. سفر رزرویی/تاریخ‌دار فقط وقتی حساب می‌شود که **کمتر از ۳ ساعت تا زمان حرکتش مانده باشد** — یک رزرویی که هفته‌ی بعد است، مانع ثبت یک سفر فوری امروز نمی‌شود. پس این خطا معمولاً فقط نزدیک به لحظه‌ی واقعیِ حرکت پیش می‌آید، نه بلافاصله بعد از هر بار ثبت یک رزرو با پت‌رسان.

**پیشنهاد UI:** این پیام را عیناً (`messages[0].item1`) نشان دهید؛ متن ثابت جداگانه ننویسید چون ممکن است بعداً عوض شود. اگر می‌خواهید تجربه‌ی بهتری بدهید، کاربر را به صفحه‌ی «سفر جاری» (`GET /api/EndUser/TripCurrent` یا هرچه در وب‌اپ معادلش است) هدایت کنید تا سفر بازش را ببیند.

## ۳. لغو رزرو حالا سفر متصلش را هم لغو می‌کند

اگر کاربر یا ادمین یک رزرو خدمت/پانسیون/مدرسه را لغو کند و آن رزرو یک سفر پت‌رسانِ متصلِ هنوز تمام‌نشده داشته باشد (درخواست‌شده یا پذیرفته‌شده)، آن سفر هم خودکار لغو می‌شود. چیزی در API لازم نیست عوض شود؛ فقط اگر وب‌اپ جایی وضعیت آن سفر را جداگانه poll می‌کند (مثلاً در `transportation/history.vue` یا صفحه‌ی سفر جاری)، حالا بعد از لغو رزرو، وضعیت آن سفر هم به‌روز به «لغوشده» می‌آید — قبلاً برای همیشه در وضعیت «درخواست‌شده» می‌ماند.

## ۴. فیلدهای تازه برای نمایش هزینه‌ی پت‌رسان کنار رزرو (اختیاری)

اگر می‌خواهید در جزئیات یک رزرو (خدمت/پانسیون/مدرسه) قیمت سفر پت‌رسانِ متصلش را هم نشان دهید، این فیلدها از قبل در پاسخ هست — چیزی برای درخواست اضافه لازم نیست:

```jsonc
{
  // ... فیلدهای همیشگی رزرو ...
  "paymentPrice": 500000,
  "petResanTrip": {              // null اگر سفری وصل نیست
    "tripId": 1234,
    "price": 80000,
    "paymentPrice": 80000,
    "isPaid": true,
    "tripStatusLabel": "پذیرفته‌شده",
    "driverStatusLabel": "...",
    "driverId": 12,
    "driverName": "..."
  },
  "totalPrice": 580000            // فقط برای نمایش = paymentPrice + petResanTrip.paymentPrice (یا price اگر هنوز پرداخت نشده)
}
```

**نکته‌ی مهم:** `totalPrice` فقط برای نمایش «جمع کل» است. این دو مبلغ همچنان **کاملاً جدا پرداخت می‌شوند** — هزینه‌ی رزرو در چک‌اوت خودش، هزینه‌ی پت‌رسان فقط بعد از قبول راننده (مثل یک تاکسی معمولی). این فیلد چیزی را در حسابداری یا پرداخت واقعی تغییر نمی‌دهد.

## ۵. چیزی که عوض نشده
- ساختار بدنه‌ی درخواست هر چهار مسیر دست‌نخورده است.
- قفل «یک سفر فعال» برای سفر **فوری** (`TripCurrent`) از قبل هم بود؛ فقط رفتارش کمی دقیق‌تر شد (پیش‌ازاین یک باگ باعث می‌شد اگر کاربر یک رزرویی با پت‌رسان روزهای بعد داشت، تا آن موقع اصلاً نمی‌توانست سفر فوری بگیرد — رفع شد).
