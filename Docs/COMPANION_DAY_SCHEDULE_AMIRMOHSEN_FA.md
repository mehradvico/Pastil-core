# صفحه‌ی «برنامه‌ی امروز» نماینده — مستند اپ نماینده (ویژه امیرمحسن)

> مخاطب: امیرمحسن (اپ Flutter نماینده) · وضعیت بک: **پیاده‌سازی و تست واحد شد (۶۴۳ تست سبز)؛ دیپلوی نشده.** مایگریشن/SQL **لازم نیست** (فقط دیپلوی Api).
> هدف: نماینده یا کارمند کلینیک در یک صفحه رزروهای یک روز را **به ترتیب ساعت** ببیند: چه کسی می‌آید، پتش چیست و چه مشخصاتی دارد، چه خدمتی، کجا (مرکز/در محل/آنلاین)، به چه کسی تخصیص دارد، و «برنامه‌ی کاری» آن روز کلینیک (ساعت‌های کاری).

پاسخ‌ها **همیشه HTTP 200** با `{ isSuccess, messages, data }` هستند؛ موفقیت را از `isSuccess` بخوانید. فیلدها camelCase. (استثنا: `Forbid` ⇒ HTTP 403 وقتی کاربر اصلاً نماینده/عضو کلینیک نیست.)

## ۱) endpoint

```
GET /api/Companion/CompanionDaySchedule
    ?date=2026-10-04          // اختیاری؛ خالی = امروز (به ساعت سرور)
    &companionId=7            // اختیاری؛ فقط وقتی بیش از یک کلینیک دارید
    &includeCancelled=false   // اختیاری
    &mineOnly=false           // اختیاری
```

`Authorization: Bearer …`

| پارامتر | معنی |
| --- | --- |
| `date` | روز مورد نظر به‌صورت `yyyy-MM-dd`. خالی ⇒ امروز. هر روز دلخواه (گذشته/آینده) مجاز است. |
| `companionId` | کلینیک. خالی ⇒ کلینیکی که مالکش هستید، وگرنه اولین کلینیکی که عضو تیمش هستید. فهرست همه‌ی کلینیک‌هایتان در `availableClinics` پاسخ است. |
| `includeCancelled` | `true` ⇒ لغو/بازپرداخت‌شده‌ها هم بیایند (با `status: 5`). پیش‌فرض `false`. |
| `mineOnly` | `true` ⇒ فقط رزروهای تخصیص‌یافته به **خودم**. (مالک پیش‌فرض همه‌ی کلینیک را می‌بیند؛ عضو تیم همیشه فقط مال خودش را می‌بیند.) |

### چه کسی چه چیزی می‌بیند
- **مالک کلینیک:** همه‌ی رزروهای کلینیک در آن روز. با `mineOnly=true` فقط تخصیص‌یافته‌ها به خودش.
- **عضو تیم (اپراتور/دکتر، فعال و تأییدشده):** فقط رزروهای خدمتی که به **او** تخصیص داده شده. رزرو بدون نماینده را فقط مالک می‌بیند (برای واگذاری).
- **مشاوره‌ی آنلاین رزروشده با ساعت** (بخش ۴): برای عضو تیم، هم تخصیص‌یافته به خودش و هم **بدون نماینده** دیده می‌شود، چون هر عضو می‌تواند «شروع» را بزند.
- کاربری که نه مالک است نه عضو تیم: HTTP 403.
- فقط رزروهای **قطعی/پرداخت‌شده** (`isReserved`) می‌آیند؛ رزرو پرداخت‌نشده نمایش داده نمی‌شود.

```json
{

  "data": {

    "companionName": "کلینیک مهر",
    "date": "2026-10-04T00:00:00",
    "serverNow": "2026-10-04T12:41:09.12+03:30",
    "dayOfWeek": "Sunday",
    "weekDayId": 2,
    "isOwner": true,
    "availableClinics": [ { "id": 7, "name": "کلینیک مهر", "isOwner": true } ],
    "workingHours": [
      { "id": 31, "start": "09:00", "end": "13:00", "capacity": 2 },
      { "id": 32, "start": "15:00", "end": "19:00", "capacity": 1 }
    ],
    "summary": { "total": 4, "upcoming": 2, "now": 1, "done": 1, "missed": 0, "cancelled": 0 },
    "items": [ … ]

```

| فیلد | توضیح |
| --- | --- |
| `date` | روز درخواستی. **بدون آفست** است (`…T00:00:00`). |
| `serverNow` | ساعت سرور با آفست. «الان» و وضعیت‌ها با همین حساب شده‌اند؛ برای شمارنده/نشانگر «الان» از آن استفاده کنید نه ساعت گوشی. |
| `dayOfWeek` / `weekDayId` | نام انگلیسی روز و شماره‌ی روز در تقویم پروژه: `1` شنبه … `7` جمعه. |
| `workingHours` | ساعت‌های کاری **کلینیک** در همان روز هفته (از «ساعت کاری مرکز»)؛ `capacity` ظرفیت هم‌زمان هر بازه. اگر خالی بود یعنی آن روز تعطیل/بدون ساعت کاری تعریف‌شده. |
| `summary` | شمار هر وضعیت (برای نوار بالای صفحه). |
| `items` | آیتم‌ها به ترتیب **ساعت شروع** (اگر شروع دو آیتم برابر بود: اول مشاوره، بعد خدمت، بعد شناسه). حداکثر ۳۰۰ آیتم. |

```json
  "channelId": null, "durationMinutes": null, "consultationStatus": null, "onlineSessionId": null,

```

نکته‌ها:
- **ساعت:** رزرو خدمت یک **بازه‌ی ساعتی** (`startTime`–`endTime`) روی همان روز است؛ برای نمایش مستقیم از `startTime/endTime` استفاده کنید. اگر بازه‌ی ساعتی ثبت نشده باشد، `end` و `endTime` برابر `null` هستند و شروع از ساعت ثبت‌شده است.
- `serviceModeName`: نوع ارائه (مرکز، در محل، آنلاین) به‌صورت نام فارسی کد؛ برای رزرو آنلاین `isOnline: true` و `onlineMethodName` نام روش (چت/تماس/ویدیو).
- `address`: فقط وقتی رزرو «در محل» است پر می‌شود. `latitude/longitude` ممکن است `null` باشد؛ دکمه‌ی «مسیریابی» را فقط وقتی هر دو پر بودند نشان دهید.
- `pets`: رزرو ممکن است چند پت داشته باشد (همه برگردانده می‌شوند). `ageMonths` سن به ماه است؛ متن «۳ سال و ۴ ماه» را در اپ بسازید (۰ یعنی تاریخ تولد نامعتبر). `specificDisease/specificMedicine` را حتماً برجسته نشان دهید (آماده‌شدن قبل از نوبت).
- `operatorUnpaid: true` یعنی هزینه‌ی نهایی ثبت شده ولی مشتری هنوز پرداخت نکرده (بدهی باز)؛ نشان هشدار بدهید.
- `customer.mobile`: برای تماس با مشتری؛ فقط خود نماینده/مالک می‌بیند.
- `canStart` برای خدمت همیشه `false` است (فقط برای مشاوره معنی دارد).

## ۴) آیتم مشاوره‌ی آنلاین رزروشده (`kind: "Consultation"`)

مشاوره‌های «قابل‌رزرو» (کاربر ساعت انتخاب کرده؛ [ONLINE_CONSULTATION_BOOKING_FA.md](ONLINE_CONSULTATION_BOOKING_FA.md)) هم در همین فهرست و بر اساس `scheduledStart` می‌آیند، تا نماینده یک برنامه‌ی واحد ببیند. مشاوره‌ی «فوری» (بدون ساعت) اینجا نیست.

```json
{
  "kind": "Consultation",
  "id": 21,                       // شناسه‌ی خرید مشاوره (purchaseId)
  "code": "CNS-20261004-1200-1234",
  "start": "2026-10-04T16:00:00", "end": "2026-10-04T16:30:00",
  "startTime": "16:00", "endTime": "16:30",
  "status": 1,
  "title": "ویدیوکال رزروی ۳۰ دقیقه‌ای",
  "isOnline": true,
  "customer": { … },
  "pets": [ … ],                  // همه‌ی پت‌های فعال مشتری (مشاوره پت مشخصی ندارد)، حداکثر ۱۰
  "assignee": null,               // یا { userId, fullName, isMe }
  "paymentPrice": 250000,
  "channelId": 3,                 // ۱ چت، ۲ تماس درون‌برنامه، ۳ تصویری، ۴ تلفنی
  "durationMinutes": 30,
  "consultationStatus": 2,        // وضعیت خرید: ۲ پرداخت‌شده، ۳ در جریان، ۴ پایان‌یافته، ۵ منقضی، ۶ لغو، ۷ بازپرداخت
  "onlineSessionId": null,        // بعد از «شروع» پر می‌شود
  "canStart": true
}
```

- `canStart: true` ⇒ از ۱۰ دقیقه قبل از `start` تا ۱۵ دقیقه بعد از آن (و اگر تخصیص دارد، فقط برای نماینده‌ی تخصیص‌یافته). دکمه‌ی «شروع» را فقط وقتی `true` است فعال کنید. شروع: `POST /api/Companion/ConsultationSession/{id}/Start` (قرارداد کامل در [ONLINE_CONSULTATION_APP_FA.md](ONLINE_CONSULTATION_APP_FA.md) §۴؛ `id` همان `id` آیتم).
- بعد از شروع (`consultationStatus == 3`) برای ورود دوباره: `POST …/ConsultationSession/{id}/Enter` و صفحه‌ی چت/تماس با `onlineSessionId`.
- `pets` مشاوره‌ی آنلاین سابقه‌ی پت‌های مشتری است، نه پت رزروشده؛ در UI عنوان «پت‌های مشتری» بگذارید.

## ۵) `status` (برای هر دو نوع)

| مقدار | معنی | رنگ/نمایش پیشنهادی |
| ---: | --- | --- |
| 1 | هنوز نرسیده (`Upcoming`) | خنثی/آبی |
| 2 | الان (`Now`): داخل بازه‌ی ساعتی، یا مشاوره‌ی در جریان | سبز، برجسته |
| 3 | انجام‌شده (`Done`) | خاکستری با تیک |
| 4 | از دست رفته (`Missed`): زمانش گذشته و انجام نشده؛ برای مشاوره: شروع‌نشده تا مهلت یا منقضی | قرمز/نارنجی |
| 5 | لغو/بازپرداخت‌شده (`Cancelled`) — فقط با `includeCancelled=true` | خط‌خورده |

قواعد: خدمت لغوشده ⇒ ۵؛ `doneDate` دارد ⇒ ۳؛ قبل از شروع ⇒ ۱؛ داخل بازه ⇒ ۲؛ بعد از پایان بدون انجام ⇒ ۴. خدمت **بدون** ساعت پایان هرگز «۴» نمی‌شود (از شروع به بعد ۲ می‌ماند).

## ۶) رفتار پیشنهادی صفحه

1. **بالای صفحه:** عنوان «برنامه‌ی امروز»، انتخابگر روز (قبل/بعد و تقویم شمسی؛ مقدار ارسالی میلادی `yyyy-MM-dd`)، و اگر `availableClinics.length > 1` انتخابگر کلینیک (`companionId`).
2. **نوار برنامه‌ی کاری:** از `workingHours` (مثلاً «ساعت کاری امروز: ۰۹–۱۳ و ۱۵–۱۹»). اگر خالی بود «امروز ساعت کاری ندارید».
3. **نوار خلاصه:** از `summary` (نرسیده/الان/انجام‌شده/از دست رفته).
4. **خط زمانی:** آیتم‌ها دقیقاً به ترتیب `items`؛ هر کارت: ساعت `startTime–endTime`، نام مشتری و (دکمه‌ی تماس با `mobile`)، پت‌ها (عکس، نام، نوع و نژاد، سن، جنسیت، سایز/وزن، بیماری/دارو برجسته)، نام خدمت/پکیج، نوع ارائه (مرکز/در محل/آنلاین)، آدرس در رزرو در محل، توضیح مشتری، تخصیص‌یافته (برای مالک: «به: دکتر رضایی»)، و نشان وضعیت.
5. **اسکرول خودکار** به اولین آیتم با `status == 2`، یا اگر نبود اولین `status == 1`.
6. **تازه‌سازی:** هنگام ورود به صفحه، بازگشت به اپ (resume)، pull-to-refresh و هر ۶۰ ثانیه (فقط وقتی صفحه باز است). برای نشانگر «الان» و تغییر وضعیت‌ها از `serverNow` استفاده کنید؛ بین دو پاسخ، فقط محلی شمارنده را جلو ببرید (قاعده‌ی طلایی زمان در [ONLINE_CONSULTATION_APP_FA.md](ONLINE_CONSULTATION_APP_FA.md) §۲: آفست را حذف کنید و اختلاف `serverNow` با ساعت گوشی را نگه دارید).
7. **روز بدون رزرو:** پیام «برای این روز رزروی ندارید» همراه برنامه‌ی کاری.
8. **جزئیات و عملیات:** برای جزئیات کامل/تغییر وضعیت رزرو خدمت از endpointهای موجود استفاده کنید (آیتم `id` همان شناسه‌ی رزرو است): `GET /api/Companion/CompanionReserve/{id}`، `PUT /api/Companion/CompanionReserveChangeState`، `PUT …/CompanionReserveCancel`، `PUT …/CompanionReserveAssign` (بدنه‌ها طبق همان سه endpoint موجود). برای مشاوره: `ConsultationSession` (بند ۴). این endpoint فقط خواندنی است و هیچ داده‌ای را عوض نمی‌کند.
9. فیلتر پیشنهادی: «همه / فقط مال من» (`mineOnly`)، و سوئیچ «نمایش لغوشده‌ها» (`includeCancelled`).

## ۷) خطاها و حالت‌های لبه

| حالت | رفتار |
| --- | --- |
| کاربر نماینده/عضو تیم نیست | HTTP 403 |
| `companionId` متعلق به کلینیک دیگری است | `isSuccess:false` + «دسترسی ندارید» |
| کلینیک پیدا نشد | `isSuccess:false` + «چیزی یافت نشد» |
| روز بدون رزرو | `isSuccess:true` و `items: []`، `summary` همه صفر |
| `date` نامعتبر | خطای اعتبارسنجی (۴۰۰)؛ فقط `yyyy-MM-dd` بفرستید |
| تعداد آیتم‌ها از ۳۰۰ بیشتر | فقط ۳۰۰ آیتم اول به ترتیب ساعت (در عمل پیش نمی‌آید) |

## ۸) چیزهایی که این صفحه نشان **نمی‌دهد** (عمداً)

- رزروهای **پانسیون/مهد پت** (بازه‌ی چندروزه‌اند، نه ساعتی) و ثبت‌نام **مدرسه**. اگر خواستید در برنامه‌ی روز هم بیایند (مثلاً «ورود/خروج امروز»)، جداگانه می‌خواهیم و می‌سازیم.
- رزرو پرداخت‌نشده و مشاوره‌ی فوری (بدون ساعت).
- رزروهای کلینیک‌های دیگر که عضو آن نیستید.

## ۹) تست پیشنهادی (بعد از دیپلوی)

۱. با مالک: یک رزرو خدمت برای امروز (پرداخت‌شده) بسازید ⇒ در `items` با `kind: "Service"` و ساعت درست و `status` مناسب بیاید.
۲. دو رزرو با ساعت‌های مختلف ⇒ ترتیب صعودی ساعت.
۳. رزرو چندپتی ⇒ همه‌ی پت‌ها در `pets`.
۴. رزرو «در محل» ⇒ `address` پر؛ رزرو مرکز ⇒ `address: null`.
۵. با عضو تیم: رزرو تخصیص‌یافته به او دیده شود و رزرو دیگران نه؛ مشاوره‌ی بی‌نماینده دیده شود.
۶. مشاوره‌ی رزروشده برای امروز ⇒ `kind: "Consultation"`، و `canStart` از ۱۰ دقیقه قبل `true` شود.
۷. `includeCancelled=true` ⇒ رزرو لغوشده با `status: 5` بیاید؛ بدون آن نیاید.
۸. روز بدون رزرو ⇒ `items: []`.

## ۱۰) چک‌لیست اپ

- [ ] صفحه‌ی «برنامه‌ی امروز» با انتخابگر روز (و کلینیک اگر بیش از یکی)
- [ ] نوار ساعت کاری (`workingHours`) و خلاصه (`summary`)
- [ ] خط زمانی به ترتیب `items`، کارت خدمت و کارت مشاوره (`kind`)
- [ ] پت‌ها با مشخصات کامل و برجسته‌کردن بیماری/دارو
- [ ] دکمه‌ی تماس با مشتری و (برای «در محل») مسیریابی با `latitude/longitude`
- [ ] وضعیت‌ها (۱ تا ۵) با رنگ، اسکرول به «الان»
- [ ] دکمه‌ی «شروع» مشاوره فقط با `canStart` (طبق `ConsultationSession/{id}/Start`)
- [ ] تازه‌سازی (ورود، resume، pull-to-refresh، ۶۰ ثانیه) با `serverNow`
- [ ] فیلترها: «فقط مال من» و «نمایش لغوشده‌ها»
- [ ] روز خالی و خطای 403/«دسترسی ندارید»
