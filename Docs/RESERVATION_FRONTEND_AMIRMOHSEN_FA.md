# قرارداد فرانت رزرو خدمات و پانسیون — مخصوص امیرمحسن

## یادآوری ثبت نظر پس از پایان رزرو

پس از انتقال رزرو همراه (Companion) یا پانسیون به وضعیت «تکمیل/انجام‌شده»، بک‌اند یک Push فارسی را برای ۱۲ ساعت بعد زمان‌بندی می‌کند. این زمان‌بندی فقط در اولین انتقال به وضعیت نهایی انجام می‌شود.

متن و مقصد Pushها:

| نوع | متن | مقصد |
|---|---|---|
| Companion | `{نام} عزیز، لطفاً نظر خود درباره خدمت «{نام خدمت}» از «{نام همراه/ارائه‌دهنده}» را ثبت نمایید.` | `/reserve?reviewType=companion&reserveId={شناسه رزرو}` |
| Pansion | `{نام} عزیز، لطفاً نظر خود درباره «{نام پانسیون}» را ثبت نمایید.` | `/reserve?reviewType=pansion&reserveId={شناسه رزرو}` |

فرانت باید بعد از کلیک Push، `reviewType` و `reserveId` را از Deep Link بخواند، جزئیات رزرو را دوباره از API بگیرد و فرم نظر همان رزرو را باز کند. وضعیت را فقط از Payload فرض نکنید.

### ثبت نظر Companion

`POST /api/EndUser/CompanionReserveComment`

```json
{
  "companionReserveId": 123,
  "text": "توضیحات کاربر",
  "companionReserveCommentRates": [
    { "assistanceQuestionnaireId": 10, "rate": 5 }
  ]
}
```

ثبت نظر فقط برای صاحب رزروِ رزروشده، لغونشده و تکمیل‌شده مجاز است. همه پرسش‌های فعال همان خدمت باید دقیقاً یک‌بار با امتیاز ۱ تا ۵ ارسال شوند؛ `UserId` از کاربر جاری سرور تعیین می‌شود.

### ثبت نظر Pansion

`POST /api/EndUser/PansionComment`

```json
{
  "pansionReserveId": 456,
  "pansionId": 22,
  "text": "توضیحات کاربر",
  "rate": 5
}
```

رزرو پانسیون نیز باید متعلق به کاربر، رزروشده، لغونشده و در وضعیت تکمیل‌شده باشد. برای هر رزرو فقط یک نظر پذیرفته می‌شود و `PansionId` نهایی از خود رزرو کنترل می‌گردد.

در هر دو فرم، پاسخ موفق با `isSuccess: true` مشخص می‌شود. در خطا، متن `messages[0].item1` به کاربر نمایش داده شود؛ به‌خصوص خطای «ثبت نظر فقط برای رزرو تکمیل‌شده‌ی خودتان امکان‌پذیر است.»

### راه‌اندازی بک‌اند

1. فایل `scripts/database/AddReserveReviewReminderPushes.sql` را یک‌بار روی دیتابیس اجرا کنید تا PushType، Pattern و Settingهای شماره ۴۶ و ۴۷ ایجاد شوند.
2. Migration `LinkPansionCommentsToReserves` را در محیط‌های مختلف اعمال کنید تا `PansionReserveId` و محدودیت یک‌نظر برای هر رزرو ایجاد شود.
3. برای تست، رزرو را به وضعیت تکمیل‌شده ببرید، زمان‌بندی Push را در صف بررسی کنید و سپس با لینک بالا فرم نظر را باز کنید.

این سند مربوط به `app.pastil.pet` و جریان رزرو EndUser است.

## قانون عمومی پاسخ

Endpointهای پروژه ممکن است در خطاهای اعتبارسنجی نیز HTTP 200 برگردانند. موفقیت عملیات فقط با مقدار زیر مشخص می‌شود:

```ts
response.isSuccess === true
```

در حالت ناموفق، متن `messages[0].item1` را بدون تبدیل به پیام عمومی نمایش بده. پیام «خطا در برقراری ارتباط با سرور» فقط برای خطای واقعی شبکه یا پاسخ غیرقابل‌خواندن استفاده شود.

## رزرو خدمات نماینده

### Endpoint

```http
POST /api/EndUser/CompanionReserve
Authorization: Bearer <token>
Content-Type: application/json
```

اگر در Nuxt از Route داخلی استفاده می‌شود، Route داخلی باید همین درخواست را به Endpoint بالا Proxy کند. `bookerId` از توکن در بک تنظیم می‌شود و فرانت نباید آن را مبنای امنیت قرار دهد.

### نمونه Request

```json
{
  "userPetIds": [2],
  "doDate": "2026-08-20T00:00:00+03:30",
  "companionAssistanceId": 3,
  "companionAssistancePackagesIds": [3],
  "companionAssistanceTypeId": 38,
  "companionAssistanceTimeId": 30,
  "companionAssistanceUserId": 12,
  "addressId": null,
  "isFemale": false,
  "bookerDetail": "",
  "assistanceDetail": ""
}
```

### قواعد Dropdownها

- `companionAssistancePackagesIds` فقط از پکیج‌های فعال همان `companionAssistanceId` پر شود.
- `companionAssistanceTypeId` فقط از انواع ارائه متصل به همان خدمت انتخاب شود؛ ID ثابت یا لیست دستی استفاده نشود.
- `companionAssistanceTimeId` فقط از زمان‌های فعال همان خدمت انتخاب شود.
- روز هفته زمان انتخاب‌شده باید با `doDate` یکی باشد. با تغییر تاریخ، زمان قبلی پاک و لیست زمان‌ها دوباره فیلتر شود.
- `companionAssistanceUserId` اختیاری است؛ اگر انتخاب شد باید اپراتور فعال همان خدمت باشد. با تغییر خدمت، مقدار اپراتور قبلی حتماً پاک شود.
- `userPetIds` باید حداقل یک پت متعلق به کاربر جاری داشته باشد.
- برای نوع ارائه در محل مشتری (`CompanionAssistanceType_InPlace`) مقدار `addressId` الزامی و متعلق به کاربر جاری است.
- تاریخ و ساعت گذشته در UI قابل انتخاب نباشد.

هیچ‌کدام از شناسه‌های Package، Type، Time یا Operator مربوط به یک خدمت را برای خدمت دیگری Cache و استفاده نکن.

### فیلدهای محاسباتی

مقادیر زیر را فرانت محاسبه یا به‌عنوان مقدار قابل اعتماد ارسال نکند؛ مبلغ نهایی در بک محاسبه می‌شود:

- `prePaymentPrice`
- `paymentPrice`
- `packagePrice`
- `walletPrice`
- `stateId`
- `operatorStateId`
- `isReserved`
- `isCancel`

### خطاهای قابل نمایش

- `نوع ارائه انتخاب‌شده متعلق به این خدمت نیست.`
- `زمان انتخاب‌شده متعلق به این خدمت نیست یا فعال نیست.`
- `روز تاریخ رزرو با روز زمان انتخاب‌شده هماهنگ نیست.`
- `انتخاب زمان خدمت الزامی است.`
- `اپراتور انتخاب‌شده متعلق به این خدمت نیست یا فعال نیست.`
- `امکان رزرو خدمت در تاریخ گذشته وجود ندارد.`
- `امکان رزرو خدمت در زمان گذشته وجود ندارد.`

در دریافت هرکدام از این خطاها، فرم حفظ شود و فقط فیلد مرتبط مشخص شود؛ صفحه Refresh نشود.

## رزرو پانسیون یا مهد ساعتی

### Endpoint

```http
POST /api/EndUser/PansionReserve
Authorization: Bearer <token>
Content-Type: application/json
```

نوع فرم باید از مقدار `isSchool` خود پانسیون تعیین شود، نه انتخاب آزاد کاربر.

### مهد ساعتی (`isSchool = true`)

```json
{
  "pansionId": 5,
  "userPetId": 2,
  "schoolCreateDate": "2026-08-20T00:00:00+03:30",
  "startTime": "17:00",
  "endTime": "18:00",
  "fromDate": null,
  "toDate": null
}
```

- `schoolCreateDate`، `startTime` و `endTime` الزامی‌اند.
- فرمت ساعت دقیقاً `HH:mm` باشد.
- `endTime` باید بعد از `startTime` باشد.
- زمان شروع گذشته قابل ارسال نیست.
- `fromDate` و `toDate` باید `null` باشند.

### پانسیون روزانه (`isSchool = false`)

```json
{
  "pansionId": 6,
  "userPetId": 2,
  "fromDate": "2026-08-20T00:00:00+03:30",
  "toDate": "2026-08-22T00:00:00+03:30",
  "schoolCreateDate": null,
  "startTime": null,
  "endTime": null
}
```

- `fromDate` و `toDate` الزامی‌اند.
- `toDate` نباید قبل از `fromDate` باشد.
- تاریخ گذشته قابل انتخاب نیست.
- فیلدهای ساعتی باید `null` باشند.

اگر `isSchool` در اطلاعات پانسیون `null` بود، دکمه رزرو غیرفعال و پیام «نوع فعالیت پانسیون مشخص نشده است» نمایش داده شود.

### تداخل رزرو

فقط رزروهای قطعی و پرداخت‌شده/تأییدشده مانع رزرو جدید هستند. رزرو رهاشده‌ای که هنوز `isReserved = false` است نباید تاریخ یا ساعت پت را در UI مسدود کند.

## رفتار پس از ثبت

ثبت دیتابیس قبل از SMS، Push و Notice نهایی می‌شود. خرابی یکی از سرویس‌های اعلان باعث ناموفق‌شدن پاسخ ثبت رزرو نمی‌شود. بنابراین اگر `isSuccess = true` دریافت شد، رزرو ایجاد شده و فرانت نباید به‌علت تأخیر اعلان درخواست را دوباره ارسال کند.

برای جلوگیری از ثبت دوباره:

1. هنگام ارسال، دکمه ثبت Disable شود.
2. بعد از اولین پاسخ موفق، فرم دوباره Submit نشود.
3. کاربر بدون Refresh به صفحه جزئیات رزرو ایجادشده هدایت شود.

## چک‌لیست تست فرانت

- انتخاب Package، Type، Time یا Operator مربوط به خدمت دیگر امکان‌پذیر نباشد.
- با تغییر خدمت، هر چهار انتخاب وابسته Reset شوند.
- با تغییر تاریخ، Time ناسازگار Reset شود.
- رزرو امروز با ساعت گذشته از UI مسدود باشد.
- فرم مهد فقط فیلدهای ساعتی و فرم پانسیون فقط فیلدهای روزانه ارسال کند.
- پیام `messages[0].item1` در خطا نمایش داده شود.
- پاسخ موفق بدون Reload کامل صفحه مدیریت شود.
