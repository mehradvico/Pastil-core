## چرا این تغییر لازم شد

ارائه‌دهنده برای یک مکان، جدا جدا «پانسیون گربه»، «مهد گربه»، «پانسیون سگ بزرگ» و «مهد سگ بزرگ» ثبت کرده بود، چون هر مرکز فقط یک خدمت و یک قیمت داشت. حالا این‌ها یک مرکز است:

- یک مرکز می‌تواند هم پانسیون باشد هم مهد.
- برای هر نوع پت و سایز می‌شود قیمت جدا گذاشت.

**هدف اپ:** ارائه‌دهنده دیگر برای نوع پت یا مهد، مرکز جدا نسازد. فقط **پانسیون عفونی** باید مرکز جدا باشد.

## قرارداد API

### ۱) `isDaycare`

| مقدار | معنی | قیمت‌های لازم |
|---|---|---|
| `false` | فقط پانسیون شبانه | `pansionPrice > 0` |
| `true` | فقط مهد ساعتی | `schoolPrice > 0` |
| `null` | **هر دو خدمت** | هر دو بیشتر از صفر |

سرور `null` با `isInfectious = true` را رد می‌کند.

**تشخیص در خواندن:** رکورد قدیمی هم ممکن است `null` باشد.

| `isDaycare` | قیمت‌ها | برداشت اپ |
|---|---|---|
| `null` | هر دو بیشتر از صفر | هر دو خدمت |
| `null` | حداقل یکی صفر | نوع نامشخص؛ هشدار فعلی «نوع ثبت نشده» نمایش داده شود |

### ۲) ثبت و ویرایش مرکز

`POST /api/Companion/Pansion` و `PUT /api/Companion/Pansion`، با همان بدنه‌ی قبلی. برای حالت هر دو، **`isDaycare` باید با مقدار `null` در بدنه باشد**:

```json
{
  "id": 73,
  "name": "پانسیون هپت",
  "isDaycare": null,
  "isInfectious": false,
  "pansionPrice": 850000,
  "schoolPrice": 150000,
  "stateId": 8,
  "cityId": 112,
  "addressValue": "تهران، خیابان آزادی",
  "location": { "x": 51.389, "y": 35.6892 },
  "openHour": "08:00",
  "closeHour": "22:00"
}
```

برای مرکز تک‌خدمتی مثل قبل قیمت خدمت خاموش را صفر بفرستید. ویرایش مرکز مثل قبل آن را تا تأیید ادمین از رزرو خارج می‌کند.

### ۳) قیمت پت‌ها: `api/Companion/PansionPet`

| کار | درخواست |
|---|---|
| فهرست یک مرکز | `GET /api/Companion/PansionPet?PansionId=73` |
| افزودن | `POST /api/Companion/PansionPet` |
| ویرایش سایز و قیمت | `PUT /api/Companion/PansionPet` |
| حذف | `DELETE /api/Companion/PansionPet?id=11` |

جزئیات مرکز (`GET /api/Companion/Pansion/{id}`) هم `pansionPets` را دارد، ولی **فهرست مراکز (`GET /api/Companion/Pansion`) آن را برنمی‌گرداند.** برای صفحه‌ی پت‌ها از جزئیات یا فهرست بالا بخوانید.

بدنه‌ی افزودن و ویرایش:

```json
{ "id": 11, "pansionId": 73, "petId": 1, "petSize": "Large", "pansionPrice": 500000, "schoolPrice": null }
```

| فیلد | قاعده |
|---|---|
| `id` | برای افزودن `0` |
| `petSize` | `Small`، `Medium`، `Large`؛ `null` = همه‌ی سایزها |
| `pansionPrice` | قیمت هر شب؛ `null` یا صفر = قیمت پایه‌ی مرکز |
| `schoolPrice` | قیمت هر ساعت مهد؛ `null` یا صفر = قیمت پایه‌ی مرکز |

- در `PUT` فقط سایز و قیمت‌ها عوض می‌شوند؛ `pansionId` و `petId` را سرور از ردیف موجود می‌خواند.
- ترکیب تکراری مرکز، پت و سایز رد می‌شود.
- **یک نوع پت می‌تواند چند ردیف داشته باشد.**
- تغییر قیمت پت‌ها مرکز را به بررسی ادمین برنمی‌گرداند و نیازی به هشدار «ارسال دوباره برای بررسی» نیست.

### ۴) قاعده‌ی محاسبه روی سرور

برای نمایش و راهنمای کاربر:

1. مرکز هیچ ردیفی ندارد: همه‌ی پت‌ها با قیمت پایه پذیرفته می‌شوند.
2. نوع پت ردیفی ندارد: رزرو رد می‌شود.
3. ردیف هم‌سایز، وگرنه ردیف «همه‌ی سایزها».
4. هیچ‌کدام نبود: رزرو رد می‌شود. پت بدون سایز فقط با ردیف «همه‌ی سایزها» می‌خواند.
5. ردیف قیمت نداشت: قیمت پایه‌ی مرکز.

**نتیجه برای راهنمای اپ:** اگر برای سگ فقط ردیف کوچک و بزرگ بگذارند، سگ متوسط و سگ بدون سایز نمی‌توانند رزرو کنند. برای پوشش بقیه، یک ردیف «همه‌ی سایزها» هم لازم است.

### ۵) پیام‌های خطا

HTTP 200 با `isSuccess: false` و متن در `messages[0].item1`.

| پیام | حالت |
|---|---|
| مرکز عفونی فقط می‌تواند پانسیون شبانه باشد و مهد ندارد. | **جدید**؛ ثبت مرکز |
| سایز انتخاب‌شده برای پت معتبر نیست. | **جدید**؛ قیمت پت |
| قیمت پت نمی‌تواند منفی باشد. | **جدید**؛ قیمت پت |
| مقدار تکراری است | ردیف تکراری |
| هزینه پانسیون باید بیشتر از صفر باشد. | قیمت پایه |
| هزینه مدرسه باید بیشتر از صفر باشد. | قیمت پایه‌ی مهد |

## ۱) مدل و مخزن

**`PansionItem`:**

```dart
final bool isBoth; // isDaycare == null و هر دو قیمت بیشتر از صفر

bool get offersOvernight => isBoth || !isDaycare;
bool get offersDaycare => isBoth || isDaycare;
```

در نگاشت پاسخ:

```dart
final isBoth = map['isDaycare'] == null &&
    _number(map, const ['pansionPrice', 'price']) > 0 &&
    _number(map, const ['schoolPrice']) > 0;
// isBoth: isBoth,
// typeUnknown: map['isDaycare'] == null && !isBoth,
```

**`PansionDraft`:** فیلد `isBoth` اضافه شود. وقتی `isBoth` روشن است، `isDaycare` برابر `null` است.

اعتبارسنجی:

- `isDaycare == null && !isBoth`: نوع مرکز را انتخاب کنید.
- `isBoth && isInfectious`: مرکز عفونی مهد ندارد.
- برای هر خدمت روشن، قیمت بیشتر از صفر باشد.

**`savePansion`:**

```dart
final both = draft.isBoth;
final daycare = draft.isDaycare == true;
// 'isDaycare': both ? null : daycare,
// 'pansionPrice': both || !daycare ? draft.pansionPrice : 0,
// 'schoolPrice': both || daycare ? draft.schoolPrice : 0,
```

کلید `isDaycare` نباید با حذف `null`ها از بدنه بیفتد.

**`PansionPetItem`:** فیلدهای `petSize` (خالی = همه)، `pansionPrice` و `schoolPrice` (صفر = قیمت پایه).

## ۲) مرحله‌ی نوع مرکز

چهار کارت فعلی می‌ماند، ولی رفتار عوض می‌شود:

| کارت | رفتار |
|---|---|
| پانسیون عادی، عفونی، غیرعفونی | بین خودشان تک‌انتخابی. زدن دوباره‌ی کارت انتخاب‌شده، پانسیون را خاموش می‌کند |
| مهد پت | مستقل و قابل روشن و خاموش |

- انتخاب «پانسیون عفونی»، مهد را خاموش می‌کند.
- روشن‌کردن مهد وقتی عفونی انتخاب شده، نوع پانسیون را به حالت غیر عفونی برمی‌گرداند.
- حداقل یکی باید انتخاب شود.
- متن راهنما: «یک نوع پانسیون را انتخاب کنید و اگر مهد هم دارید «مهد پت» را هم بزنید؛ نیازی به ثبت مرکز جدا نیست.»
- پیش‌فرض ثبت جدید: پانسیون عادی.
- بارگذاری در ویرایش: `isBoth` هر دو را روشن می‌کند؛ نوع نامشخص هیچ‌کدام را.

«پانسیون غیرعفونی» هنوز فیلد جدا در سرور ندارد و مثل «عادی» ذخیره می‌شود؛ این محدودیت از قبل بوده است.

## ۳) مرحله‌ی تعرفه و بازبینی

- برای هر خدمت روشن یک فیلد قیمت نشان دهید: «تعرفه‌ی هر شب اقامت» و «تعرفه‌ی هر ساعت».
- متن محاسبه: پانسیون = تعرفه × تعداد شب؛ مهد = تعرفه × ساعت‌ها (رو به بالا).
- راهنمای زیر فیلدها: «این تعرفه‌ی پایه است. برای قیمت جدا برای سگ کوچک، سگ بزرگ یا گربه، بعد از ثبت از منوی مرکز وارد «پت‌های حاضر» شوید.»
- بازبینی: عنوان ترکیبی مثل «پانسیون عادی و مهد پت» و هر دو قیمت.

## ۴) کارت، جزئیات، فیلتر و آمار

| جا | حالت هر دو |
|---|---|
| برچسب کارت | «اقامتی و مهد» |
| قیمت کارت | «x تومان هر شب · y تومان هر ساعت» |
| برچسب عادی/عفونی | برای هر مرکزی که پانسیون دارد |
| جزئیات | «تعرفه شبانه / ساعتی» و عنوان «پانسیون و مهد پت» |
| فیلتر اقامتی | `offersOvernight` |
| فیلتر مهد | `offersDaycare` |
| آمار | مرکز هر دو در هر دو شمارنده حساب می‌شود |

## ۵) خاموش‌کردن یک نوع پت

کد قبلی با `firstWhere` فقط اولین ردیف را حذف می‌کرد. حالا **همه‌ی ردیف‌های آن `petId`** باید حذف شوند؛ وگرنه کلید خاموش نمی‌شود.

## ۶) «پت‌های حاضر»

برای هر نوع پت روشن:

```
🐶 سگ                                   [روشن]
   کوچک · هر شب: ۳۰۰٬۰۰۰ · هر ساعت: ۵۰٬۰۰۰   ✎ 🗑
   بزرگ · هر شب: ۵۰۰٬۰۰۰ · هر ساعت: قیمت پایه ✎ 🗑
   + قیمت برای سایز دیگر
```

- روشن‌کردن نوع پت، یک ردیف «همه‌ی سایزها» بدون قیمت می‌سازد (رفتار قبلی).
- ستون هر خدمت فقط وقتی نشان داده شود که مرکز آن خدمت را دارد.
- دکمه‌ی حذف فقط وقتی پت بیش از یک ردیف دارد؛ ردیف آخر با کلید نوع پت حذف می‌شود.
- دیالوگ قیمت: انتخاب سایز (سایزهای استفاده‌شده حذف شوند) و قیمت‌ها با راهنمای «خالی = قیمت پایه‌ی مرکز».
- بعد از هر تغییر، فهرست را دوباره از سرور بخوانید.

## سازگاری نسخه‌های قدیمی اپ

| نسخه‌ی قدیمی روی داده‌ی جدید | نتیجه |
|---|---|
| مرکز `null` | به‌عنوان «نوع نامشخص» نمایش داده می‌شود |
| ذخیره‌ی چنین مرکزی | اپ انتخاب یک نوع را اجبار می‌کند و مرکز تک‌خدمتی می‌شود |
| خاموش‌کردن پت با چند ردیف | فقط یک ردیف حذف می‌شود |
| قیمت‌های اختصاصی | نمایش داده نمی‌شوند، ولی سرور اعمال می‌کند |

پس نسخه‌ی جدید اپ باید **قبل از** فعال‌شدن اولین مرکز «هر دو» منتشر شود.
