## ۱) وضعیت جدید ثبت‌نام مدرسه: `Started = 5`

| `statusId` | معنی |
|---|---|
| 1 | ثبت‌نام‌شده (پرداخت‌نشده) |
| 2 | پرداخت‌شده |
| **5** | **دوره شروع شده (جدید)** |
| 3 | تکمیل‌شده |
| 4 | لغوشده |

**چرا اجباری است:** در کد فعلی، مقدار `5` به `SchoolReserveStatus.unknown` می‌رسد. برچسب «نامشخص» می‌گیرد و `isSchoolReservePaid` برایش `false` برمی‌گرداند، پس ثبت‌نام پرداخت‌شده ممکن است پرداخت‌نشده حساب شود.

`features/companion/domain/companion_school_data.dart`:

```dart
enum SchoolReserveStatus {
  registered(1, CodeLabel.reserveRegistered),
  paid(2, CodeLabel.reservePaid),
  started(5, CodeLabel.reservePaid), // جدید؛ برچسب را در UI «دوره شروع شده» بگذارید
  complete(3, CodeLabel.reserveComplete),
  cancelled(4, CodeLabel.operatorCancelled),
  unknown(0, null);
  // ...
}

bool isSchoolReservePaid(Map<dynamic, dynamic> reserve) {
  final status = SchoolReserveStatus.fromId(
    int.tryParse('${reserve['statusId'] ?? ''}'),
  );
  if (status == SchoolReserveStatus.paid ||
      status == SchoolReserveStatus.started || // جدید
      status == SchoolReserveStatus.complete) {
    return true;
  }
  // ...
}
```

`label` از `codeStatus(codeLabel)` می‌آید، پس برای `started` متن «دوره شروع شده» را جدا برگردانید.

هر جا فقط `SchoolReserveStatus.paid` چک شده، `started` را هم اضافه کنید:
- `companion_school_page.dart`: شمارش و فیلتر ثبت‌نام‌های فعال
- `companion_school_course_page.dart`: دکمه‌ی تکمیل (`onComplete`)
- `school_reserves_page.dart`: فیلتر وضعیت و دکمه‌ی تکمیل
- `companion_school_reserve_sheet.dart`: `canComplete`
- `companion_school_repository.dart`: بخشی که با `SchoolReserveStatus.fromId` ردیف‌ها را جدا می‌کند

## ۲) دکمه‌ی «دوره شروع شد»

دوره‌ی حضوری تاریخ ثبت‌شده ندارد، پس شروع دوره را ارائه‌دهنده برای **هر ثبت‌نام** جدا ثبت می‌کند. بعد از آن مشتری نمی‌تواند خودش لغو کند و فقط ادمین می‌تواند.

```
PUT /api/Companion/SchoolReserve/{id}/Start
```
بدون بدنه، مثل `/{id}/Complete`.

| حالت | پاسخ |
|---|---|
| ثبت‌نام پرداخت‌شده (`statusId = 2`) | HTTP 200، `isSuccess=true`؛ `statusId` می‌شود `5` |
| قبلاً شروع، تکمیل یا لغو شده | HTTP 200، `isSuccess=false`؛ متن را از `messages` نشان دهید |
| ثبت‌نام مال این ارائه‌دهنده نیست | HTTP 404 |

ریپازیتوری (`companion_school_repository.dart`، کنار `completeReserve`):

```dart
Future<void> startReserve(int id) => _send(
  () => _dio.put('$_reserve/$id/Start'),
  'ثبت شروع دوره انجام نشد.',
);
```

**UI:**
1. در جزئیات ثبت‌نام و کارت ثبت‌نام، فقط برای دوره‌ی **حضوری** (`courseTypeId = 3`) با `statusId = 2` دکمه‌ی «دوره شروع شد» را نشان دهید.
2. قبل از ارسال، تأیید بگیرید:
   > «بعد از ثبت شروع، مشتری نمی‌تواند ثبت‌نام را لغو کند. ادامه می‌دهید؟»
3. برای `statusId = 5` برچسب «دوره شروع شده» را نشان دهید و دکمه‌ی «دوره شروع شد» را بردارید.
4. دکمه‌ی «تکمیل» برای `2` و `5` فعال باشد. `/{id}/Complete` هر دو را می‌پذیرد.
5. گواهی مثل قبل بعد از تکمیل (`statusId = 3`) است.

## ۳) دوره‌ی حضوری بدون تعیین روز

**قانون:** ارائه‌دهنده برای دوره‌ی حضوری فقط **تعداد جلسات** (`sessionCount`) را می‌زند. زمان جلسات بین خودش و مشتری هماهنگ می‌شود و در پاستیل ثبت نمی‌شود. دوره‌ی ویدیویی و آنلاین زنده تغییری نکرده‌اند.

در `companion_school_course_page.dart`، بخش «جلسه‌های دوره»:

```dart
final isInPerson = course.courseType == SchoolCourseType.inPerson;
final showSessions = !isInPerson || course.sessions.isNotEmpty;
```

| وضعیت دوره | نمایش |
|---|---|
| حضوری بدون جلسه | **کل بخش مخفی**: دکمه‌های «تعیین روزهای دوره» و «افزودن جلسه»، هشدار «برای این دوره N جلسه تعریف کرده‌اید…» و متن «هنوز جلسه‌ای ثبت نشده است». به‌جایش: «زمان جلسات با توافق شما و مشتری تعیین می‌شود.» |
| حضوری قدیمی که جلسه دارد | بخش جلسه‌ها بماند، ولی هشدار کم بودن جلسه و دکمه‌ی «تعیین روزهای دوره» را نشان ندهید. |
| آنلاین زنده | بدون تغییر |

کنار فیلد «تعداد جلسات» در فرم دوره‌ی حضوری بنویسید: «فقط تعداد را وارد کنید؛ زمان جلسات با توافق شما و مشتری است.»

ساخت یا فعال‌کردن دوره را به داشتن جلسه مشروط نکنید. سرور هم چنین شرطی ندارد.

**رفتار دوره‌ی بدون جلسه:**

| موضوع | رفتار سرور | کار اپ |
|---|---|---|
| حضور و غیاب | به جلسه وابسته است | دکمه‌ی حضور و غیاب را مخفی کنید |
| نمره‌ی مهارت | بدون جلسه ثبت می‌شود (`schoolCourseSessionId` خالی) | انتخاب جلسه را اجباری نکنید |
| کارنامه و گواهی | `sessionCount` همان تعداد دوره است؛ `attendance` خالی است | درصد حضور را نشان ندهید |
| یادآوری کلاس | ارسال نمی‌شود | کاری لازم نیست |
| `firstSessionDate`، `sessionsPerWeek`، `totalDurationWeeks` | خالی یا صفر | نمایش ندهید |
| لغو مشتری | تا قبل از «دوره شروع شد»، با برگشت ۱۰۰٪ | در راهنمای ارائه‌دهنده توضیح دهید |

`PUT /api/Companion/SchoolCourseSession/Schedule` حذف نشده است، ولی برای دوره‌ی حضوری جدید لازم نیست.

## ۴) خطای ویرایش عکس مدرسه

**وضعیت:** علت قطعی **هنوز پیدا نشده** و تغییری در بک‌اند برای آن داده نشده است. ذخیره‌ی `pictureId` جدید در منطق سرور روی دیتابیس تست درست کار کرد. برای پیدا کردن علت، پیام واقعی لازم است.

**مسیر فعلی در اپ** (`companion_school_wizard_page.dart`): انتخاب و برش عکس ← `uploadCompanionImage` روی `POST {fileBase}/api/PictureUpload` ← `saveSchool` روی `PUT /api/Companion/School`.

**لطفاً خطا را بازسازی کنید و این‌ها را به تیم بک‌اند بدهید:** متن خطا، کدام درخواست شکست خورد، کد HTTP، بدنه‌ی پاسخ، موبایل حساب و شناسه‌ی مدرسه.

| نشانه | معنی احتمالی | اقدام |
|---|---|---|
| «تصویر…»، «استان و شهر…»، «موقعیت…» یا «حداقل یک قانون…» قبل از ارسال | ویزارد برای تغییر فقط عکس هم همه‌ی مرحله‌ها را اعتبارسنجی می‌کند؛ مدرسه‌ی قدیمی ممکن است موقعیت یا قوانین نداشته باشد | اطلاعات ناقص را به کاربر نشان دهید و مستقیم به همان مرحله ببرید |
| 404 روی `PUT Companion/School` | ارائه‌دهنده یا نمایندگی فعال و تأیید نیست، یا مدرسه مال این حساب نیست | وضعیت حساب در پنل بررسی شود |
| 403 | همکار است و دسترسی بخش پروفایل مدرسه را ندارد | نقش همکار بررسی شود |
| `isSuccess=false` در آپلود | فرمت مجاز نیست یا تصویر بیش از 8000 پیکسل عرض/ارتفاع یا 25 مگاپیکسل است | پیام `messages` را نشان دهید |
| 413 | فایل بزرگ‌تر از ۱۵ مگابایت است | فشرده‌سازی قبل از آپلود |
| 429 | محدودیت تعداد آپلود | پیام «کمی بعد دوباره امتحان کنید» |
| `isSuccess=false` با «عملیات ناموفق» در `PUT` | خطای ذخیره روی سرور | شناسه‌ی مدرسه را برای بررسی لاگ بدهید |

در `uploadCompanionImage` اگر پاسخ خطا `messages` نداشته باشد، کاربر فقط «آپلود تصویر انجام نشد» را می‌بیند و کد HTTP گم می‌شود. لطفاً کد HTTP را لاگ کنید.

## ۵) هشدار قبل از تغییر زمان نوبت

**قانون جدید بک‌اند:** اگر مربی، کلینیک، آرایشگاه یا ادمین زمان نوبت را عوض کند، مشتری تا قبل از شروع نوبت می‌تواند لغو کند و کل مبلغ آنلاین به کیف پولش برمی‌گردد، حتی اگر مهلت لغو رایگان تمام شده باشد.

اندپوینت‌ها عوض نشده‌اند (`.../Reschedule` در `clinic_repository`، `coach_repository` و `groomer_repository`).

**پیشنهاد UI:** در دیالوگ تغییر زمان این سه بخش بنویسید:
> «با تغییر زمان، مشتری تا قبل از شروع نوبت می‌تواند با برگشت کامل مبلغ لغو کند.»

این قانون فقط مربی، کلینیک و آرایشگاه را شامل می‌شود. رزرو قدیمی نماینده و پانسیون تغییر نکرده‌اند.
