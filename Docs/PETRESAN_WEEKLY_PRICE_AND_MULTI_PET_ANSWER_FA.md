# پاسخ به دو گزارش وب‌اپ درباره‌ی سرویس هفتگی پت‌رسان — ۱۴۰۵/۰۷/۰۷

## ۱. تفاوت قیمت بر اساس ساعت — تأیید شد، درست شد

آرمان درست تشخیص داده بود: `PreviewPriceAsync` قیمت یک نوبت را با نرخ «همین الان» حساب می‌کرد و در تعداد نوبت‌ها ضرب می‌کرد؛ `schedules[].time` در محاسبه‌ی قیمت اصلاً استفاده نمی‌شد.

نکته‌ی مهم: **مبلغی که واقعاً از کیف پول کسر می‌شود از اول درست بود.** جاب پس‌زمینه‌ای که هر روز سفر واقعی روز بعد را می‌سازد (`TripService.GeneratePetResanServiceTripsAsync`) از ابتدا نرخ همان ساعت واقعی سفر را حساب می‌کرد. باگ فقط در **پیش‌نمایش قیمت** بود که قبل از ثبت به کاربر نشان داده می‌شد.

**چه چیزی عوض شد:** `PetResanServiceService.CalculateWeeklyTotalPriceAsync` (تابع تازه) حالا هر نوبت یکتا را با نرخ ساعت واقعی خودش حساب و جمع می‌کند. برای پرهیز از فراخوانی تکراری پرهزینه‌ی محاسبه‌ی مسافت، این کار به‌ازای هر **ساعت متفاوت** یک‌بار انجام می‌شود (نه به‌ازای هر ترکیب روز+ساعت) چون نرخ فقط به ساعت وابسته است، نه روز هفته. مقدار ذخیره‌شده‌ی `PricePerOccurrence` روی خود سرویس هم به میانگین درست به‌روزرسانی شد.

بدون تغییر در API — همان `POST /api/EndUser/PetResanService/preview-price` با همان بدنه، فقط عدد برگشتی حالا درست است. کاری برای وب‌اپ لازم نیست.

## ۲. چند پت هم‌زمان — اضافه شد

طبق تصمیم گرفته‌شده، پشتیبانی از چند پت به سرویس هفتگی اضافه شد؛ دقیقاً هم‌الگوی «رزرو فوری» (`Trip.UserPetIds`/`Trip.TripPets`).

### تغییر API (`POST/PUT` مربوط به `PetResanServiceCreateDto`، شامل `preview-price` و ثبت نهایی)

بدنه‌ی درخواست فیلد جدید گرفت:
```jsonc
{
  "userPetIds": [12, 34],   // جدید — آرایه، چند پت مجاز
  "userPetId": 12,          // قدیمی — همچنان پذیرفته می‌شود، فقط اگر userPetIds خالی باشد استفاده می‌شود
  "origin": { ... },
  ...
}
```
- **اگر `userPetIds` پر باشد، اولویت با آن است** و `userPetId` نادیده گرفته می‌شود.
- **اگر `userPetIds` خالی/نال باشد**، مثل قبل با `userPetId` تکی کار می‌کند — یعنی اپ‌های قدیمی بدون هیچ تغییری کار می‌کنند.
- خالی‌بودن هر دو ⇒ خطای «حداقل یک مورد را انتخاب کنید» (`SelectAtLeastOneType`).
- شناسه‌ی تکراری در `userPetIds` ⇒ خطای «مقدار تکراری است» (`DuplicateValue`).
- هر پتی که مال کاربر لاگین‌شده نباشد ⇒ خطای «پیدا نشد» (`NothingFound`) — دقیقاً مثل اعتبارسنجی رزرو فوری.

### تغییر پاسخ (`PetResanServiceVDto`)
فیلد جدید `userPets` اضافه شد:
```jsonc
{
  "id": 501,
  "userPetId": 12,                 // پت اول، فقط برای سازگاری با کدهای قدیمی
  "userPetName": "نودل",
  "userPets": [                    // جدید — فهرست کامل
    { "userPetId": 12, "name": "نودل" },
    { "userPetId": 34, "name": "میشا" }
  ],
  ...
}
```
اگر وب‌اپ می‌خواهد چند پت را نشان دهد، از `userPets` بخواند، نه `userPetId`/`userPetName` (که فقط اولین پت است).

### دیتابیس
جدول جدید `PetResanServicePets` (`PetResanServiceId`, `UserPetId`) — دقیقاً هم‌شکل `TripPets`. سرویس‌های قبلی خودکار بک‌فیل شدند (هرکدام یک ردیف بر اساس `UserPetId` قدیمی‌شان گرفتند)، پس داده‌ی قدیمی هم از `userPets` قابل خواندن است. مایگریشن: `PetResanServiceMultiPet` (ساخته شده، اعمال نشده).

### سفر واقعی هفتگی
`GeneratePetResanServiceTripsAsync` هم به‌روز شد: حالا Trip واقعی هر هفته با همه‌ی پت‌های سرویس ساخته می‌شود (`Trip.TripPets`)، نه فقط پت اول.

## وضعیت
بک‌اند بدون خطا بیلد شد و همه‌ی ۵۶۲ تست موجود سبز است. مایگریشن ساخته شده، اعمال نشده — قبل از دیپلوی بک‌اند باید زده شود.
