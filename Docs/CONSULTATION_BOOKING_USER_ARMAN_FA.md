# مشاوره آنلاین قابل‌رزرو — مستند سمت کاربر (ویژه آرمان)

> مخاطب: توسعه‌دهنده‌ی کلاینتی که **کاربر** با آن مشاوره را رزرو می‌کند · طراحی بک: [ONLINE_CONSULTATION_BOOKING_FA.md](ONLINE_CONSULTATION_BOOKING_FA.md) · مستند نماینده: [CONSULTATION_BOOKING_AGENT_AMIRMOHSEN_FA.md](CONSULTATION_BOOKING_AGENT_AMIRMOHSEN_FA.md)
> پیش‌نیاز: جریان خرید فوری و چت/تماس در [ONLINE_CONSULTATION_APP_FA.md](ONLINE_CONSULTATION_APP_FA.md) و [NOBES_ONLINE_CONSULTATION_CHAT_CALL_VIDEO_FA.md](NOBES_ONLINE_CONSULTATION_CHAT_CALL_VIDEO_FA.md). این مستند فقط **انتخاب ساعت و رزرو** را می‌گوید؛ بعد از «شروع» همه‌چیز (چت، تماس، پنجره، بازگشت، پایان) دقیقاً مثل خرید فوری است.
> وضعیت بک: پیاده‌سازی و تست واحد شد؛ **مایگریشن روی سرور اجرا نشده** — تا اجرا نشود endpointهای جدید خطا می‌دهند. قبل از تست روی سرور از بک بپرسید.
> نکته: این قابلیت **نیازمند ورود کاربر** است و API آن زیر `/api/EndUser/` است. در `/api/Site/` (سایت عمومی `pastil.pet`) هیچ endpoint مشاوره‌ای وجود ندارد؛ اگر قرار است سایت هم رزرو را نشان بدهد، بک باید endpoint عمومی جدا بسازد (در حال حاضر نیست).

همه‌ی endpointها `Authorization: Bearer …` می‌خواهند و پاسخ‌ها **همیشه HTTP 200** با `{ isSuccess, messages, data }` هستند؛ موفقیت را از `isSuccess` بخوانید. فیلدها camelCase.

## ۱) مفهوم

هر پکیج مشاوره یک فیلد `bookable` دارد:

- `bookable: false` ⇒ **خرید فوری** (مثل قبل): می‌خرد، منتظر شروع نماینده می‌ماند.
- `bookable: true` ⇒ **قابل رزرو**: قبل از پرداخت باید یک **ساعت شروع** انتخاب شود. مشاوره در همان ساعت انجام می‌شود (مثلاً «فردا ساعت ۱۶:۰۰ ویدیوکال ۳۰ دقیقه‌ای»).

یک کلینیک می‌تواند هر دو نوع پکیج داشته باشد؛ در فهرست پکیج‌ها هر کدام با `bookable` مشخص است.

## ۲) قاعده‌ی طلایی زمان

همه‌ی زمان‌ها **ساعت دیواری سرور (ایران)** هستند. جزئیات کامل در `ONLINE_CONSULTATION_APP_FA.md` §۲؛ خلاصه برای رزرو:

- ساعت‌هایی که سرور می‌دهد (`start`, `end`, `scheduledStart`, …) **بدون آفست** هستند، مثل `2026-10-03T16:00:00`؛ `serverNow` با آفست می‌آید. همه را بدون تبدیل منطقه‌ی زمانی بخوانید (آفست را حذف کنید) و **همان ساعت دیواری** را به کاربر نشان بدهید.
- موقع ارسال `scheduledStart`: همان رشته‌ی بدون آفستی که از `slots` گرفتید را **عیناً** برگردانید. اگر خودتان `DateTime` می‌سازید، **UTC (`Z`) نفرستید** — سرور `Z` را به ساعت محلی سرور تبدیل می‌کند و ساعت را جابه‌جا می‌بیند.
- «الان» را از `serverNow` بگیرید، نه ساعت گوشی.
- تقویم نمایشی شمسی است؛ مقدار ارسالی/دریافتی میلادی ISO.

## ۳) مرحله ۱ — فهرست پکیج‌ها

`GET /api/EndUser/ConsultationPackage?companionId={id}` (مهمان هم می‌تواند ببیند)

هر آیتم فیلد جدید `bookable` دارد (در کنار `id, name, channelId, durationMinutes, price, companionOnline, …`).

- پکیج `bookable: true`: دکمه‌ی «انتخاب ساعت» (نه «همین الان بخر»). شرط `companionOnline` برای آن **اهمیتی ندارد**: نماینده لازم نیست الان آنلاین باشد؛ چراغ «آنلاین» را برایش نشان ندهید و خرید را به آنلاین بودن مشروط نکنید.
- پکیج `bookable: false`: مثل قبل (و همچنان به `companionOnline` وابسته است).

## ۴) مرحله ۲ — انتخاب روز

`GET /api/EndUser/ConsultationBooking/Days?packageId={id}`

```json
{ "isSuccess": true, "data": {
  "packageId": 12, "durationMinutes": 30,
  "serverNow": "2026-10-03T13:05:00+03:30",
  "days": [
    { "date": "2026-10-03T00:00:00", "weekDayId": 1, "availableSlots": 6 },
    { "date": "2026-10-04T00:00:00", "weekDayId": 2, "availableSlots": 0 },
    …  // ۱۵ روز: امروز تا ۱۴ روز بعد
  ]
}}
```

- یک نوار/تقویم ۱۵ روزه بسازید؛ روزی با `availableSlots == 0` غیرفعال (خاکستری) با متن «ساعت خالی ندارد».
- اگر **همه‌ی** روزها `0` بود: «فعلاً ساعت قابل رزروی برای این پکیج وجود ندارد».
- `weekDayId`: `1` شنبه … `7` جمعه (برای عنوان روز).
- اگر پاسخ `isSuccess: false` با «چیزی یافت نشد» بود: پکیج دیگر فعال/رزروی نیست یا کلینیک بسته است؛ به فهرست پکیج‌ها برگردید.

## ۵) مرحله ۳ — انتخاب ساعت

`GET /api/EndUser/ConsultationBooking/Slots?packageId={id}&date=2026-10-03`

```json
{ "isSuccess": true, "data": {
  "packageId": 12, "durationMinutes": 30,
  "date": "2026-10-03T00:00:00",
  "serverNow": "2026-10-03T13:05:00+03:30",
  "slots": [
    { "start": "2026-10-03T16:00:00", "end": "2026-10-03T16:30:00", "available": true },
    { "start": "2026-10-03T16:15:00", "end": "2026-10-03T16:45:00", "available": false },
    …
  ]
}}
```

- هر `slot` یک **ساعت شروع** ممکن است؛ شروع‌ها هر **۱۵ دقیقه** هستند. `end = start + durationMinutes` (برای نمایش «۱۶:۰۰ تا ۱۶:۳۰»).
- `available: false` ⇒ ظرفیت آن ساعت پر است؛ نمایش خاکستری و غیرقابل‌انتخاب (نه حذف، تا کاربر بفهمد پر شده).
- اسلات‌هایی که کمتر از **۳۰ دقیقه** تا الان مانده‌اند اصلاً در لیست نمی‌آیند. روزهای بیش از ۱۴ روز بعد لیست خالی دارند.
- لیست خالی برای روز ⇒ «در این روز ساعتی وجود ندارد».
- پیشنهاد UI: گروه‌بندی صبح/ظهر/عصر/شب. از شمارنده‌ی «ساعت‌ها هر چند وقت تازه می‌شود» خودداری کنید؛ فقط هنگام ورود به صفحه، بعد از هر خطا، و هنگام فوکوس دوباره بگیرید. لیست یک **عکس لحظه‌ای** است و ممکن است تا لحظه‌ی خرید پر شود (بند ۶).

## ۶) مرحله ۴ — رزرو و پرداخت

`POST /api/EndUser/ConsultationPurchase` + هدر `Idempotency-Key` (UUID، مثل خرید فوری)

```json
{
  "packageId": 12,
  "scheduledStart": "2026-10-03T16:00:00",
  "fromWallet": true,
  "merchantId": null,
  "rebateCode": null
}
```

- `scheduledStart` برای پکیج `bookable` **الزامی** است؛ فقط یکی از `start`های همین `Slots`. برای پکیج فوری نادیده گرفته می‌شود.
- قیمت را هرگز نفرستید (فقط `packageId`). `fromWallet`، `merchantId` و `rebateCode` همان معنی قبلی را دارند؛ شکل پاسخ (`paymentIsLink`, `paymentUrl`) هم همان خرید فوری است ([ONLINE_CONSULTATION_APP_FA.md §۵](ONLINE_CONSULTATION_APP_FA.md)).
- سرور داخل **یک تراکنش** اسلات را دوباره می‌سنجد؛ دو کاربر هم‌زمان یک ظرفیت آخر را نمی‌گیرند. از لحظه‌ی ساخت رزرو تا **۲۰ دقیقه** ظرفیت برای شما نگه داشته می‌شود تا پرداخت کنید؛ اگر پرداخت ناموفق/رها شد، ظرفیت دوباره آزاد می‌شود.

**خطاها** (`isSuccess:false`، متن در `messages`؛ همه‌ی HTTP 200):

| متن پیام | معنی | کار UI |
| --- | --- | --- |
| «برای این پکیج باید ساعت مشاوره را انتخاب کنید.» | پکیج bookable ولی `scheduledStart` نفرستادید | باگ کلاینت؛ برگردید به انتخاب ساعت |
| «ظرفیت این ساعت پر شده است؛ لطفاً ساعت دیگری انتخاب کنید.» | بین نمایش لیست و خرید پر شد | لیست `Slots` را دوباره بگیرید و پیام دوستانه نشان دهید |
| «این ساعت خیلی نزدیک است؛ رزرو باید دست‌کم ۳۰ دقیقه جلوتر باشد.» | ساعت گذشته/نزدیک شد | لیست را تازه کنید |
| «این ساعت برای رزرو معتبر نیست یا خارج از ساعت‌های کاری کلینیک است.» | ساعت روی شبکه نیست/بازه تغییر کرد/خیلی دور | لیست را تازه کنید |
| «شما در همین ساعت مشاوره‌ی دیگری رزرو کرده‌اید.» | تداخل با رزرو دیگر خود کاربر | پیام + لینک «مشاوره‌های من» |
| «شما یک مشاوره‌ی آنلاین فعال دارید؛ …» | فقط برای **پکیج فوری** | رزرو آینده مانع خرید فوری نیست و برعکس |
| پیام‌های قبلی (بدهی باز، مرچنت، موجودی، …) | مثل خرید فوری | بدون تغییر |

**چند رزرو:** کاربر می‌تواند چند رزرو در ساعت‌های **غیرهم‌پوشان** هم‌زمان داشته باشد (برخلاف خرید فوری که فقط یکی). رزرو آینده با خرید فوری تداخلی ندارد.

## ۷) بعد از رزرو — «مشاوره‌های من»

`GET /api/EndUser/ConsultationPurchase` و `GET …/{id}` (فیلدهای جدید):

```json
{
  "id": 21, "status": 2, "channelId": 3, "durationMinutes": 30,
  "packageName": "ویدیوکال رزروی ۳۰ دقیقه‌ای", "companionName": "کلینیک مهر",
  "scheduledStart": "2026-10-03T16:00:00",    // null = خرید فوری
  "scheduledEnd":   "2026-10-03T16:30:00",
  "cancelAllowedUntil": "2026-10-03T14:00:00", // ساعت رزرو − ۲ ساعت
  "startDeadline": "2026-10-03T16:15:00",
  "serverNow": "2026-10-03T13:05:00+03:30"
}
```

- `status == 2` و `scheduledStart != null` ⇒ کارت «رزرو شده برای {تاریخ شمسی} ساعت {HH:mm}» با شمارش معکوس تا شروع. به‌جای «منتظر شروع نماینده» بنویسید «منتظر ساعت مشاوره».
- **لغو:** `PUT /api/EndUser/ConsultationPurchase/{id}/Cancel` با بازپرداخت **کامل** به کیف پول، **فقط تا `cancelAllowedUntil`** (۲ ساعت قبل از ساعت رزرو). بعد از آن دکمه را پنهان/غیرفعال کنید با متن «لغو فقط تا ۲ ساعت قبل از مشاوره ممکن است»؛ اگر هنوز زده شد سرور خطا می‌دهد: «رزرو فقط تا ۲ ساعت قبل از ساعت مشاوره قابل لغو است.». **دکمه را از روی `serverNow` و `cancelAllowedUntil` فعال/غیرفعال کنید، نه ساعت گوشی.**
- **اگر نماینده نیامد:** تا ۱۵ دقیقه بعد از ساعت رزرو (`startDeadline`) صبر می‌شود؛ بعد خودکار `status = 5` (منقضی) و **بازپرداخت کامل** به کیف پول + پوش ۷۴. در کارت بعد از ساعت رزرو و قبل از شروع متن «در انتظار نماینده…» نشان دهید؛ بعد از `startDeadline` «شروع نشد؛ مبلغ برگشت داده شد».
- رزرو منقضی/لغو/بازپرداخت‌شده در فهرست با همان وضعیت‌های قبلی (۵، ۶، ۷) نمایش داده می‌شود.

## ۸) در ساعت مشاوره

1. نماینده از ۱۰ دقیقه قبل می‌تواند «شروع» را بزند؛ معمولاً در ساعت رزرو شروع می‌کند.
2. با شروع، کاربر همان پوش‌ها/اتصال‌های خرید فوری را می‌گیرد: چت ⇒ پوش ۶۶ و صفحه‌ی چت؛ تماس درون‌برنامه/تصویری ⇒ زنگ ورودی (پوش ۶۸/۶۹ و `JoinSessionCall`)؛ تلفنی ⇒ پوش ۷۰ و «نماینده با شما تماس می‌گیرد». جزئیات: `ONLINE_CONSULTATION_APP_FA.md` §۷–۹.
3. وضعیت `3` (در جریان) در `GET …/ConsultationPurchase/Active` می‌آید و **نوار بازگشت** (`ConsultationReturnBar`) را با شمارنده نشان می‌دهد. **رزرو شروع‌نشده (`status == 2`) در `Active` نمی‌آید**؛ برای «رزرو پیش‌رو» از فهرست `GET /ConsultationPurchase` استفاده کنید.
4. پنجره از **لحظه‌ی واقعی شروع** حساب می‌شود (نه از ساعت رزرو): اگر نماینده ۵ دقیقه دیر شروع کند، مدت کامل را می‌گیرید. شمارنده را از `expireDate − serverNow` بسازید.
5. پایان پنجره، فقط‌خواندنی‌شدن چت، `callEnded`، و نظر دادن بعد از `status == 4`: بدون تغییر.

## ۱۰) قواعد خلاصه

| قاعده | مقدار |
| --- | --- |
| شروع‌ها روی شبکه‌ی | ۱۵ دقیقه (۰۰/۱۵/۳۰/۴۵) |
| نزدیک‌ترین زمان قابل رزرو | ۳۰ دقیقه بعد از الان |
| دورترین زمان | ۱۴ روز بعد |
| نگه‌داشتن ظرفیت تا پرداخت | ۲۰ دقیقه |
| لغو آزاد (بازپرداخت کامل) | تا ۲ ساعت قبل از ساعت رزرو |
| نماینده می‌تواند شروع کند | از ۱۰ دقیقه قبل |
| لغو خودکار + بازپرداخت اگر نماینده نیامد | ۱۵ دقیقه بعد از ساعت رزرو |
| جابه‌جایی ساعت رزرو | وجود ندارد؛ لغو (در مهلت) و رزرو دوباره |

**عددها پیش‌فرض‌اند و ممکن است محصول تغییرشان بدهد؛ در کلاینت هاردکد نکنید.** مقدارها را از فیلدها بخوانید (`cancelAllowedUntil`, `startDeadline`) و فقط متن توضیحی را در UI نگه دارید.

## ۱۱) چک‌لیست پیاده‌سازی

- [ ] `bookable` در فهرست پکیج؛ برای رزروی دکمه‌ی «انتخاب ساعت» و بی‌اعتنایی به `companionOnline`
- [ ] صفحه‌ی انتخاب روز (`Days`) و ساعت (`Slots`)، اسلات پر خاکستری، حالت‌های خالی
- [ ] ارسال `scheduledStart` عیناً از لیست اسلات‌ها (بدون UTC)؛ `Idempotency-Key`
- [ ] مدیریت خطاهای بند ۶ (به‌خصوص «ظرفیت پر شده» ⇒ تازه‌سازی ساعت‌ها)
- [ ] «مشاوره‌های من»: کارت رزروی با `scheduledStart`، شمارش معکوس، لغو تا `cancelAllowedUntil`
- [ ] هندل پوش ۸۴ و ۸۵ (و عدم انتظار ۷۲ برای رزروی)
- [ ] نوار بازگشت فقط برای `status == 3` (مثل قبل)
- [ ] همه‌ی محاسبات زمان با `serverNow` و حذف آفست (قاعده‌ی طلایی)
