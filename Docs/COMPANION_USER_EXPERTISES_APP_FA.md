# چند تخصص / عنوان شغلی برای عضو تیم کلینیک — مستند تیم اپ موبایل

> مخاطب: توسعه‌دهنده‌ی اپ (Flutter) و پنل · وب‌اپ و پنل ادمین پیاده شده‌اند

## ۱) خلاصه
قبلاً هر عضو تیم (`CompanionUser`) فقط **یک** تخصص/عنوان شغلی (`expertiseId`) داشت. حالا می‌تواند **چند تخصص** داشته باشد.

- فیلد جدید در ورودی و خروجی: **`expertiseIds`** (آرایه‌ی شناسه‌ها) و در خروجی **`expertises`** (آرایه‌ی `{ id, name, priority, active }`).
- **`expertiseId`** (تکی) همچنان هست و همیشه **تخصص اصلی = اولین مورد `expertiseIds`** است؛ اپ‌های قدیمی که فقط `expertiseId` می‌فرستند/می‌خوانند بدون تغییر کار می‌کنند.
- اولین مورد انتخابی «تخصص اصلی» است؛ **ترتیب انتخاب کاربر حفظ می‌شود**.
- حداکثر ۱۰ تخصص برای هر عضو؛ همه باید فعال و حذف‌نشده باشند.

## ۲) نوشتن (نماینده)

| کار | endpoint | بدنه |
| --- | --- | --- |
| افزودن عضو | `POST /api/Companion/CompanionUser` | `{ "phone": "0912…", "expertiseIds": [1, 2] }` |
| ویرایش تخصص‌ها/فعال بودن | `PUT /api/Companion/CompanionUser` | `{ "id": 7, "active": true, "expertiseIds": [2, 3] }` |

- در `PUT` اگر `expertiseIds` (یا `expertiseId`) **نفرستید** تخصص‌ها دست‌نخورده می‌مانند و فقط `active` عوض می‌شود.
- فقط `expertiseId` تکی هم پذیرفته می‌شود (معادل `expertiseIds: [id]`).
- اگر `expertiseIds` خالی باشد در **ساخت** خطا می‌دهد («عنوان شغلی معتبر انتخاب کنید»)؛ حداقل یک مورد لازم است.
- پاسخ‌ها مثل همیشه HTTP 200 با `isSuccess`.

## ۳) خواندن

`GET /api/Companion/CompanionUser`، `GET …/{id}` و فهرست عمومی (کلینیک/پزشکان) حالا این شکل را دارند:

```json
{
  "id": 7,
  "expertiseId": 1,                    // تخصص اصلی
  "expertiseIds": [1, 2],
  "expertise": { "id": 1, "name": "دامپزشک عمومی" },
  "expertises": [
    { "id": 1, "name": "دامپزشک عمومی" },
    { "id": 2, "name": "متخصص پوست" }
  ]
}
```

- پروفایل کاربر (`user.expertise`، رشته) بعد از **تأیید عضویت** به‌صورت متن ترکیبی می‌آید: «دامپزشک عمومی، متخصص پوست».
- فهرست همه‌ی عنوان‌های قابل انتخاب: همان endpoint قبلی `Expertise` (`Available=true`).

## ۴) UI پیشنهادی در اپ (صفحه‌ی «ویرایش عضو تیم»)
- به‌جای Dropdown تکی، **چند انتخابی** (چیپ‌های قابل انتخاب یا BottomSheet با Checkbox) بگذارید.
- ترتیب انتخاب را نگه دارید و اولی را «عنوان اصلی» نشان دهید.
- دکمه‌ی «ذخیره تغییرات» فقط وقتی فعال باشد که حداقل یک تخصص انتخاب شده.
- در نمایش کارت عضو، همه‌ی نام‌ها را با «،» جدا کنید (یا `expertises.map(name)`).

## ۵) دیتابیس (توجه: نیاز به مایگریشن)
- جدول جدید `CompanionUserExpertises` (`CompanionUserId`, `ExpertiseId`، یکتا روی جفت).
- مایگریشن: `AddCompanionUserExpertises` — اسکریپت idempotent: `backend/scripts/AddCompanionUserExpertises.sql` (یا `update-database`).
- مایگریشن **داده‌ی قبلی را حفظ می‌کند**: هر عضوی که تخصص تکی داشت همان یک تخصص را در جدول جدید هم می‌گیرد.
- تا مایگریشن اجرا نشود، بک‌اند جدید خطای «جدول پیدا نشد» می‌دهد؛ ترتیب دیپلوی: مایگریشن ← بک‌اند.
