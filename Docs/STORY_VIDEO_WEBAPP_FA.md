# استوری ویدیویی: پخش در وب‌اپ (طول استوری = طول ویدیو)

**وضعیت:** پیاده‌سازی و تست شد (۲۰۲۶-۱۰-۱۷). commit و دیپلوی نشده است.
**دیپلوی لازم:** Api، File، وب‌اپ و پنل (فقط متن راهنمای آپلود). ترتیب مهم نیست، چون هیچ‌کدام به دیگری وابسته نیستند.

---

## ۰. مشکل

گزارش: «استوری را باز می‌کنم، صفحه مشکی و خالی است.» این برای استوری‌هایی بود که در پنل با نوع **ویدیو** ثبت شده‌اند.

| علت | جا | وضعیت |
|---|---|---|
| ویوور فقط `<img>` داشت و آدرس را فقط از `picture` می‌ساخت. ویدیو در `file` است، پس چیزی نمایش داده نمی‌شد و تایمر ثابت ۵ ثانیه روی صفحه‌ی سیاه می‌گذشت. | وب‌اپ `StoryViewer.vue` | ✅ |
| `ensureItemDetails` برای آیتم بدون تصویر جزئیات می‌گرفت و کل آیتم را عوض می‌کرد. جزئیات `file` نداشت، پس همان `file` فهرست هم پاک می‌شد. | وب‌اپ | ✅ |
| `GET /api/StoryItem/{id}` جدول `File` را Include نمی‌کرد. | بک‌اند `StoryItemService` | ✅ |
| فایل‌هایی که فقط روی Object Storage هستند (همه‌ی آپلودهای جدید) با 200 و کل فایل سرو می‌شدند و `Range` نادیده گرفته می‌شد. **Safari/iOS بدون پاسخ 206 ویدیو را پخش نمی‌کند.** | File service `Program.cs` | ✅ |
| بعد از نگه‌داشتن انگشت (مکث)، رها کردن به‌عنوان «تپ» حساب می‌شد و به استوری بعدی می‌رفت. | وب‌اپ | ✅ |
| فوتر (لایک/پروفایل) و اشتراک‌گذاری برای ویدیو کار نمی‌کرد. | وب‌اپ | ✅ |

## ۱. رفتار فعلی

| وضعیت | رفتار |
|---|---|
| استوری تصویری | مثل قبل: ۵ ثانیه با cross-fade |
| استوری ویدیویی | پخش تمام‌قاب. نوار پیشرفت از `currentTime / duration` پر می‌شود و استوری بعدی **دقیقاً با رویداد `ended`** می‌آید، پس طول استوری = طول ویدیو. |
| نگه‌داشتن انگشت (بیش از ۲۵۰ms) | ویدیو و نوار می‌ایستند. با رها کردن از همان نقطه ادامه می‌دهد و به استوری بعد/قبل نمی‌رود. |
| کشیدن افقی / جابه‌جایی گروه / کشیدن به پایین (بستن) | ویدیو فوراً متوقف می‌شود. با بستن، src هم خالی می‌شود و دانلود قطع می‌شود. |
| رفتن اپ به پس‌زمینه | ویدیو و نوار متوقف می‌شوند و با برگشت ادامه می‌دهند. |
| صدا | اول **با صدا** پخش می‌شود (المان ویدیو داخل همان تپ باز کردن استوری برای صدا باز می‌شود، بخش ۲). اگر مرورگر باز هم اجازه ندهد: پخش بی‌صدا + دکمه‌ی «برای پخش صدا لمس کنید». هر لمس بعدی صدا را برمی‌گرداند. |
| دکمه‌ی بلندگو (هدر) | iOS: فقط قطع/وصل (بلندی صدا در Safari فقط با دکمه‌های خود گوشی تغییر می‌کند و `video.volume` فقط‌خواندنی است). بقیه: لمس اول نوار بلندی صدا را باز می‌کند، لمس دوم (با نوار باز) قطع می‌کند، روی حالت قطع، صدا را وصل می‌کند. نوار بعد از ۲٫۵ ثانیه بی‌کاری بسته می‌شود. |
| ترجیح صدا | قطع/بلندی در `localStorage` همان مرورگر می‌ماند (`pastil-story-muted` / `pastil-story-volume`). |
| حتی پخش بی‌صدا هم مجاز نیست (Low Power در iOS) | دکمه‌ی ▶ وسط صفحه. استوری منتظر می‌ماند (اسپینر و جلو رفتن ندارد) تا کاربر لمس کند. |
| بارگذاری / بافر | اسپینر بعد از ۲۶۰ms. اگر ۲۰ ثانیه پخش شروع نشود (مکث کاربر حساب نیست)، مثل خطا رفتار می‌کند. |
| فایل خراب / ناسازگار | «پخش این ویدیو ممکن نشد» و بعد از ۵ ثانیه استوری بعدی |
| اشتراک‌گذاری ویدیو | فقط لینک فایل ویدیو (کل فایل دانلود نمی‌شود) |

## ۲. پیاده‌سازی

### وب‌اپ: `app/components/home/StoryViewer.vue`
- `isVideoItem(item)` = `file.url` دارد و `picture.guidName` ندارد. آدرس = `showImageBaseUrl` + `/` + `file.url`.
- **یک المان `<video>` ثابت** برای کل عمر ویوور (`videoEl`، با `document.createElement`) که با `setVideoHost` داخل کارت فعلی جابه‌جا می‌شود. iOS پخش با صدا را فقط به المانی اجازه می‌دهد که یک بار داخل لمس کاربر play شده باشد. اگر برای هر استوری المان تازه ساخته شود، هر ویدیو دوباره بی‌صدا می‌شود.
- `primeVideoFromGesture()` همگام داخل رویداد لمس صدا زده می‌شود: در `Story.vue` → `openStory`، روی لایه‌ی ژست (`@click`)، دکمه‌ی صدا و دکمه‌ی ▶.
- `playVideo()` برای هر src فقط یک تلاش در جریان دارد. «حتی بی‌صدا هم مجاز نیست» فقط وقتی نتیجه گرفته می‌شود که تلاشِ بی‌صدا خودش `NotAllowedError` بگیرد. (نسخه‌ی اول که هم‌زمانی را مدیریت نمی‌کرد در تست به اشتباه دکمه‌ی ▶ نشان می‌داد.)
- `watch(videoShouldPlay)` پخش/مکث را با `isPaused`، `dragging`، `animating`، `pageHidden` و `needsTap` هماهنگ می‌کند. این watch در انتهای script است، چون getter همان لحظه اجرا می‌شود.
- `frame()`: در حالت ویدیو نوار از زمان پخش است. در غیر این صورت همان تایمر ۵ ثانیه‌ای.
- `HOLD_MS = 250`: نگه‌داشتن طولانی‌تر = مکث، و رها کردن فقط `resume()`.
- هدر: اسم ارائه‌دهنده `truncate` شده تا با باز شدن نوار صدا دو خطی نشود.

### بک‌اند
- `Application/Services/Content/StoryItemSrv/StoryItemService.cs`: `FindAsyncVDto` و `FindAsyncAdminVDto` حالا `.Include(s => s.File)` دارند.
- `Application/Common/Storage/ObjectStorageService.cs` و `IObjectStorageService.cs`: `TryGetAsync(key, byteRange)` بازه را به S3 (`GetObjectRequest.ByteRange`) می‌دهد و `ContentLength` / `ContentRange` / `RangeNotSatisfiable` برمی‌گرداند.
- `File/Program.cs` (fallback فایل‌های Object Storage): `Range` تک‌بازه‌ای → 206 + `Content-Range` + `Content-Length` + `Accept-Ranges: bytes`. بازه‌ی نامعتبر → 416. فایل‌های روی دیسک مثل قبل از `UseStaticFiles` (که از قبل Range را پشتیبانی می‌کرد) سرو می‌شوند.

### پنل: `components/base/VideoUploader.vue`
- متن راهنما: MP4 با H.264 بهترین است.
- اگر پیش‌نمایش در مرورگر ادمین پخش نشود: «احتمالاً روی گوشی کاربران هم پخش نمی‌شود؛ به MP4 (H.264) تبدیل و دوباره آپلود کنید.»
- MOV آیفون معمولاً HEVC است و روی بعضی اندرویدها/ویندوزها پخش نمی‌شود. تبدیل خودکار سمت سرور وجود ندارد (`docs/ai/KNOWN_ISSUES.md`).

## ۳. تست‌هایی که انجام شد

وب‌اپ واقعی (`nuxt dev`) روی یک mock بک‌اند با ویدیوی ۱۰ ثانیه‌ای باصدا، دو ویدیوی بی‌صدای ۱۰٫۴ و ۱۳ ثانیه‌ای، یک تصویر و یک ویدیوی خراب (404). سرور mock از Range پشتیبانی می‌کرد.

| سناریو | نتیجه |
|---|---|
| اجرای کامل از تپ اول تا بسته شدن (۳ گروه) | ویدیوی ۱: با صدا، ۷۰ms بعد از تپ شروع شد و با `ended` تمام شد. تصویر: ۴٫۹۶ ثانیه. ویدیوی ۲: ۱۰٫۵۵ ثانیه (طول ۱۰٫۴۴). گروه ۲: دقیقاً ۱۳٫۰ ثانیه. ویدیوی خراب: پیام خطا و ۵ ثانیه بعد تصویر. پایان گروه آخر: بسته شد. |
| نوار پیشرفت | ۹۰٫۵۷٪ در t=11.78 از 13.0 (دقیقاً برابر) |
| نگه‌داشتن ۲ ثانیه وسط ویدیو | مکث، زمان و نوار ثابت. بعد از رها کردن از همان نقطه ادامه داد و استوری عوض نشد. |
| نوار صدا | باز شد، ۰٫۳ ← `volume=0.3`. لمس دوم ← قطع. لمس سوم ← وصل با همان بلندی. ۰ ← قطع، ۰٫۸ ← وصل. ترجیح ذخیره شد. |
| مرورگر صدا را می‌بندد (شبیه‌سازی سیاست autoplay) | پخش بی‌صدا + دکمه‌ی «برای پخش صدا لمس کنید». لمس ← صدا برگشت و پخش ادامه داشت. |
| مرورگر حتی بی‌صدا هم اجازه نمی‌دهد | دکمه‌ی ▶، بدون اسپینر و بدون جلو رفتن. لمس ← پخش. |
| کشیدن افقی وسط ویدیو | مکث حین کشیدن. گروه قبلی آمد و ویدیوی قبلی قطع شد. |
| پس‌زمینه / برگشت | مکث (زمان و نوار ثابت) / ادامه |
| کشیدن به پایین | بسته شد و src خالی شد |
| اشتراک‌گذاری | لینک ویدیو فرستاده شد و پخش ادامه داشت |
| لایک و لینک پروفایل حین ویدیو | نمایش داده می‌شوند |
| lint / تست‌ها | فایل‌های تغییرکرده: ۰ خطا (تعداد warningها همان قبل). `story-viewer-transition.test.mjs` پاس. ۹ تست دیگر وب‌اپ و افزایش baseline لینت **بدون این تغییر هم** fail هستند (روی HEAD بررسی شد). |
| build بک‌اند | `Application` و `File` بدون خطا build شدند |

**تست نشده:** iPhone و اندروید واقعی، و سرور واقعی (از این سیستم به `api.pastil.pet` / `file.pastil.pet` دسترسی نبود). سیاست autoplay در مرورگر تست شبیه‌سازی شد. رفتار واقعی Safari را فقط روی خود آیفون می‌شود دید.

## ۴. چک‌لیست بعد از دیپلوی (روی گوشی واقعی)

1. iPhone (Safari و PWA نصب‌شده): اولین استوری ویدیویی بعد از تپ روی حلقه **با صدا** شروع شود. نوار با پایان ویدیو پر شود و استوری بعدی بیاید.
2. iPhone در حالت Low Power: دکمه‌ی ▶ بیاید و با لمس پخش شود.
3. Android Chrome: صدا، نوار صدا و دکمه‌های صدای خود گوشی.
4. نگه‌داشتن، کشیدن به گروه دیگر و بستن وسط پخش: صدای ویدیو نباید ادامه پیدا کند.
5. یک ویدیوی تازه آپلودشده (روی Object Storage) روی iPhone پخش شود. اگر نشد، از سیستمی که به سرور دسترسی دارد:

   ```bash
   curl -sI -r 0-1 "https://file.pastil.pet/<file.url>"
   ```

   باید `206`، `Content-Range: bytes 0-1/...` و `Content-Type: video/mp4` برگردد. اگر nginx جلوی File service است، نباید `Range` را حذف کند یا بافر کامل اجباری داشته باشد.
