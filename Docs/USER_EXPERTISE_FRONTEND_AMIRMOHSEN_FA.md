# راهنمای عنوان شغلی پروفایل کاربر برای فرانت اپ

## قانون اصلی

فیلد `expertise` فقط برای یکی از کاربران زیر قابل ثبت و نمایش است:

1. صاحب یک نمایندگی فعال و تأییدشده؛
2. کاربر یک نمایندگی فعال و تأییدشده که عضویت خودش را تأیید کرده و عضویتش فعال است.

کاربر عادی، کاربر در انتظار تأیید، کاربر ردشده، عضو غیرفعال و صاحب نمایندگی تأییدنشده امکان ثبت عنوان شغلی ندارد.

## دریافت وضعیت کاربر

```http
GET /api/EndUser/CurrentUser
Authorization: Bearer {token}
```

در `data` دو فیلد مرتبط وجود دارد:

```json
{
  "expertise": "دامپزشک جراح",
  "canSetExpertise": true,
  "isCompanionUser": true
}
```

- `canSetExpertise=true`: فیلد عنوان شغلی نمایش داده و قابل ویرایش باشد.
- `canSetExpertise=false`: فیلد عنوان شغلی کاملاً مخفی شود و در درخواست ویرایش مقدار `null` ارسال شود.
- وقتی `canSetExpertise=false` باشد، بک نیز مقدار `expertise` را در اطلاعات پروفایل نمایش نمی‌دهد.

برای تصمیم‌گیری UI فقط از `canSetExpertise` استفاده کنید و وضعیت را از روی `companionId` یا مقادیر محلی حدس نزنید.

## ویرایش پروفایل

```http
PUT /api/EndUser/User
Authorization: Bearer {token}
Content-Type: application/json
```

بک شناسه کاربر را از توکن استخراج می‌کند. مقدار `id` ارسالی فرانت قابل اعتماد نیست و برای کاربر جاری بازنویسی می‌شود.

نمونه برای عضو مجاز:

```json
{
  "id": 0,
  "mobile": "09120000000",
  "firstName": "امیرمحسن",
  "lastName": "رجایی",
  "email": "",
  "expertise": "دامپزشک عمومی",
  "isFemale": false
}
```

نمونه برای کاربر غیرمجاز:

```json
{
  "id": 0,
  "mobile": "09120000000",
  "firstName": "امیرمحسن",
  "lastName": "رجایی",
  "email": "",
  "expertise": null,
  "isFemale": false
}
```

اگر کاربر غیرمجاز مقدار غیرخالی ارسال کند، پاسخ ناموفق با خطای فیلد `Expertise` دریافت می‌شود:

```json
{
  "isSuccess": false,
  "messages": [
    {
      "item1": "عنوان شغلی فقط برای صاحب نمایندگی یا عضو فعال و تأییدشده نمایندگی قابل ثبت است.",
      "item2": "Expertise"
    }
  ]
}
```

## تغییر وضعیت عضویت

بعد از تأیید یا غیرفعال‌شدن عضویت، اطلاعات `CurrentUser` مجدداً دریافت شود. وضعیت `canSetExpertise` منبع نهایی نمایش فیلد است.

پس از تأیید عضویت:

1. درخواست تصمیم عضویت با موفقیت تمام شود؛
2. `GET /api/EndUser/CurrentUser` دوباره اجرا شود؛
3. در صورت `canSetExpertise=true` فیلد عنوان شغلی نمایش داده شود.
