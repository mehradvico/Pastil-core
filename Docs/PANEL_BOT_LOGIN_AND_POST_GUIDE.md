# راهنمای ورود ربات به پنل و نوشتن مقاله (Post)

این مستند برای رباتی نوشته شده که قراره خودکار وارد سیستم بشه، عکس کاور آپلود کنه و مقاله (Post) ثبت کنه. همه‌چیز رو قدم‌به‌قدم و با مثال واقعی JSON توضیح دادم.

**آدرس‌های پایه:**
- سرویس اصلی API: `https://api.pastil.pet`
- سرویس فایل (آپلود عکس): `https://file.pastil.pet`

همه‌ی پاسخ‌های API با همین ساختار برمی‌گردن (همیشه HTTP 200، موفقیت واقعی رو از `isSuccess` بخون، نه status code):

```json
{
  "isSuccess": true,
  "code": 0,
  "messages": [],
  "data": { ... }
}
```

---

## قدم اول: پیش‌نیاز — ساخت اکانت ربات (کار تیم بک‌اند)

قبل از اینکه ربات بتونه کار کنه، یک نفر از تیم بک‌اند باید یک بار این کار رو انجام بده (این بخش کار خود رباته نیست، فقط برای اطلاعت می‌نویسم که بدونی چرا لازمه):

1. یک نقش (Role) جدید به اسم مثلاً «تولیدکننده محتوا» ساخته می‌شه (نه نقش Admin — دسترسی محدود می‌مونه).
2. به این نقش، فقط دسترسی «ثبت مقاله» و «ویرایش مقاله» داده می‌شه (نه دسترسی‌های دیگه).
3. یک کاربر (User) با موبایل و رمز عبور مشخص، با این نقش ساخته می‌شه و **کد یک‌بارمصرف (OTP) روی اکانتش غیرفعال** می‌مونه — یعنی ربات فقط با موبایل+رمز عبور وارد می‌شه، نیازی به کد تأیید نداره.

بعد از این مرحله، موبایل و رمز عبور این اکانت رو بهت می‌دن و ربات با همون‌ها وارد می‌شه.

## قدم دوم: ورود (Login) و گرفتن توکن

```
POST https://api.pastil.pet/api/Account/signin
Content-Type: application/json
```

بدنه‌ی درخواست:

```json
{
  "mobile": "09120000000",
  "password": "رمز عبور اکانت ربات",
  "isAdmin": true,
  "rememberMe": true
}
```

⚠️ نکته‌ی مهم: `isAdmin` حتماً باید `true` باشه، وگرنه سیستم اجازه‌ی ورود به پنل رو نمی‌ده (چون این ورود مخصوص کاربرای پنل مدیریتیه، نه اپلیکیشن مشتری).

پاسخ موفق:

```json
{
  "isSuccess": true,
  "code": 0,
  "messages": [],
  "data": {
    "token": "eyJhbGciOiJIUzI1NiIs...",
    "refreshToken": "b3f1b0a2-....",
    "tokenExp": "2026-08-28T10:00:00",
    "refreshTokenExp": "2026-09-04T10:00:00",
    "userId": 123,
    "firstName": "...",
    "lastName": "..."
  }
}
```

مقدار `data.token` همون توکنیه که باید توی همه‌ی درخواست‌های بعدی بفرستی. اسمش دقیقاً `token` هست، نه `accessToken`.

### فرستادن توکن در درخواست‌های بعدی

توی هدر هر درخواست (چه به `api.pastil.pet` چه به `file.pastil.pet`) این هدر رو اضافه کن:

```
Authorization: Bearer eyJhbGciOiJIUzI1NiIs...
```

### وقتی توکن منقضی شد

توکن یک تاریخ انقضا داره (`tokenExp`). وقتی نزدیک انقضا یا بعد از انقضا بود، به‌جای لاگین دوباره از این استفاده کن:

```
POST https://api.pastil.pet/api/Account/refreshtoken
Content-Type: application/json
```

```json
{
  "refreshToken": "b3f1b0a2-...."
}
```

پاسخش دقیقاً همون ساختار توکن جدیده (`data.token` جدید).

## قدم سوم: آپلود عکس و ویدیو

قبل از ثبت مقاله، اگه می‌خوای عکس کاور (یا هر عکس/ویدیوی دیگه‌ای داخل متن مقاله) داشته باشه، اول باید فایل رو آپلود کنی و شناسه‌اش (`Id`) رو بگیری. **آپلود عکس و ویدیو دقیقاً از یک endpoint یکسان انجام می‌شه**، فرقی نمی‌کنه چه فایلی بفرستی:

```
POST https://file.pastil.pet/api/PictureUpload
Authorization: Bearer <توکن>
Content-Type: multipart/form-data
```

فرم‌دیتا فقط یک فیلد داره، دقیقاً با همین اسم:

| نام فیلد | نوع |
|---|---|
| `PictureFile` | فایل عکس یا ویدیو |

پسوندهای مجاز:
- **عکس:** `jpg`, `jpeg`, `png`, `webp`
- **ویدیو:** `mp4`, `webm`, `ogg`

محدودیت‌ها: حداکثر حجم فایل ۵ مگابایت (برای هر دو نوع). برای عکس، حداکثر ابعاد ۸۰۰۰×۸۰۰۰ پیکسل هم اضافه می‌شه.

### تفاوت رفتار عکس و ویدیو بعد از آپلود

| | عکس | ویدیو |
|---|---|---|
| تبدیل فرمت | همیشه به `webp` تبدیل می‌شه (حتی اگه jpg/png فرستاده باشی) | فرمت اصلی فایل حفظ می‌شه (mp4/webm/ogg) |
| سایزهای مختلف | ۳ نسخه‌ی `sm`/`md`/`lg` هم خودکار ساخته می‌شه | فقط همون یک فایل اصلی ذخیره می‌شه، نسخه‌ی دیگه‌ای ساخته نمی‌شه |
| نام فایل | `{guidName}.webp` + `{guidName}-sm.webp` و... | `{guidName}.{پسوند اصلی}` |

پاسخ موفق (برای هر دو نوع، ساختار یکسانه):

```json
{
  "isSuccess": true,
  "code": 0,
  "messages": [],
  "data": {
    "id": 4521,
    "guidName": "a1b2c3d4e5f6...",
    "url": "...",
    "extension": ".webp"
  }
}
```

مقدار `data.id` رو نگه دار — همین رو باید بعداً به‌عنوان `pictureId` توی درخواست ثبت مقاله بفرستی (برای عکس کاور).

> اگه مقاله عکس کاور نداشته باشه هم اشکالی نداره، فیلد `pictureId` رو خالی (`null`) بذار یا اصلاً نفرست.

> اگه می‌خوای چند تا عکس یا ویدیوی اضافه (نه فقط کاور) به مقاله وصل کنی — مثلاً یک گالری یا یک ویدیوی داخل متن — بعد از آپلود هرکدوم و گرفتن `id`شون، می‌تونی توی درخواست ثبت مقاله (قدم پنجم) از فیلد `postPicturesList` استفاده کنی: آرایه‌ای از `{ "pictureId": <شناسه> }`. برای نمایش ویدیو *داخل* متن مقاله هم راه ساده‌تر اینه که تگ `<video>` رو مستقیم توی HTML فیلد `description` بنویسی و آدرس فایل رو بهش بدی (آدرس فایل از فرمول قسمت پایین به دست میاد).

### فرمول آدرس نهایی فایل

بعد از آپلود، برای ساختن URL قابل‌نمایش فایل (چه عکس چه ویدیو) از این فرمول استفاده کن:

```
{baseUrl}/{guidName}-{size}{extension}
```

- `baseUrl` همون `https://file.pastil.pet` هست.
- برای عکس، `size` یکی از `sm`/`md`/`lg` هست (بسته به اینکه چه سایزی لازم داری).
- برای ویدیو، بخش `-{size}` اصلاً وجود نداره — فقط `{baseUrl}/{guidName}{extension}`.

## قدم چهارم: پیدا کردن شناسه‌ی دسته‌بندی (Category)

مقاله‌ها می‌تونن به یک یا چند دسته‌بندی وصل بشن (فیلد `categoryId`/`categoryIds` توی قدم بعدی). برای اینکه بدونی شناسه‌ی هر دسته‌بندی چیه، این endpoint رو صدا بزن:

```
GET https://api.pastil.pet/api/Admin/Category?ParentId=31&PageSize=50
Authorization: Bearer <توکن>
```

- `ParentId=31` یعنی «فقط زیردسته‌های مستقیمِ دسته‌بندی مادر مقالات (شناسه‌ی ۳۱) رو بده» — چون همه‌ی دسته‌بندی‌های مربوط به مقاله، زیرشاخه‌ی همین دسته‌ی مادر هستن.
- اگه `ParentId` رو ندی، همه‌ی دسته‌بندی‌های موجود (از هر نوعی، نه فقط مقاله) برمی‌گرده — پس همیشه `ParentId` رو بفرست.
- برای رفتن به عمق بعدی (مثلاً زیردسته‌های «سگ»)، همین درخواست رو با `ParentId=<شناسه‌ی سگ>` دوباره بزن.

پاسخ موفق:

```json
{
  "isSuccess": true,
  "code": 0,
  "messages": [],
  "data": {
    "list": [
      { "id": 45, "name": "سگ", "parentId": 31, "active": true, "priority": 1 },
      { "id": 46, "name": "گربه", "parentId": 31, "active": true, "priority": 2 }
    ],
    "totalCount": 8
  }
}
```

از هر آیتم فقط `id` رو لازم داری — همین رو توی `categoryId`/`categoryIds` قدم بعدی بفرست. اگه اسم دسته‌بندی موردنظرت رو نمی‌دونی چه شناسه‌ای داره، اول یک‌بار با `ParentId=31` لیست دسته‌های اصلی (سگ، گربه، پرنده، ...) رو بگیر، بعد با شناسه‌ی همون دسته، `ParentId` بزن تا زیردسته‌هاش (نگهداری و مراقبت، تغذیه، ...) رو ببینی.

## قدم پنجم: ثبت مقاله (Post)

```
POST https://api.pastil.pet/api/Admin/Post
Authorization: Bearer <توکن>
Content-Type: application/json
```

نمونه‌ی کامل بدنه‌ی درخواست:

```json
{
  "name": "۱۰ نکته برای نگهداری از سگ در آپارتمان",
  "label": "10-tips-for-dog-apartment",
  "description": "<p>متن کامل مقاله اینجا قرار می‌گیرد، به‌صورت HTML...</p>",
  "summary": "خلاصه‌ی کوتاه مقاله برای نمایش در لیست",
  "subNews": "زیرعنوان کوتاه که در کارت‌های لیست بلاگ نشان داده می‌شود",
  "pictureId": 4521,
  "active": true,
  "publishDate": "2026-08-28T10:00:00",
  "categoryId": 45,
  "categoryIds": [45],
  "hashTagList": ["سگ", "نگهداری از حیوانات"],
  "seoH1": "نگهداری از سگ در آپارتمان",
  "seoTitle": "۱۰ نکته برای نگهداری از سگ در آپارتمان | پاستیل",
  "seoMinDescription": "خلاصه‌ی کوتاه برای نتیجه‌ی گوگل، حداکثر ۱۶۰ کاراکتر",
  "seoDescription": "توضیحات کامل‌تر سئو، محدودیت طول ندارد",
  "seoPictureAlt": "سگ نژاد پاگ در حال بازی در آپارتمان",
  "seoUrlText": "10-tips-for-dog-apartment",
  "seoCanonical": "",
  "seoNoIndex": false,
  "seoNoFollow": false
}
```

### توضیح فیلدها

| فیلد | اجباری؟ | توضیح |
|---|---|---|
| `name` | ✅ بله | عنوان مقاله (فارسی، همونی که همه‌جا نمایش داده می‌شه) |
| `label` | ✅ بله | **فقط حروف/عدد انگلیسی، فاصله، `-` و `_`.** منبع ساخت اسلاگ مقاله‌ست — سرور خودش از روی این فیلد، مقدار `slug` رو می‌سازه (کوچک، با خط‌تیره جدا). خودت نیازی نداری `slug` رو مستقیم بفرستی؛ هرچی هم بفرستی سرور موقع ذخیره بازنویسیش می‌کنه. مثال: `label: "10 Tips For Dog Apartment"` → `slug: "10-tips-for-dog-apartment"` |
| `description` | خیر (ولی عملاً همیشه لازمه) | **متن کامل مقاله، به‌صورت HTML** (نه Markdown، نه متن ساده) |
| `summary` | خیر | خلاصه‌ی مقاله |
| `subNews` | خیر | زیرعنوان کوتاه، برای کارت‌های لیست بلاگ |
| `pictureId` | خیر | شناسه‌ی عکس کاور (از قدم سوم) |
| `postPicturesList` | خیر | آرایه‌ای از `{ "pictureId": <شناسه> }` برای عکس/ویدیوهای اضافه (غیر از کاور) |
| `active` | ✅ بله | اگه `true` باشه مقاله منتشر/قابل‌نمایش می‌شه، اگه `false` باشه پیش‌نویس می‌مونه |
| `publishDate` | ✅ بله | تاریخ انتشار. اگه تاریخ گذشته بفرستی، سرور خودش با زمان همین لحظه جایگزینش می‌کنه — یعنی نمی‌شه مقاله رو با تاریخ گذشته «قدیمی» جا زد |
| `categoryId` | خیر | شناسه‌ی دسته‌بندی اصلی مقاله |
| `categoryIds` | خیر | لیست همه‌ی دسته‌بندی‌هایی که مقاله بهشون تعلق داره (می‌تونه چند دسته باشه) |
| `hashTagList` | خیر | لیست هشتگ‌ها (فقط اسمشون، رشته‌ی متنی) |

چیزهایی که **نباید** نگرانشون باشی:
- `id` رو نفرست یا هرچی فرستادی مهم نیست — برای مقاله‌ی جدید سرور خودش شناسه می‌سازه.
- نویسنده‌ی مقاله خودکار همون اکانت ربات ثبت می‌شه (چیزی برای `userId` نفرست، مهم نیست).
- خودِ `slug` رو نساز و نفرست — همیشه از روی `label` خودکار ساخته می‌شه.

### فیلدهای سئو (همه اختیاری، ولی پیشنهاد می‌شه پر بشن)

| فیلد | محدودیت | توضیح |
|---|---|---|
| `seoH1` | — | تگ H1 صفحه‌ی مقاله (می‌تونه با `name` فرق داشته باشه) |
| `seoTitle` | حداکثر ۶۰ کاراکتر (توصیه‌شده) | عنوانی که توی نتیجه‌ی گوگل نمایش داده می‌شه |
| `seoMinDescription` | حداکثر ۱۶۰ کاراکتر (توصیه‌شده) | خلاصه‌ی کوتاهی که زیر عنوان توی نتیجه‌ی گوگل میاد |
| `seoDescription` | — | توضیحات کامل‌تر سئو (متا توضیحات)، محدودیت طول نداره |
| `seoPictureAlt` | — | متن جایگزین (`alt`) عکس کاور، برای دسترس‌پذیری و سئوی تصویر |
| `seoUrlText` | — | متن کمکی برای URL — معمولاً همون مقدار `label`/`slug` رو بفرست |
| `seoCanonical` | — | آدرس Canonical کامل، فقط وقتی لازمه که همین محتوا جای دیگه‌ای هم منتشر شده و می‌خوای گوگل نسخه‌ی اصلی رو این صفحه بدونه — معمولاً خالی بذار |
| `seoNoIndex` | `true`/`false` | اگه `true` باشه، به گوگل می‌گه این صفحه رو ایندکس نکنه |
| `seoNoFollow` | `true`/`false` | اگه `true` باشه، به گوگل می‌گه لینک‌های داخل این صفحه رو دنبال نکنه |

> ⚠️ محدودیت‌های طول (۶۰ و ۱۶۰ کاراکتر) توی خودِ API اجباری نیستن (رد نمی‌کنه)، ولی توصیه‌ی استاندارد سئو گوگل هستن و توی پنل مدیریت هم همین‌ها رو نشون می‌ده.
- اسلاگ (slug) برای مقاله وجود نداره — نمایش در سایت فقط بر اساس شناسه‌ی عددیه؛ اگه فرانت سایت می‌خواد URL خوانا بسازه، خودش از روی `name` می‌سازتش (مثل مقاله‌های قبلی).

پاسخ موفق:

```json
{
  "isSuccess": true,
  "code": 0,
  "messages": [],
  "data": {
    "id": 1032,
    "name": "۱۰ نکته برای نگهداری از سگ در آپارتمان",
    "...": "..."
  }
}
```

`data.id` شناسه‌ی مقاله‌ی تازه‌ساخته‌شده‌ست.

### ویرایش یک مقاله‌ی موجود

دقیقاً همون endpoint، فقط با متد `PUT` به‌جای `POST`، و این‌بار باید `id` مقاله‌ی موجود رو هم توی بدنه بفرستی:

```
PUT https://api.pastil.pet/api/Admin/Post
```

## خطاهای رایج

| پیام خطا | یعنی چی |
|---|---|
| `AccessDenied` هنگام لاگین | اکانت ربات دسترسی پنل نداره — باید نقش/دسترسیش چک بشه (قدم اول) |
| `YouHaveNotPermission` هنگام ثبت مقاله | اکانت لاگین کرده ولی دسترسی «ثبت مقاله» بهش داده نشده |
| `PostMainPictureInvalidOrDeleted` | شناسه‌ی `pictureId` که فرستادی وجود نداره — باید اول با قدم سوم عکس رو آپلود کنی و شناسه‌ی برگشتی همون آپلود رو بفرستی |
| خطای HTTP 500 با متن «Slug ساخته‌شده تکراری است...» | مقدار `label` که فرستادی، وقتی به اسلاگ تبدیل بشه، با یک مقاله‌ی دیگه یکی می‌شه — `label` رو یکتاتر کن (مثلاً یک عدد یا کلمه‌ی اضافه بهش اضافه کن). ⚠️ برخلاف بقیه‌ی خطاها، این یکی داخل envelope عادی (`isSuccess:false`) نمیاد — یک خطای خام HTTP 500 با متن ساده‌ست، پس موقع بررسی خطا باید status code رو هم چک کنی، نه فقط `isSuccess`. |

## خلاصه‌ی کل مسیر

1. `POST /api/Account/signin` با موبایل+رمز → گرفتن `token`
2. (اختیاری) `POST /api/PictureUpload` روی `file.pastil.pet` (عکس یا ویدیو) → گرفتن `pictureId`
3. (اختیاری) `GET /api/Admin/Category?ParentId=31` روی `api.pastil.pet` → گرفتن `categoryId`
4. `POST /api/Admin/Post` روی `api.pastil.pet` با `token` توی هدر → ثبت مقاله
5. هر جا توکن منقضی شد → `POST /api/Account/refreshtoken`
