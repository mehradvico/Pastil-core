# پانسیون آموزشی مربی — سند اپ نماینده (مربی و پرسنل) — ۱۴۰۵/۰۸/۱۴

> مخاطب: تیم اپ نماینده (Flutter). بک‌اند و پنل ادمین ساخته شده‌اند؛ این سند همه‌ی چیزی است که سمت مربی و پرسنل باید پیاده شود.
> همه‌ی پاسخ‌ها HTTP 200 با قالب `{ isSuccess, code, messages, data }` هستند. موفقیت را فقط با `isSuccess` بسنجید و در خطا `messages[0]` را نشان دهید.
> مبلغ‌ها **تومان** هستند. تاریخ‌ها به وقت محلی سرور (ایران) و بدون timezone هستند.

## ۱. خلاصه

مربی فقط **سه** نحوه‌ی ارائه دارد:

| `mode` | عنوان در اپ |
|---|---|
| **38** | **پانسیون آموزشی (در مرکز)** |
| **39** | **در محل مشتری** |
| **37** | **آنلاین** |

«در محل مربی»، «حضوری» و «خدمات در مربی» دیگر نباید جایی دیده شوند.

برای **پانسیون آموزشی**، مربی چهار عدد وارد می‌کند:

| فیلد فرم | فیلد API | معنی |
|---|---|---|
| هزینه‌ی دوره | `price` | هزینه‌ی آموزش |
| پیش‌پرداخت | `prePaymentPrice` | تنها مبلغی که مشتری آنلاین می‌پردازد |
| **تعداد روز پانسیون** | `stayDays` | چند روز پت پیش مربی می‌ماند |
| **هزینه‌ی پانسیون روزانه** | `dailyPrice` | هزینه‌ی هر روز نگه‌داری |

مبلغ‌ها:

| | فرمول |
|---|---|
| مبلغ کل | هزینه‌ی دوره + (پانسیون روزانه × تعداد روز) |
| **پرداخت آنلاین مشتری** | **فقط پیش‌پرداخت** |
| دریافت در مرکز | مبلغ کل − پیش‌پرداخت (باقی‌مانده‌ی دوره + کل پانسیون روزانه) |

> مثال: دوره ۱۰٬۰۰۰٬۰۰۰، پیش‌پرداخت ۲٬۰۰۰٬۰۰۰، ۶۰ روز × ۵۰۰٬۰۰۰
> → کل ۱۰٬۰۰۰٬۰۰۰ + ۳۰٬۰۰۰٬۰۰۰ = ۴۰٬۰۰۰٬۰۰۰ — آنلاین ۲٬۰۰۰٬۰۰۰ — در مرکز ۳۸٬۰۰۰٬۰۰۰.

مشتری فقط دوره و **روز و ساعت تحویل پت** را انتخاب می‌کند (داخل ساعت کاری مربی). تحویل گرفتن = تحویل دادن + تعداد روز.

## ۲. تنظیمات مربی (پروفایل مرکز)
- دریافت: `GET /api/Companion/Coach/{id}`
- ذخیره: `PUT /api/Companion/Coach`، با بدنه‌ی **کامل** مثل قبل

| فیلد | عنوان در اپ | قاعده |
|---|---|---|
| `serviceInPerson` | **پانسیون آموزشی (در مرکز)** (سوییچ) | قبلاً «خدمات در مربی» بود |
| `serviceAtHome` | **در محل مشتری** (سوییچ) | بدون تغییر |
| `serviceOnline` | **آنلاین** (سوییچ) | بدون تغییر |
| `boardingCapacity` | **ظرفیت پانسیون (تعداد پت مقیم هم‌زمان)** | ۰ تا ۱۰۰۰؛ **۰ = بدون سقف**. فقط وقتی سوییچ پانسیون روشن است نشان دهید |
| `maxConcurrentPets` | ظرفیت هم‌زمان نوبت‌های ساعتی | بدون تغییر؛ ربطی به پانسیون ندارد |

**مهم:**
- `PUT` کل شیء را جایگزین می‌کند. **`boardingCapacity` را همیشه بفرستید** (مقدار `GET`)؛ اگر نفرستید ۰ (بدون سقف) ذخیره می‌شود.
- متن راهنما: «حداکثر چند پت هم‌زمان در پانسیون می‌مانند. ۰ یعنی محدودیت ندارد.»
- پت‌های مقیم جای نوبت‌های «در محل مشتری» و «آنلاین» را نمی‌گیرند.

## ۳. تعریف دوره (خدمت ← بسته‌ها)
- لیست: `GET /api/Companion/CoachService?coachId={coachId}`
- افزودن: `POST /api/Companion/CoachService/Package`
- ویرایش: `PUT /api/Companion/CoachService/Package` (با `id`)

### ۳-۱. فرم
نوع قیمت‌گذاری را «قیمت جدا برای هر نحوه‌ی ارائه» بگذارید. سه ردیف با چک‌باکس، **به همین ترتیب**:

| ردیف | فیلدها به ترتیب | بدنه |
|---|---|---|
| ☐ **پانسیون آموزشی (در مرکز)** | «هزینه‌ی دوره»، «پیش‌پرداخت»، «تعداد روز پانسیون»، «هزینه‌ی پانسیون روزانه» | `mode: 38, price, prePaymentPrice, stayDays, dailyPrice` |
| ☐ **در محل مشتری** | «قیمت»، «پیش‌پرداخت»، «تعداد جلسات» (اختیاری) | `mode: 39, price, prePaymentPrice, sessionCount` |
| ☐ **آنلاین** | «قیمت»، «پیش‌پرداخت» | `mode: 37, price, prePaymentPrice` |

زیر ردیف پانسیون، یک خلاصه‌ی زنده نشان دهید:
```
مبلغ کل: ۱۰٬۰۰۰٬۰۰۰ + ۶۰ × ۵۰۰٬۰۰۰ = ۴۰٬۰۰۰٬۰۰۰ تومان
مشتری آنلاین می‌پردازد: ۲٬۰۰۰٬۰۰۰ تومان — در مرکز دریافت می‌کنید: ۳۸٬۰۰۰٬۰۰۰ تومان
```

نمونه‌ی بدنه:
```json
{
  "id": 0,
  "coachServiceId": 31,
  "name": "آموزش اطاعت پایه",
  "petSizes": ["Medium", "Large"],
  "pictureId": null,
  "discription": "دوره‌ی کامل اطاعت‌پذیری با پانسیون",
  "price": 0,
  "prePaymentPrice": 0,
  "types": [
    { "mode": 38, "price": 10000000, "prePaymentPrice": 2000000, "stayDays": 60, "dailyPrice": 500000 },
    { "mode": 39, "price": 8000000, "prePaymentPrice": 1000000, "sessionCount": 10 },
    { "mode": 37, "price": 1500000, "prePaymentPrice": 0 }
  ]
}
```
(`petSizes` چند انتخابی است؛ سند `VENUE_PACKAGE_PET_SIZES_FA.md`.)

### ۳-۲. اعتبارسنجی (سرور چک می‌کند؛ در اپ هم قبل از ارسال چک کنید)

| حالت | قاعده | پیام سرور |
|---|---|---|
| 38 | `price ≥ 0`، `dailyPrice ≥ 0`؛ **دست‌کم یکی از `price` و `dailyPrice` بیشتر از صفر** | «قیمت/پیش‌پرداخت نامعتبر» (فعلی) |
| 38 | `prePaymentPrice` بین ۰ و مبلغ کل (`price + dailyPrice × stayDays`) | «قیمت/پیش‌پرداخت نامعتبر» |
| 38 | اگر `dailyPrice > 0` باشد، `stayDays` **الزامی** است | «برای پانسیون آموزشی با پانسیون روزانه، تعداد روز پانسیون را وارد کنید.» |
| 38 | `stayDays` بین ۱ و ۳۶۵ | «مقدار خارج از محدوده» (فعلی) |
| 39 و 37 | `price > 0`، `prePaymentPrice` بین ۰ و `price` | «قیمت/پیش‌پرداخت نامعتبر» |
| همه | هر `mode` حداکثر یک‌بار | «حالت نامعتبر» (فعلی) |

**نکته‌ها:**
- `stayDays` و `dailyPrice` فقط برای ۳۸ ذخیره می‌شوند؛ روی ۳۹ و ۳۷ نادیده گرفته می‌شوند. صفر یعنی ندارد (`null`).
- **پانسیون آموزشی واقعی = ردیف ۳۸ با `stayDays`.** ردیف ۳۸ بدون `stayDays` مثل یک نوبت ساعتی قدیمی رزرو می‌شود. توصیه: در اپ «تعداد روز پانسیون» را برای ۳۸ همیشه الزامی کنید.
- پانسیون رایگان (فقط دوره): `stayDays` را پر کنید و `dailyPrice` را ۰ بگذارید.
- «یک قیمت برای همه» (`types: []`) پانسیون (روز و روزانه) ندارد؛ برای پانسیون از حالت جدا استفاده کنید.

### ۳-۳. نمایش دوره در لیست
از پاسخ `types[]`:
- ۳۸: «پانسیون آموزشی (در مرکز) — دوره ۱۰٬۰۰۰٬۰۰۰ — پیش‌پرداخت ۲٬۰۰۰٬۰۰۰ — پانسیون ۶۰ روز × ۵۰۰٬۰۰۰»
- ۳۹: «در محل مشتری — ۸٬۰۰۰٬۰۰۰ — ۱۰ جلسه»
- ۳۷: «آنلاین — ۱٬۵۰۰٬۰۰۰»

### ۳-۴. دوره‌های قدیمی
دوره‌هایی که قبلاً با «در محل مربی» ساخته شده‌اند تعداد روز ندارند و مثل نوبت ساعتی رزرو می‌شوند. برای تبدیل به پانسیون، مربی دوره را ویرایش کند و «تعداد روز پانسیون» (و در صورت نیاز «پانسیون روزانه») را پر کند. پیشنهاد: کنار این دوره‌ها برچسب «تعداد روز ندارد» نشان دهید.

## ۴. ساعت کاری
`CoachSchedule` حالا برای پانسیون هم تعیین‌کننده است: **مشتری فقط داخل ساعت کاری می‌تواند پت را تحویل بدهد.** روزی که ساعت کاری ندارد، روز شروع پانسیون نیست (ولی پت می‌تواند آن روز در اقامت باشد). ساعت تحویل گرفتن همان ساعت تحویل دادن در روز پایان است و سرور آن را با ساعت کاری چک نمی‌کند؛ هماهنگی با مربی است. این را در صفحه‌ی ساعت کاری در یک خط به مربی بگویید.

## ۵. رزروها
- لیست: `GET /api/Companion/CoachReserve?coachId=&status=&ownerDecision=&dateFrom=&dateTo=&pageIndex=&pageSize=` (فقط رزروهای پرداخت‌شده)
- جزئیات: `GET /api/Companion/CoachReserve/{id}`

### ۵-۱. نمایش
**رزرو پانسیون = `dailyPrice != null`** (حتی ۰).

| فیلد | عنوان در اپ |
|---|---|
| `mode` | ۳۸ → «پانسیون آموزشی» |
| `doDate` | «تحویل دادن پت» (تاریخ و ساعت) |
| `endDate` | «تحویل گرفتن پت» |
| `stayDays` | «۶۰ روز» |
| `dailyPrice` | «پانسیون روزانه ۵۰۰٬۰۰۰» (اگر ۰ است نشان ندهید) |
| `price` | «مبلغ کل» |
| `paymentPrice` | «پرداخت‌شده‌ی آنلاین» (پیش‌پرداخت، منهای تخفیف) |
| `payAtVenue` | «دریافتی در مرکز» (باقی‌مانده‌ی دوره + پانسیون) |
| `bookerNote` | **«توضیحات صاحب پت»** (غذا، دارو، واکسن، رفتار)؛ برجسته نمایش دهید |
| `petName`، `bookerName`، `bookerMobile` | پت و صاحب پت |
| `durationMinutes` | **نمایش ندهید** |

نمونه‌ی ردیف لیست: «پانسیون آموزشی · رکس · ۱۰ آبان ← ۹ دی (۶۰ روز)».

**فیلتر تاریخ:** `dateFrom`/`dateTo` روی روز تحویل دادن (`doDate`) اعمال می‌شوند. برای تب «پت‌های مقیم الان»، رزروهای `status = 1` را بگیرید و آن‌هایی را نگه دارید که `dailyPrice != null` و `doDate ≤ الان < endDate` است.

### ۵-۲. تأیید / رد (بدون تغییر)
- تأیید: `PUT /api/Companion/CoachReserve/Approve?id={id}`
- رد: `PUT /api/Companion/CoachReserve/Reject` با `{ "id": 0, "reason": "…" }`. رد = لغو + برگشت کل مبلغ به کیف پول مشتری.
- مهلت پاسخ: ۱۲ ساعت از پرداخت، حداکثر تا ۳۰ دقیقه قبل از تحویل پت. بی‌پاسخی = لغو خودکار + برگشت وجه.

### ۵-۳. تغییر زمان
`PUT /api/Companion/CoachReserve/Reschedule` با `{ "id": 0, "newDoDate": "2026-11-15T10:00:00" }`
- `newDoDate` = روز و ساعت **تحویل دادن جدید** (داخل ساعت کاری).
- **کل اقامت با همان تعداد روز** جابه‌جا می‌شود و مبلغ تغییر نمی‌کند.
- سرور ظرفیت پانسیون را در بازه‌ی جدید و آزاد بودن پت را دوباره چک می‌کند.
- تغییر تعداد روز یک رزرو endpoint ندارد. برای تحویل زودتر از ۵-۵ استفاده کنید.

### ۵-۴. تعیین مسئول
`PUT /api/Companion/CoachReserve/Assign` با `{ "id": 0, "assigneeUserId": 123 }` (`null` = برداشتن). مسئولِ پانسیون در روزهای اقامت «مشغول» حساب نمی‌شود.

### ۵-۵. تکمیل (و تحویل زودتر)
`PUT /api/Companion/CoachReserve/Complete?id={id}`، بدنه‌ی اختیاری:
```json
{ "finalAmount": 30000000, "receivedAtVenue": 28000000, "notReceived": false, "detail": "تحویل زودتر، بعد از ۴۰ روز" }
```
- از لحظه‌ی تحویل دادن پت (`doDate`) مجاز است؛ لازم نیست تا `endDate` صبر کنید. رزرو باید تأییدشده باشد.
- **بدون بدنه:** مبلغ نهایی = `price` و باقی‌مانده (`payAtVenue`) دریافت‌شده حساب می‌شود.
- **تحویل زودتر از موعد:** پانسیون در مرکز پرداخت می‌شود، پس مبلغ واقعی را در `finalAmount` بنویسید. مثال بالا: تحویل بعد از ۴۰ روز → `10,000,000 + 500,000 × 40 = 30,000,000`؛ با ۲ میلیون پیش‌پرداخت، `receivedAtVenue = 28,000,000`. `finalAmount` نمی‌تواند از پیش‌پرداخت پرداخت‌شده کمتر باشد.
- پیشنهاد UI: در فرم تکمیل رزرو پانسیون، فیلد «تعداد روز واقعی» بگذارید و `finalAmount = (price − dailyPrice × stayDays) + dailyPrice × روز واقعی` را خودکار پر کنید؛ مربی می‌تواند دستی اصلاحش کند.
- اگر مشتری باقی‌مانده را کامل نداد: `receivedAtVenue` = مبلغ دریافتی و `notReceived: true`؛ کسری بدهی مشتری می‌شود.

| فیلد | قاعده |
|---|---|
| `finalAmount` | ≥ پرداخت آنلاین؛ خالی = `price` |
| `receivedAtVenue` | ۰ تا (`finalAmount` − آنلاین)؛ خالی = کل باقی‌مانده (یا ۰ اگر `notReceived`) |
| `notReceived` | `true` = باقی‌مانده‌ی دریافت‌نشده بدهی مشتری می‌شود |
| `detail` | حداکثر ۵۰۰ کاراکتر |

### ۵-۶. لغو توسط مشتری (برای اطلاع)
- لغو رایگان و برگشت کامل: تا **۴۸ ساعت قبل از تحویل پت**، یا هر زمانی که هنوز تأیید نکرده‌اید.
- کمتر از ۴۸ ساعت و بعد از تأیید: بدون برگشت وجه، مگر اینکه شما یا ادمین تاریخ را عوض کرده باشید؛ در این حالت کاربر تا قبل از تحویل با برگشت کامل لغو می‌کند.
- در محل مشتری و آنلاین همان ۱۲ ساعت قبلی را دارند.
