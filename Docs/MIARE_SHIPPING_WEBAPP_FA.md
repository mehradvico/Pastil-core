# مستند وب‌اپ: مرحله‌ی «اطلاعات ارسال» (ارسال با میاره + روز و بازه)

مرجع بک‌اند: `MIARE_SHIPPING_SLOTS_FA.md`. همه‌ی پاسخ‌ها `{IsSuccess, Code, Messages, Data}` هستند (HTTP معمولاً ۲۰۰؛ `IsSuccess` را چک کنید).

## ظاهر صفحه (طبق طراحی)

۱. بخش **آدرس ارسال** (انتخاب/ویرایش آدرس؛ مثل الان).
۲. برای **هر فروشگاه سبد** یک کارت:
   - عنوان: نام فروشگاه + عکس کالاها.
   - اگر `requiresSlot = true`: فقط یک روش «ارسال با میاره» (بدون برچسب «اکسپرس/ارزان‌تر»)، انتخاب **روز** (چیپ‌های افقی) و زیرش **بازه‌ی ساعتی** (۹–۱۳ و ...)، هزینه‌ی پیک همین فروشگاه. **قیمت همان برآورد میاره است و برای همه‌ی روزها/بازه‌ها یکی است** (روی چیپ هر روز قیمت جدا نمایش ندهید).
   - اگر `requiresSlot = false` (مثلاً **پست**): فقط نام روش و هزینه؛ **انتخاب روز/بازه نمایش داده نشود.**
۳. **جزئیات هزینه‌ها:** جمع کالاها، تخفیف، **جمع هزینه‌ی ارسال = مجموع هزینه‌ی پیک همه‌ی فروشگاه‌ها** (هر فروشگاه جدا پرداخت می‌شود).
۴. دکمه‌ی «ادامه» تا وقتی همه‌ی فروشگاه‌ها روش (و برای میاره: روز و بازه) را انتخاب نکرده‌اند غیرفعال.

روش‌های «سریع‌ترین / به‌صرفه‌ترین» از این صفحه برداشته می‌شوند؛ بک‌اند خودش برای هر فروشگاه فقط گزینه‌ی مجاز را برمی‌گرداند.

## ترتیب فراخوانی

### ۱) قیمت‌ها: `POST /api/EndUser/ShippingQuote`
بدنه: `{ "storeId": 12 }` (برای هر فروشگاه سبد، با آدرس انتخاب‌شده‌ی سبد).
پاسخ `Data`: لیست

```json
{ "quoteToken": "guid", "deliveryId": 5, "deliveryName": "ارسال با میاره", "provider": 4,
  "paymentMode": 1, "quotedPrice": 650000, "payableDeliveryPrice": 650000,
  "payAtDestination": false, "currency": "IRR", "expiresAtUtc": "...", "requiresSlot": true }
```

- `provider = 4` میاره. اگر آدرس بیرون از محدوده‌ی میاره باشد، فقط روش‌های غیرمیاره (پست) با `requiresSlot=false` می‌آید.
- قیمت‌ها **۵ دقیقه** اعتبار دارند (`expiresAtUtc`)؛ بعد از آن دوباره بگیرید.
- اگر لیست خالی/خطا: پیام `Messages` را نشان بدهید (فروشگاه روش ارسال ندارد یا استعلام ممکن نیست).

### ۲) روزها و بازه‌ها: `GET /api/EndUser/ShippingSlot?storeId=12`
برای **هر فروشگاهِ** `requiresSlot=true` جدا صدا بزنید (`storeId` الزامی است): بازه‌ها بر اساس «حداکثر زمان آماده‌سازی» همان فروشگاه فیلتر می‌شوند (مثلاً فروشگاهی که ۱ روز آماده‌سازی دارد برای صبح فردا بازه ندارد). ممکن است روزهای اول لیست خالی باشد و اولین روز با بازه بعدتر بیاید؛ لیست خالی یعنی «فعلاً بازه‌ای برای این فروشگاه نیست».

```json
[ { "date": "2026-10-05T00:00:00", "dayOfWeek": 0,
    "slots": [ { "slotId": 3, "startTime": "13:00", "endTime": "17:00", "remaining": 4, "available": true } ] } ]
```

- فقط روزهای دارای بازه‌ی ممکن می‌آیند (افق = ۳ روز + روزهای آماده‌سازی). `available=false` یعنی ظرفیت پر است ← غیرفعال/خاکستری نشان دهید.
- `dayOfWeek` = `System.DayOfWeek` (یکشنبه ۰ … شنبه ۶). نام روز را در کلاینت بسازید؛ پیشنهاد: «امروز / فردا / پس‌فردا» و بعد تاریخ شمسی.
- ساعت‌ها به وقت تهران و رشته‌ی `HH:mm` است؛ نمایش «۱۳ تا ۱۷».

### ۳) انتخاب: `POST /api/EndUser/ShippingSelection`
```json
{ "quoteToken": "guid", "slotId": 3, "slotDate": "2026-10-05" }
```
- برای میاره `slotId` و `slotDate` (فقط روز، همان `date` پاسخ بالا) **الزامی** است؛ برای پست لازم نیست.
- خطاهای مهم: «این روز و بازه دیگر قابل انتخاب نیست» (دوباره `ShippingSlot` را بگیرید)، «ظرفیت پر شده»، «روز و بازه را انتخاب کنید».
- بعد از هر تغییر آدرس یا سبد، انتخاب‌ها از سبد پاک می‌شوند (روش، قیمت و بازه) ← دوباره قیمت و بازه بگیرید.

### ۴) سبد و پرداخت
`CartStore` در پاسخ سبد حالا `shippingSlotId` و `shippingSlotDate` دارد. قبل از پرداخت بک‌اند دوباره اعتبار و ظرفیت را چک می‌کند؛ اگر بازه پر شده باشد پرداخت رد و پیام می‌دهد ← برگردید به این صفحه.

## بعد از پرداخت (جزئیات سفارش)

`GET /api/EndUser/ProductOrder/{id}` → هر `productOrderStores[]`:

| فیلد | معنی |
|---|---|
| `shippingSlotDate` | روز تحویل انتخابی |
| `shipmentSlotStartUtc` / `shipmentSlotEndUtc` | بازه‌ی تحویل (UTC؛ به وقت تهران نمایش دهید) |
| `shipmentStatus` | **۸، ۹، ۲، ۳ (قبل از گرفتن کالا) همه را «در حال آماده‌سازی» نشان بدهید** (جزئیات تأیید فروشنده/آماده‌سازی/پیک داخلی است و نباید دیده شود)؛ ۴ تحویل پیک شد (در راه)، ۵ تحویل شد، ۶ لغو، ۷ ناموفق |
| `shipmentDeliveryCode` | **کد ۵ رقمی تحویل** — پررنگ و بزرگ نشان بدهید و بنویسید: «این کد را فقط هنگام تحویل کالا به پیک بگویید.» |
| `shipmentTrackingCode` | لینک ردیابی میاره |

متن پیشنهادی برای ۸/۹/۲/۳: «در حال آماده‌سازی — تحویل در بازه‌ی انتخابی شما». اگر فروشنده تأیید نکند به مشتری پوش «سفارش شما در انتظار پیگیری است» می‌رسد و پشتیبانی استرداد را انجام می‌دهد.

## مسیرها
مسیرهای فروشگاه زیر `/store` هستند (`/store/basket`، `/store/products`، ...). صفحه‌ی اطلاعات ارسال را هم در همین بخش بگذارید (مثلاً `/store/basket/shipping`) تا نوار پایینِ بخش فروشگاه نمایش داده شود.

## اضافه‌ها بعد از ارسال (چرخه‌ی ارسال)
مرجع: `MIARE_SHIPPING_LIFECYCLE_FA.md`.

- **کد تحویل فقط بعد از تحویل پیک** (`shipmentStatus` ۴ یا ۵) در `shipmentDeliveryCode` می‌آید؛ قبلش `null` است. تا آن موقع به‌جای کد بنویسید «کد تحویل بعد از تحویل کالا به پیک نمایش داده می‌شود».
- **لینک پیامک** `https://app.pastil.pet/orders/<شماره سفارش>` است؛ مسیر `GET /api/EndUser/ProductOrder/{id}` هم شناسه و هم **شماره‌ی سفارش** را می‌پذیرد. بعد از لود، برای تماس‌های بعدی (تأیید تحویل و ...) از `data.id` پاسخ استفاده کنید، نه از پارامتر مسیر.
- **تحویل خودکار:** برای میاره، با اعلام کد به پیک، سفارش خودش «تحویل شد» و «تحویل گرفتم» می‌شود؛ دکمه‌ی «تحویل گرفتم/نگرفتم» برای سفارش میاره لازم نیست. یک متن بگذارید: «اعلام کد به پیک = تأیید دریافت».
- **«تحویل نگرفتم» تا ۳ ساعت بعد از تحویل میاره** هنوز فعال است (`PUT /api/EndUser/ProductOrderDelivery` با `received=false`)؛ برای سفارش تحویل‌شده‌ی میاره، تا ۳ ساعت دکمه‌ی «کالا را دریافت نکردم» را نگه دارید. بعدش بک‌اند رد می‌کند.
- پوش «تحویل پیک شد» (`فروشگاه پاستیل — کد تحویل شما: ... ، برای سفارش ...`) را با `/orders/<شماره سفارش>` باز کنید.
- سفارش پستی: کد رهگیری و پیامک دارد؛ پوش ندارد.

## پرسش راس پایان بازه (جایگزین «تحویل خودکار با کد»)
مرجع: بخش «پرسش راس پایان بازه» در `MIARE_SHIPPING_LIFECYCLE_FA.md`.

- دیگر با اعلام کد به پیک سفارش خودکار «تحویل شد» نمی‌شود؛ **راس پایان بازه** پوش «آیا سفارش … را تحویل گرفتید؟» با دکمه‌های «بله، تحویل گرفتم» و «خیر، تحویل نگرفتم» می‌رود و فقط پاسخ مشتری سفارش را تکمیل می‌کند (یا ۷ روز بعد خودکار).
- دکمه‌های پوش صفحه‌ی `/orders/<شماره سفارش>` را با `?delivery=received|not` باز می‌کنند؛ صفحه‌ی سفارش (`reserve/order-[orderId].vue`) خودش پاسخ را می‌فرستد و آدرس را تمیز می‌کند (پیاده شد).
- `canConfirmDelivery` بعد از ارسال پوش پرسش، حتی قبل از وضعیت «ارسال» true است؛ پس کارت «تحویل گرفتم/نگرفتم» (`OrderDeliveryConfirm`) نمایش داده می‌شود.
