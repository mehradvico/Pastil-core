# تغییر زمان رزرو توسط نماینده/ادمین (کلینیک، مربی، آرایشگاه)

نماینده (و ادمین) می‌تواند **زمان یک رزرو پرداخت‌شده** را عوض کند و دلیلش را بنویسد. زمان جدید در دیتابیس ثبت می‌شود (روی رزرو + یک ردیف تاریخچه)، به **کاربر** پیامک می‌رود و اگر رزرو **سفر پت‌رسان متصل** داشته باشد، زمان حرکت سفر هم جابه‌جا می‌شود و به **راننده‌ی پذیرنده** هم پیامک می‌رود.

این قابلیت برای هر سه نوع مرکز (کلینیک، مربی، آرایشگاه) یکی است؛ همه از یک مدل `CompanionReserve` استفاده می‌کنند.

---

## ۱) مدل زمان رزرو (مهم برای اپ)
- `doDate` فقط **روز** رزرو است (ساعت ۰۰:۰۰).
- **ساعت** از بازه‌ی انتخابی می‌آید: `companionTimeId` (ساعت کاری مرکز؛ شامل `startTime`/`endTime` به‌صورت `HH:mm`). رزروهای خیلی قدیمی به‌جایش `companionAssistanceTimeId` دارند.
- زمان شروع واقعی = `doDate` + `startTime` همان بازه.
- بازه‌ها برای هر روز هفته تعریف شده‌اند؛ روز جدید باید با روز هفته‌ی بازه بخواند (مثلاً بازه‌ی «دوشنبه ۱۰:۰۰» فقط برای یک دوشنبه).
- هر بازه ظرفیت دارد (`capacity`)؛ رزروهای غیرلغوشده‌ی همان بازه در همان روز از ظرفیت کم می‌شوند.

## ۲) چه رزروی قابل تغییر زمان است؟
فقط وقتی **همه** برقرار باشد:
- پرداخت‌شده (`isReserved = true`)
- لغو نشده (`isCancel = false`)
- انجام نشده (`doneDate == null`) و وضعیتش «تکمیل» (۳۳) نیست
- **آنلاین فوری نیست** (گزینه‌ی آنلاین با `isInstant = true` زمان ندارد)

وگرنه: «این رزرو قابل تغییر زمان نیست …».

## ۳) API نماینده (مرکز خودش)
همه با توکن نماینده (`CompanionId` در توکن). رزرو مرکز دیگر → `AccessDenied`.

### الف) بازه‌های قابل انتخاب برای یک روز
`GET api/Companion/CompanionReserveReschedule/slots?reserveId=123&date=2026-10-12`

`date` میلادی `yyyy-MM-dd`. پاسخ:
```json
{ "isSuccess": true, "data": {
  "date": "2026-10-12T00:00:00",
  "slots": [
    { "companionTimeId": 41, "startTime": "10:00", "endTime": "10:30", "capacity": 2, "remainingCapacity": 1,
      "selectable": true, "reason": null, "isCurrent": false },
    { "companionTimeId": 42, "startTime": "11:00", "endTime": "11:30", "capacity": 1, "remainingCapacity": 0,
      "selectable": false, "reason": "ظرفیت این بازه در این روز پر است.", "isCurrent": false }
  ] } }
```
- فقط بازه‌هایی می‌آیند که روز هفته‌شان با `date` می‌خواند؛ لیست خالی یعنی در آن روز بازه‌ی فعالی نیست.
- `selectable = false` را غیرفعال نشان دهید و `reason` را زیرش بنویسید. دلیل‌ها: ظرفیت پر، کمتر از ۳۰ دقیقه تا شروع، زمان فعلی همین رزرو، تداخل با رزرو دیگرِ نیروی تخصیص‌یافته.

### ب) ثبت تغییر
`PUT api/Companion/CompanionReserveReschedule`
```json
{ "id": 123, "newDoDate": "2026-10-12T00:00:00", "newCompanionTimeId": 41,
  "reason": "به‌دلیل بیماری پزشک، نوبت به این زمان منتقل شد" }
```
- `newDoDate`: فقط روز (ساعتش مهم نیست؛ بک‌اند `.Date` می‌گیرد).
- `reason`: **الزامی**، حداکثر ۲۰۰ نویسه (بیشتر بریده می‌شود)، فاصله‌های اضافی جمع می‌شود. همین متن در پیامک کاربر می‌آید.

پاسخ موفق:
```json
{ "isSuccess": true, "messages": [{"item1":"زمان رزرو تغییر کرد و به کاربر اطلاع داده شد."}],
  "data": { "reserveId": 123, "newDoDate": "2026-10-12T00:00:00", "newCompanionTimeId": 41,
            "newStartAt": "2026-10-12T10:00:00",
            "linkedTripId": 777, "linkedTripDepartureAt": "2026-10-12T09:00:00",
            "userNotified": true, "driverNotified": true } }
```
`linkedTripId`/`linkedTripDepartureAt` فقط وقتی رزرو سفر پت‌رسان متصل (قبل از «پت سوار شد») داشته باشد. `userNotified`/`driverNotified` یعنی پیامک با موفقیت به سرویس پیامک سپرده شد.

### پ) تاریخچه‌ی تغییرها
`GET api/Companion/CompanionReserveReschedule/history?reserveId=123` → آرایه‌ی ردیف‌ها (جدیدترین اول):
`id, oldDoDate, oldCompanionTimeId, oldStartAt, newDoDate, newCompanionTimeId, newStartAt, reason, actorKind (1 نماینده، 2 ادمین), actorName, linkedTripId, userNotified, driverNotified, createDate`.

## ۴) خطاهای ثبت (همه HTTP 200 با `isSuccess:false` و متن فارسی در `messages[0].item1`)
| وضعیت | پیام |
|---|---|
| رزرو پیدا نشد / مرکز دیگر | «چیزی یافت نشد» / «دسترسی ندارید» |
| قابل تغییر نیست (بند ۲) | این رزرو قابل تغییر زمان نیست… |
| دلیل خالی | دلیل تغییر زمان را وارد کنید. |
| بازه‌ی نامعتبر/غیرفعال/متعلق به مرکز دیگر | بازه‌ی زمانی متعلق به این مرکز نیست یا غیرفعال است |
| روز با روز هفته‌ی بازه نمی‌خواند | روز انتخابی با روز بازه‌ی انتخاب‌شده یکی نیست |
| همان زمان فعلی | زمان جدید با زمان فعلی یکی است. |
| کمتر از ۳۰ دقیقه تا شروع | زمان باید حداقل ۳۰ دقیقه بعد از الان باشد. |
| ظرفیت پر | ظرفیت این بازه در این روز پر است. |
| تداخل نیرو | نیروی تخصیص‌یافته در این بازه رزرو دیگری دارد |

## ۵) پیامک‌ها (ارسال بعد از ثبت موفق)
نام قالب در کاوه‌نگار = Label بدون `_` و بدون تغییر. فاصله داخل توکن‌ها خودکار به نیم‌فاصله می‌شود.

### الف) به کاربر — `CompanionReserveRescheduledUser`
| توکن | معنی |
|---|---|
| `token` | نام مرکز |
| `token2` | تاریخ قبلی (شمسی `1405/07/18`) |
| `token3` | تاریخ جدید (شمسی) |
| `token10` | ساعت جدید `HH.mm` (مثلاً `14.00`؛ بدون «:» چون کاوه‌نگار ۴۳۱ می‌داد) |
| `token20` | دلیل تغییر |

متن قالب:
```
زمان رزرو شما در %token از %token2 به %token3 ساعت %token10 تغییر کرد.
علت: %token20
پاستیل
```

### ب) به راننده — `CompanionReserveRescheduledDriver`
فقط اگر سفر متصل راننده‌ی پذیرنده داشته باشد.
| توکن | معنی |
|---|---|
| `token` | تاریخ جدید حرکت (شمسی) |
| `token2` | ساعت جدید حرکت `HH.mm` (بدون «:») |
| `token3` | نام مرکز |

متن قالب:
```
راننده‌ی گرامی، زمان سفر پت‌رسان مربوط به رزرو %token3 تغییر کرد.
زمان جدید حرکت: %token ساعت %token2
پاستیل
```
> «ساعت حرکت» برای راننده = ساعت جدید شروع رزرو منهای فاصله‌ای که کاربر هنگام ثبت سفر انتخاب کرده (۶۰ یا ۱۲۰ دقیقه)، نه خود ساعت نوبت.

راه‌اندازی: اسکریپت `backend/scripts/SeedCompanionReserveRescheduleSms.sql` دو `MessageType` و `SmsSetting` را می‌سازد؛ قالب‌ها را هم در کاوه‌نگار با نام‌های بالا ثبت کنید.

### پ) پوش (هم‌زمان با پیامک)
- به کاربر: `PushCompanionReserveRescheduledUser` (۱۱۹) — «زمان رزرو شما در {مرکز} به {تاریخ} ساعت {ساعت} تغییر کرد. علت: …» (لینک `/reserve`).
- به راننده‌ی پذیرنده: `PushCompanionReserveRescheduledDriver` (۱۲۰) — «زمان سفر پت‌رسان رزرو {مرکز} تغییر کرد. زمان جدید حرکت: …».
- `userNotified`/`driverNotified` در پاسخ و تاریخچه یعنی «حداقل یکی از دو کانال (پیامک یا پوش) موفق بود». پیامک فقط وقتی موفق حساب می‌شود که کاوه‌نگار آن را پذیرفته باشد (ردیف `Smses.Status = 1`)، نه فقط ثبت در صف.
- فعال‌سازی: اسکریپت `backend/scripts/AddCompanionReserveReschedulePush.sql`.

## ۶) سفر پت‌رسان متصل
وقتی رزرو سفر متصل (`CompanionReserveId`) دارد که هنوز لغو/تکمیل نشده و پت سوار نشده:
- `scheduledDepartureAt` و `tripStartDateTime` = زمان جدید شروع منهای `scheduledLeadMinutes`. اگر این زمان گذشته باشد روی «الان» می‌ماند.
- **قیمت سفر عوض نمی‌شود** (حتی اگر نرخ شب/روز فرق کند).
- راننده‌ی پذیرنده **حفظ می‌شود** و پیامک می‌گیرد؛ یادآوری ۳۰ دقیقه‌ای او دوباره برای زمان جدید فعال می‌شود.
- سفر بدون راننده دوباره وارد صف اعزام می‌شود (ادمین/راننده‌ها با زمان جدید می‌بینند).

## ۷) یادآورهای آنلاین
یادآورهای Push زمان‌بندی‌شده‌ی رزرو آنلاین (۱۰ دقیقه قبل و سر ساعت) که هنوز نرفته‌اند، با زمان جدید هماهنگ می‌شوند.

## ۸) چه چیزی به اپ نماینده اضافه شود (گام‌به‌گام)
1. در **جزئیات رزرو** (پرداخت‌شده و باز) دکمه‌ی «تغییر زمان» بگذارید (بند ۲ را برای نمایش/پنهان‌کردن رعایت کنید). زمان فعلی را از `doDate` + `companionTime.startTime/endTime` نمایش دهید.
2. صفحه/مودال: انتخاب‌گر **روز** (تقویم؛ روزهای گذشته غیرفعال) → با انتخاب روز، `slots` را بگیرید → لیست بازه‌ها (غیرقابل‌انتخاب‌ها غیرفعال با `reason`).
3. فیلد **دلیل** (الزامی، حداکثر ۲۰۰ نویسه) با متن راهنما: «این دلیل برای مشتری پیامک می‌شود».
4. تأیید نهایی: «زمان رزرو به <روز و ساعت جدید> تغییر کند و برای مشتری پیامک ارسال شود؟».
5. `PUT` با بدنه‌ی بند ۳‑ب. روی موفقیت: پیام را نشان دهید، جزئیات رزرو را دوباره بگیرید، و اگر `linkedTripId` بود یک خط «زمان سفر پت‌رسان هم تغییر کرد» نمایش دهید. اگر `userNotified=false` هشدار «پیامک به مشتری ارسال نشد؛ خودتان تماس بگیرید» بدهید.
6. خطاها را همان‌طور که هستند (`messages[0].item1`) نشان دهید.
7. تاریخچه را در جزئیات رزرو با `history` نمایش دهید (اختیاری ولی توصیه‌شده).

## ۹) پنل ادمین (انجام‌شده)
صفحه‌ی جزئیات رزرو (`/admin/companionreserve/detail-[id]`): کارت «زمان رزرو» با دکمه‌ی «تغییر زمان رزرو» (روز، بازه‌ها با ظرفیت، دلیل، ثبت) و فهرست تاریخچه (چه کسی، از چه زمانی به چه زمانی، دلیل، وضعیت پیامک). API ادمین همان نشانی‌ها با `api/Admin/CompanionReserveReschedule` است و بر هر مرکزی کار می‌کند.

## ۱۰) دو باگ زمانی که هم‌زمان رفع شد
`doDate` فقط روز است ولی دو جا مثل «زمان کامل» خوانده می‌شد:
- **سفر پت‌رسانِ متصل به رزرو کلینیک/مربی/آرایشگاه** زمان حرکت را از نیمه‌شب (۰۰:۰۰) منهای ۶۰/۱۲۰ دقیقه می‌ساخت، نه از ساعت واقعی نوبت. حالا از ساعت بازه حساب می‌شود. (سفرهای از قبل ساخته‌شده همان زمان قبلی را دارند؛ با «تغییر زمان» یا اصلاح دستی درست می‌شوند.)
- **یادآورهای Push رزرو آنلاین** (۱۰ دقیقه قبل / سر ساعت) هم از نیمه‌شب گرفته می‌شد؛ حالا از ساعت بازه.

## ۱۱) دیتابیس
مایگریشن `AddCompanionReserveReschedule`: جدول `CompanionReserveReschedules` (تاریخچه). اسکریپت idempotent: `backend/scripts/AddCompanionReserveReschedule.sql`. روی رزرو فقط `DoDate` و `CompanionTimeId` عوض می‌شود (و `CompanionAssistanceTimeId` برای رزروهای قدیمی خالی می‌شود).
