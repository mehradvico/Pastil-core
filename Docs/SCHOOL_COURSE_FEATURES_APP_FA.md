## ۱) تعریف روزهای دوره
جریان مورد نظر: ارائه‌دهنده در فرم دوره می‌گوید «این دوره **۴ جلسه** است» (`sessionCount`)، بعد **روزها و ساعت‌هایش** را انتخاب می‌کند.

### اپ ارائه‌دهنده
- در فرم دوره، `sessionCount` مثل قبل است.
- صفحه‌ی «روزهای دوره»: یک تقویم که کاربر **دقیقاً `sessionCount` روز** را انتخاب کند، و برای هر روز ساعت شروع و پایان (پیش‌فرض: همان ساعت قبلی، قابل تغییر برای هر روز).
- دکمه‌ی «ذخیره‌ی روزها» همه را یک‌جا می‌فرستد:

```
PUT /api/Companion/SchoolCourseSession/Schedule
{
  "schoolCourseId": 12,
  "sessions": [
    { "sessionDate": "2026-11-01", "startTime": "10:00", "endTime": "11:30" },
    { "sessionDate": "2026-11-03", "startTime": "10:00", "endTime": "11:30" },
    { "sessionDate": "2026-11-05", "startTime": "17:00", "endTime": "18:30" },
    { "sessionDate": "2026-11-08", "startTime": "10:00", "endTime": "11:30" }
  ]
}
```
پاسخ: لیست کامل جلسه‌های دوره به ترتیب زمان.

**قواعد سرور:**
- همه‌ی روزها باید **در آینده** باشند و ساعت پایان بعد از شروع باشد.
- دو جلسه نباید هم‌پوشانی زمانی داشته باشند.
- ذخیره‌ی دوباره، جلسه‌های **آینده** را با لیست جدید **جایگزین** می‌کند (اضافه نمی‌کند).
- جلسه‌هایی که گذشته‌اند، یا حضور و غیاب یا کلاس زنده دارند، دست نمی‌خورند و **جزو شمارش‌اند**. پس اگر دوره ۴ جلسه است و یک جلسه گذشته، باید **۳ روز جدید** بفرستید.
- اگر تعداد درست نباشد، پیام می‌آید: «این دوره ۴ جلسه است؛ باید دقیقاً ۳ روز جدید انتخاب کنید.» متن را همان‌طور نشان دهید.

مسیر قبلی تک‌جلسه‌ای (`POST/PUT /api/Companion/SchoolCourseSession`) هم مثل قبل کار می‌کند، برای ویرایش یک جلسه (مثلاً جابه‌جا کردنش).

## ۲) تنظیمات جدید دوره
در `POST/PUT /api/Companion/SchoolCourse` (و پاسخ GET دوره) این فیلدها اضافه شده‌اند:

| فیلد | نوع | مقدار پیش‌فرض | معنی |
|---|---|---|---|
| `level` | int | ۰ | سطح: ۰ نامشخص، ۱ مقدماتی، ۲ متوسط، ۳ پیشرفته |
| `prerequisiteCourseId` | long? | null | دوره‌ی پیش‌نیاز از **همین مدرسه**: همان پت باید آن دوره را «کامل‌شده» داشته باشد |
| `lateEnrollmentMode` | int | ۰ | ثبت‌نام بعد از شروع جلسه‌ی اول: ۰ بسته، ۱ باز با قیمت کامل، ۲ باز با قیمت جلسه‌های باقی‌مانده (هر دو تا شروع جلسه‌ی آخر) |
| `fullRefundHoursBeforeStart` | int? | ۲۴ | اگر کاربر تا این چند ساعت قبل از جلسه‌ی اول لغو کند، **کل** مبلغ برمی‌گردد (۰ تا ۷۲۰) |
| `lateCancelRefundPercent` | int? | ۵۰ | لغو دیرتر از آن (ولی قبل از شروع): این درصد برمی‌گردد (۰ تا ۱۰۰) |
| `certificateEnabled` | bool | false | صدور گواهی پایان دوره |

فقط در پاسخ GET دوره (فقط خواندنی):

| فیلد | معنی |
|---|---|
| `prerequisiteCourseName` | نام دوره‌ی پیش‌نیاز |
| `enrollPrice` | **قیمتی که همین الان پرداخت می‌شود.** با حالت ۲ بعد از شروع، کمتر از `price` است. در صفحه‌ی دوره و دکمه‌ی ثبت‌نام **این را نشان دهید** |
| `remainingSessions` | جلسه‌های باقی‌مانده |
| `isRegistrationOpen` | حالا حالت ثبت‌نام دیرهنگام را هم حساب می‌کند |
| `rateAvg`، `rateCount` | امتیاز خودِ دوره |

**پیشنهاد UI در اپ ارائه‌دهنده:** یک بخش «تنظیمات پیشرفته» در فرم دوره با همین ۶ فیلد. پیش‌نیاز = لیست دوره‌های همین مدرسه به‌جز خودش.

**در اپ مشتری:**
- برچسب سطح روی کارت دوره.
- «پیش‌نیاز: دوره‌ی X».
- اگر `enrollPrice < price`: «قیمت برای جلسه‌های باقی‌مانده: …» و قیمت کامل خط‌خورده.
- متن سیاست لغو، مثلاً: «تا ۲۴ ساعت قبل از شروع، بازگشت کامل؛ بعد از آن ۵۰٪؛ بعد از شروع امکان لغو ندارد».

**خطای ثبت‌نام جدید:** `SchoolCoursePrerequisiteRequired`، با متن «این دوره پیش‌نیاز دارد؛ پت شما باید ابتدا دوره‌ی پیش‌نیاز را کامل کرده باشد.»

### لغو توسط مشتری (رفتار جدید)
- لغو فقط **قبل از شروع جلسه‌ی اول** ممکن است (مثل قبل).
- مبلغ برگشتی به **کیف پول** = مبلغ پرداختی × درصد سیاست. قبلاً همیشه ۱۰۰٪ بود.
- قبل از تأیید لغو به کاربر بگویید چقدر برمی‌گردد. محاسبه سمت اپ: اگر تا شروع ≥ `fullRefundHoursBeforeStart` ساعت مانده، ۱۰۰٪؛ وگرنه `lateCancelRefundPercent`.
- لغو توسط ادمین همیشه ۱۰۰٪ است.

## ۳) لیست انتظار (اپ مشتری)
وقتی دوره پر است (`remainingCapacity == 0`)، به‌جای «ظرفیت تکمیل» دکمه‌ی **«عضویت در لیست انتظار»** بگذارید.

| متد | مسیر | توضیح |
|---|---|---|
| POST | `/api/EndUser/SchoolLearning/Waitlist` | بدنه `{ "schoolCourseId": 12, "userPetId": 55 }` |
| GET | `/api/EndUser/SchoolLearning/Waitlist` | لیست انتظارهای من، با `position` (جایگاه در صف) |
| DELETE | `/api/EndUser/SchoolLearning/Waitlist?id=` | خروج از صف |

- فقط وقتی دوره واقعاً پر است. وگرنه پیام «این دوره هنوز جای خالی دارد؛ مستقیم ثبت‌نام کنید.»
- هر پت یک بار در صف هر دوره.
- وقتی کسی لغو کند و جا باز شود، **به همه‌ی افراد صف** پوش «در دوره‌ی X جا باز شد» می‌رود (نوع ۱۶۹، باز کردن صفحه‌ی دوره). هر کس زودتر ثبت‌نام کند جا را می‌گیرد؛ جا برای نفر اول نگه داشته نمی‌شود.
- با ثبت‌نام موفق، پت خودکار از صف همان دوره خارج می‌شود.

**اپ ارائه‌دهنده:** `GET /api/Companion/SchoolTeaching/Waitlist?courseId=` صف هر دوره را نشان می‌دهد (فقط مالک).

## ۴) مدرس‌ها (اپ ارائه‌دهنده)
هر دوره می‌تواند یک **مدرس اصلی** و چند **کمک‌مدرس** داشته باشد. مدرس کاربرِ پاستیل است و با موبایل اضافه می‌شود.

| متد | مسیر | دسترسی |
|---|---|---|
| GET | `/api/Companion/SchoolTeaching/Instructors?courseId=` | مالک یا مدرس |
| POST | `/api/Companion/SchoolTeaching/Instructors` با `{ "schoolCourseId": 12, "mobile": "0912...", "isLead": true }` | فقط مالک |
| DELETE | `/api/Companion/SchoolTeaching/Instructors?courseId=&id=` | فقط مالک |
| GET | `/api/Companion/SchoolTeaching/MyCourses` | هر کاربر: شناسه‌ی دوره‌هایی که مدرسشان است |

- مدرس اصلی فقط یکی است؛ افزودن مدرس اصلی جدید، قبلی را کمک‌مدرس می‌کند.
- **مدرس** می‌تواند حضور و غیاب، مهارت‌ها، نمره و گواهی همان دوره را مدیریت کند.
- مدیریت مدرس‌ها، لیست انتظار و داشبورد فقط برای **مالک** است.
- خطاها: «کاربری با این شماره موبایل در پاستیل پیدا نشد.» و «این کاربر قبلاً مدرس همین دوره است.»
- مدرسی که مالک مدرسه نیست، دوره‌هایش را از `MyCourses` پیدا می‌کند. اپ برای او یک بخش «کلاس‌های من» نشان دهد.
- کلاس زنده (LiveKit) در این نسخه هنوز فقط برای مالک است.

## ۵) حضور و غیاب (اپ ارائه‌دهنده / مدرس)
روی هر جلسه، دکمه‌ی «حضور و غیاب».

```
GET /api/Companion/SchoolTeaching/Roster?sessionId=88
→ [{ "schoolReserveId": 301, "reserveCode": "...", "userPetId": 55, "petName": "رکس", "ownerFullName": "...", "present": null, "note": null }, ...]

PUT /api/Companion/SchoolTeaching/Attendance
{ "schoolCourseSessionId": 88, "items": [ { "schoolReserveId": 301, "present": true }, { "schoolReserveId": 302, "present": false, "note": "اطلاع داد" } ] }
```
- `present: null` یعنی هنوز ثبت نشده.
- ذخیره‌ی دوباره، همان را ویرایش می‌کند.
- یادداشت حداکثر ۵۰۰ نویسه.
- به **غایب‌ها** یک بار برای هر جلسه پوش «جلسه را از دست دادید» می‌رود (نوع ۱۷۱، بند ۸).

## ۶) کارنامه‌ی پیشرفت پت
### اپ ارائه‌دهنده / مدرس
۱. **مهارت‌های دوره** را تعریف کنید، مثلاً «نشستن با فرمان»، «ماندن»، «آمدن با صدا زدن»:
```
GET    /api/Companion/SchoolTeaching/Skills?courseId=12
POST   /api/Companion/SchoolTeaching/Skills     { "id": 0, "schoolCourseId": 12, "name": "نشستن", "sortOrder": 1 }   (id>0 = ویرایش)
DELETE /api/Companion/SchoolTeaching/Skills?courseId=12&id=7
```
۲. بعد از هر جلسه برای هر پت **نمره‌ی ۱ تا ۵** ثبت کنید (اختیاری برای همان جلسه):
```
POST /api/Companion/SchoolTeaching/Progress
{ "schoolReserveId": 301, "schoolCourseSessionId": 88, "items": [ { "schoolCourseSkillId": 7, "score": 4, "note": "خیلی بهتر شد" } ] }
```
هر ثبت، یک ردیف تاریخچه می‌سازد؛ «آخرین نمره» همان آخرین ثبت است. نمره‌ی خارج از ۱ تا ۵ این پیام را می‌دهد: «نمره باید بین ۱ تا ۵ باشد.»

۳. کارنامه‌ی یک پت: `GET /api/Companion/SchoolTeaching/Report?reserveId=301`

### اپ مشتری
`GET /api/EndUser/SchoolLearning/Report?reserveId=301`، فقط برای ثبت‌نام خود کاربر:
```json
{
  "schoolReserveId": 301, "courseName": "تربیت پایه", "petName": "رکس", "statusId": 2,
  "sessionCount": 4, "attendedCount": 3, "absentCount": 1, "attendancePercent": 75,
  "attendance": [ { "schoolCourseSessionId": 88, "sessionDate": "...", "startTime": "10:00", "present": true, "note": null } ],
  "skills": [ { "skillId": 7, "skillName": "نشستن", "latestScore": 4,
               "history": [ { "score": 2, "sessionDate": "...", "note": null }, { "score": 4, "sessionDate": "...", "note": "خیلی بهتر شد" } ] } ],
  "certificate": null
}
```
**پیشنهاد UI:** صفحه‌ی «کارنامه‌ی {نام پت}» در جزئیات ثبت‌نام. شامل درصد حضور به‌شکل دایره‌ای، لیست جلسه‌ها با تیک یا ضربدر، هر مهارت با ستاره‌ی ۱ تا ۵ و نمودار کوچک تاریخچه، و کارت گواهی (بند ۷).

## ۷) گواهی پایان دوره
- فقط برای دوره‌ای که `certificateEnabled = true` است، و فقط وقتی ثبت‌نام **«کامل‌شده»** باشد.
- وقتی ارائه‌دهنده ثبت‌نام را «کامل‌شده» می‌کند (`PUT /api/Companion/SchoolReserve/{id}/Complete`، مثل قبل)، **گواهی خودکار صادر** می‌شود و به مالک پت پوش می‌رود (نوع ۱۷۲).
- صدور دستی یا دوباره: `POST /api/Companion/SchoolTeaching/Certificate?reserveId=` (تکرار، همان گواهی را برمی‌گرداند).
- کد گواهی مثل `PSC-7KQ2MX9A` است.
- **استعلام عمومی بدون ورود:** `GET /api/School/Certificate/{code}`. حروف بزرگ و کوچک فرقی ندارد.
```json
{ "code": "PSC-7KQ2MX9A", "issueDate": "...", "courseName": "تربیت پایه", "courseLevel": 1, "schoolName": "...",
  "petName": "رکس", "ownerFullName": "...", "sessionCount": 4, "attendedCount": 4 }
```
**اپ مشتری:** کارت گواهی در کارنامه، و دکمه‌ی «اشتراک‌گذاری» با متن و لینک استعلام. **ساخت PDF یا تصویر گواهی سمت اپ است:** طرح گواهی را با همین فیلدها بسازید و برای اعتبار، QR لینک استعلام را بگذارید. سرور در این نسخه PDF نمی‌سازد.

## ۸) یادآوری‌ها و جلسه‌ی از دست رفته
بدون نیاز به کار در اپ؛ فقط مسیر باز کردن پوش‌ها را پیاده کنید (بند ۱۱).
- **یک روز قبل:** حدود ۲۴ ساعت مانده به هر جلسه (حضوری و زنده)، به ثبت‌نام‌های پرداخت‌شده: «فردا کلاس دارید» (نوع ۱۷۰).
- **۵ دقیقه قبل و لحظه‌ی شروع:** مثل قبل، برای کلاس زنده.
- **غیبت:** وقتی مدرس «غایب» ثبت کند، یک بار (نوع ۱۷۱). اگر ضبط کلاس زنده موجود باشد، کاربر از صفحه‌ی دوره می‌بیند.

## ۹) امتیاز و نظر برای هر دوره
### اپ مشتری
- بعد از «کامل‌شده» شدن ثبت‌نام، دکمه‌ی «امتیاز به دوره»:
```
POST /api/EndUser/SchoolLearning/Rate
{ "schoolReserveId": 301, "rate": 5, "text": "عالی بود" }
```
- یک نظر برای هر ثبت‌نام؛ ارسال دوباره = ویرایش. امتیاز ۱ تا ۵، متن حداکثر ۱۰۰۰ نویسه.
- امتیاز همان لحظه در `rateAvg`/`rateCount` دوره و مدرسه حساب می‌شود.
- **نمایش نظرهای دوره (عمومی، بدون ورود):** `GET /api/School/Course/{courseId}/Rates?take=50`. فقط نظرهای ردنشده می‌آیند.

### اپ ارائه‌دهنده
`GET /api/Companion/SchoolTeaching/Rates?courseId=` (همان لیست).

ادمین می‌تواند نظر نامناسب را رد کند؛ نظر ردشده پنهان می‌شود و از میانگین خارج می‌شود.

## ۱۰) داشبورد مدرسه (اپ ارائه‌دهنده)
`GET /api/Companion/SchoolTeaching/Dashboard?schoolId=` (فقط مالک)
```json
{
  "schoolId": 3, "schoolName": "...", "courseCount": 4, "activeEnrollments": 18, "waitingCount": 5,
  "revenue": 12400000, "providerShare": 11160000, "attendancePercent": 87, "rateAvg": 4.6, "rateCount": 21,
  "courses": [ { "courseId": 12, "courseName": "تربیت پایه", "courseTypeId": 3, "level": 1, "active": true,
                 "capacity": 10, "enrolled": 9, "fillPercent": 90, "waiting": 3, "completed": 2, "cancelled": 1,
                 "revenue": 3600000, "providerShare": 3240000, "attendancePercent": 92, "rateAvg": 4.8, "rateCount": 6,
                 "firstSessionDate": "...", "lastSessionDate": "..." } ]

```
- `fillPercent` برای دوره‌ی بدون سقف ظرفیت `null` است.
- `attendancePercent` وقتی هنوز حضور و غیابی ثبت نشده `null` است.
- `providerShare` شامل بخشِ نگه‌داشته‌شده از لغوهای دیرهنگام هم هست.

**پیشنهاد UI:** کارت‌های خلاصه در بالا (ثبت‌نام فعال، لیست انتظار، درآمد، درصد حضور، امتیاز)، و زیرشان یک کارت برای هر دوره با نوار پر شدن ظرفیت.

## ۱۲) چک‌لیست تست (بعد از اعلام دیپلوی)
1. دوره‌ی ۴ جلسه‌ای ← انتخاب ۳ روز ← پیام «باید دقیقاً ۴ روز…» ← انتخاب ۴ روز ← ذخیره ← ۴ جلسه.
2. ذخیره‌ی دوباره با روزهای دیگر ← هنوز ۴ جلسه، با روزهای جدید.
3. دوره با پیش‌نیاز ← ثبت‌نام با پتی که پیش‌نیاز را ندارد ← پیام پیش‌نیاز.
4. دوره با `lateEnrollmentMode = 2` بعد از جلسه‌ی اول ← `enrollPrice` کمتر از `price` ← پرداخت با همان مبلغ.
5. لغو ۴۸ ساعت قبل ← ۱۰۰٪ به کیف پول؛ لغو ۱۰ ساعت قبل ← ۵۰٪.
6. دوره‌ی پر ← عضویت در لیست انتظار ← لغو یک ثبت‌نام دیگر ← پوش «جا باز شد».
7. افزودن کمک‌مدرس با موبایل ← مدرس وارد اپ شود ← `MyCourses` ← حضور و غیاب ثبت کند.
8. غایب ثبت کردن ← پوش «جلسه را از دست دادید» به مالک پت.
9. مهارت و نمره ← کارنامه در اپ مشتری.
10. دوره با گواهی ← «کامل‌شده» ← پوش گواهی ← استعلام با کد.
11. امتیاز به دوره ← `rateAvg` دوره به‌روز شود.
12. داشبورد مدرسه ← اعداد با واقعیت بخواند.
