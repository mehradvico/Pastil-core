# راهنمای اتصال Push برای اپ فلاتر (اندروید / iOS / ویندوز)

این سند برای تیم فلاتر است. بک‌اند الان از سه مسیر پوش پشتیبانی می‌کند که هم‌زمان و مستقل از هم کار می‌کنند:

| پلتفرم | مکانیزم | چرا |
|---|---|---|
| وب‌اپ (مرورگر/PWA) | Web Push (بدون تغییر) | همون چیزی که از قبل بود |
| اندروید / iOS (اپ فلاتر) | Firebase Cloud Messaging (FCM) | پوش واقعی سیستم‌عامل، حتی وقتی اپ کاملاً بسته است |
| ویندوز (اپ فلاتر) | اتصال زنده‌ی SignalR | FCM از ویندوز دسکتاپ پشتیبانی رسمی نمی‌کند؛ چون اپ دسکتاپ معمولاً باز می‌ماند، این عملاً معادل Push زنده است — فقط وقتی اپ واقعاً در حال اجراست پیام می‌رسد |

---

## ۱. اندروید و iOS — ثبت FCM Token

بعد از راه‌اندازی Firebase در پروژه‌ی فلاتر (پلاگین `firebase_messaging`) و گرفتن Token:

```http
POST /api/EndUser/push/subscribe-fcm
Content-Type: application/json
```

اگر کاربر لاگین کرده، هدر `Authorization: Bearer <token>` هم بفرستید (اختیاری نیست الزامی؛ بدون توکن هم قبول می‌شود ولی فقط با `DeviceKey` — بخش ۳ را ببینید).

```json
{
  "deviceKey": "11111111-1111-1111-1111-111111111111",
  "fcmToken": "توکن گرفته‌شده از Firebase",
  "platform": "android",
  "userAgent": "Pastil Flutter App 1.0.0"
}
```

- `platform`: دقیقاً `"android"` یا `"ios"`.
- `deviceKey`: یک UUID که خودتان (یک‌بار، در همان دستگاه) می‌سازید و برای همیشه ذخیره می‌کنید — نقشش دقیقاً در بخش ۳ توضیح داده شده.
- هر بار که Firebase توکن را Refresh کرد (`onTokenRefresh`)، همین Endpoint را دوباره با توکن جدید صدا بزنید.

پاسخ:
```json
{ "isSuccess": true, "code": 0, "messages": [] }
```

### دریافت پوش در اپ

چون بک‌اند فقط `data` می‌فرستد (نه `notification` payload مستقیم Firebase)، اپ فلاتر باید خودش نوتیفیکیشن را از روی `data` بسازد — هم در Foreground هم Background/Terminated (`firebase_messaging`'s `onBackgroundMessage` handler را حتماً ثبت کنید، وگرنه در iOS/Android وقتی اپ کاملاً بسته است پیام نمایش داده نمی‌شود).

شکل `data` که می‌رسد:
```json
{
  "title": "متن عنوان",
  "body": "متن بدنه",
  "url": "/reserve/123",
  "icon": "/icon-192x192.png",
  "tag": "notice-123"
}
```

- `url`: مسیر داخلی اپ که با زدن روی نوتیفیکیشن باید به آن Navigate شود.
- `icon`: یک مسیر نسبی به دامنه‌ی `app.pastil.pet` — روی موبایل معمولاً آیکون خودِ اپ را نشون بدید و این فیلد را نادیده بگیرید (بیشتر برای وب‌اپ کاربرد داره).

## ۲. ویندوز — اتصال SignalR

هیچ Endpoint ثبتی لازم نیست. اپ فلاتر ویندوز (بعد از لاگین) یک اتصال SignalR باز نگه می‌دارد:

```
wss://api.pastil.pet/hubs/push
```

با هدر `Authorization: Bearer <token>` (پکیج [signalr_netcore](https://pub.dev/packages/signalr_netcore) یا مشابه، دقیقاً همون چیزی که احتمالاً برای هاب تماس (`/hubs/call`) از قبل استفاده کردید).

روی رویداد `"push"` گوش بدید:

```dart
connection.on('push', (arguments) {
  final data = arguments![0];
  // data['title'], data['body'], data['url'], data['icon'], data['tag']
  // یک نوتیفیکیشن سیستم‌عامل ویندوز بسازید (مثلاً با local_notifier یا win_toast)
});
```

⚠️ این فقط وقتی کار می‌کند که اپ باز و اتصال برقرار باشد — اگر اپ بسته باشد، پیام گم می‌شود (Retry/Queue ندارد). اگر ویندوز واقعاً به Push حین بسته‌بودن اپ نیاز پیدا کرد، آن‌موقع باید سراغ WNS برویم؛ فعلاً طبق تصمیم مشترک، از همین مسیر ساده‌تر استفاده می‌کنیم.

## ۳. منطق `DeviceKey` (قبل از لاگین → بعد از لاگین)

این دقیقاً همون الگویی‌ست که وب‌اپ هم استفاده می‌کند:

1. همون اول (حتی قبل از لاگین کاربر)، یک UUID بسازید و توی Local Storage اپ ذخیره کنید (`deviceKey`).
2. `subscribe-fcm` را همیشه با همین `deviceKey` صدا بزنید (چه لاگین باشید چه نباشید).
3. وقتی کاربر واقعاً لاگین کرد، یک‌بار این را هم صدا بزنید تا Subscription قبلی به حسابش وصل شود:

```http
POST /api/EndUser/push/attach
Authorization: Bearer <token>
Content-Type: application/json
```
```json
{ "deviceKey": "11111111-1111-1111-1111-111111111111" }
```

بدون این مرحله، پوش‌هایی که قبل از لاگین ثبت شدن هیچ‌وقت به کاربر مشخصی وصل نمی‌شن و هیچ پوش شخصی‌سازی‌شده‌ای (مثل «سفارشت تایید شد») دریافت نمی‌کنید.

---

## سمت بک‌اند (فقط جهت اطلاع — کاری از شما نمی‌خواهد)

- `PushSubscription` حالا سه‌حالته: `Provider` = WebPush(۱) یا Fcm(۲) — بقیه‌ی منطق (چه وقت، چه پیامی، چند بار Retry) دقیقاً همون Pattern فعلی پوش‌های سایت است، فقط لایه‌ی ارسال گسترش پیدا کرده.
- برای این‌که FCM واقعاً کار کند، تیم بک‌اند باید یک Service Account JSON از Firebase Console بگیرد و به‌عنوان `PASTIL_FCM_SERVICE_ACCOUNT_JSON` روی سرور تنظیم کند؛ تا قبل از آن، پوش موبایل بی‌صدا نادیده گرفته می‌شود (نه خطا، فقط ارسال نمی‌شود).
