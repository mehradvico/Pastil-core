# مستند فرم تماس با ما برای اپ EndUser

این مستند برای پیاده‌سازی فرم تماس با ما در `app.pastil.pet` تهیه شده است.

## 1. دریافت دپارتمان‌ها و فرم داینامیک

```http
GET /api/ContactUsGroup?PageIndex=1&PageSize=50&SortBy=7
```

این API عمومی است و به توکن نیاز ندارد. فقط دپارتمان‌های فعال برمی‌گردند. فرانت نباید دپارتمان‌ها یا فیلدهای اختصاصی آن‌ها را به‌صورت ثابت در کد قرار دهد.

نمونه هر دپارتمان:

```json
{
  "id": 2,
  "name": "درخواست راننده",
  "label": "driver-request",
  "active": true,
  "priority": 2,
  "formFields": [
    {
      "key": "city",
      "label": "شهر محل فعالیت",
      "inputType": "text",
      "required": true,
      "priority": 1,
      "maxLength": 100,
      "minValue": null,
      "placeholder": "مثلاً تهران",
      "options": []
    }
  ]
}
```

فرم را بر اساس `formFields` و به‌ترتیب `priority` بسازید. انواع فعلی فیلد:

- `text`: ورودی متنی
- `number`: ورودی عددی با رعایت `minValue`
- `url`: لینک کامل با `http://` یا `https://`
- `select`: انتخاب یکی از `options` و ارسال `option.value`

## 2. دپارتمان‌های پیش‌فرض

| عنوان | Label |
|---|---|
| ارتباط با پاستیل | `contact-pastil` |
| درخواست راننده | `driver-request` |
| درخواست نمایندگی | `companion-request` |
| درخواست پت‌شاپ | `pet-shop-request` |
| درخواست محصول خاص | `special-product-request` |
| درخواست تبلیغات | `advertising-request` |

در ارسال فرم از `id` دریافت‌شده از API استفاده کنید، نه یک ID ثابت داخل فرانت.

## 3. ارسال درخواست

```http
POST /api/ContactUs
Content-Type: application/json
Authorization: Bearer {token}  // اختیاری
```

کاربر مهمان و کاربر لاگین‌شده هر دو می‌توانند فرم را ارسال کنند. اگر توکن معتبر وجود داشته باشد، بک `userId` را از توکن استخراج می‌کند. فرانت نباید `userId`، `status`، `answer`، `id` یا `contactUsId` ارسال کند.

فیلدهای اصلی:

| فیلد | الزامی | محدودیت |
|---|---:|---|
| `fullName` | بله | حداکثر 120 کاراکتر |
| `mobile` | بله | موبایل ایران؛ اعداد فارسی، فاصله، `+98` و `98` در بک نرمال می‌شوند |
| `email` | خیر | ایمیل معتبر، حداکثر 200 کاراکتر |
| `title` | بله | حداکثر 150 کاراکتر |
| `body` | بله | حداکثر 4000 کاراکتر |
| `contactUsGroupId` | بله | ID دپارتمان فعال |
| `fileId` | خیر | ID فایل آپلودشده معتبر |
| `contactUsItems` | وابسته به دپارتمان | پاسخ فیلدهای داینامیک |

نمونه درخواست:

```json
{
  "fullName": "علی رضایی",
  "mobile": "09121234567",
  "email": "ali@example.com",
  "title": "درخواست همکاری به عنوان راننده",
  "body": "امکان فعالیت تمام‌وقت در تهران را دارم.",
  "contactUsGroupId": 2,
  "fileId": null,
  "contactUsItems": [
    { "title": "city", "value": "تهران" },
    { "title": "vehicleType", "value": "motorcycle" },
    { "title": "hasDriverLicense", "value": "yes" },
    { "title": "experienceYears", "value": "2" }
  ]
}
```

در `contactUsItems`:

- `title` باید دقیقاً برابر `formFields.key` باشد.
- برای `select` مقدار `options.value` ارسال شود، نه عنوان فارسی گزینه.
- فیلد خالی اختیاری را ارسال نکنید.
- حداکثر 20 آیتم مجاز است.

## 4. آپلود فایل اختیاری

ابتدا فایل را به سرویس فایل ارسال کنید:

```http
POST {FILE_BASE_URL}/api/FileUpload
Content-Type: multipart/form-data
```

نام فیلد multipart باید `file` باشد. سپس `data.id` پاسخ را به‌عنوان `fileId` در فرم تماس با ما بفرستید.

محدودیت فایل برای فرم تماس با ما:

- فرمت‌های مجاز: `jpg`، `jpeg`، `png`، `webp` و `pdf`
- حداکثر حجم: 10 مگابایت
- فایل باید حداکثر دو ساعت قبل آپلود شده باشد.
- هر فایل فقط برای یک درخواست تماس با ما قابل استفاده است.

## 5. مدیریت پاسخ

موفقیت:

```json
{
  "isSuccess": true,
  "messages": [],
  "code": 0
}
```

تنها در صورت `isSuccess === true` فرم را پاک و پیام موفقیت نمایش دهید.

خطای اعتبارسنجی یا درخواست تکراری معمولاً با HTTP 200 و `isSuccess: false` برمی‌گردد. متن قابل نمایش را از `messages[0].item1` بخوانید.

نمونه درخواست تکراری:

```json
{
  "isSuccess": false,
  "messages": [
    { "item1": "این درخواست به‌تازگی ثبت شده است و نیازی به ارسال مجدد نیست." }
  ]
}
```

محدودیت تعداد ارسال با HTTP `429 Too Many Requests` اعلام می‌شود. در این حالت پیام زیر نمایش داده شود:

> تعداد درخواست‌های شما بیش از حد مجاز است. لطفاً چند دقیقه دیگر دوباره تلاش کنید.

برای جلوگیری از دوبار ارسال در فرانت:

1. از لحظه شروع درخواست، دکمه ارسال را `disabled` کنید.
2. تا پایان درخواست اجازه کلیک مجدد ندهید.
3. در خطای شبکه فرم را حفظ کنید.
4. در `isSuccess: false` فرم پاک نشود.

## 6. کنترل‌های بک

بک موارد زیر را مستقل از فرانت کنترل می‌کند:

- نرمال‌سازی موبایل و اعداد فارسی
- پاک‌سازی HTML ورودی‌ها
- وجود و فعال‌بودن دپارتمان
- فیلدهای الزامی و طول مقادیر
- کلیدهای ناشناخته یا تکراری
- گزینه‌های معتبر `select`
- عدد و حداقل مقدار
- URL معتبر
- امنیت، نوع، حجم، تازگی و مصرف‌نشدن فایل
- جلوگیری از ثبت درخواست یکسان در بازه دو دقیقه
- حداکثر پنج ارسال در ده دقیقه برای هر IP
