# جستجوی پت با میکروچیپ در «ارتباط با ما» — مستند مو‌به‌مو برای اپ (امیرمحسن) و سایت/وب‌اپ (آرمان)

> وضعیت بک: پیاده شد، **دیپلوی نشده** (تا اجرای SQL و دیپلوی Api، endpointها 404 می‌دهند).
> قرارداد: پاسخ همیشه **HTTP 200** با `{ isSuccess, messages, data }` (به‌جز 429)؛ موفقیت را از `isSuccess` بخوانید؛ فیلدها camelCase؛ متن خطا را عیناً از `messages[0].item1` نشان دهید.
> طراحی و قواعد بک: [PET_MICROCHIP_LOOKUP_FA.md](PET_MICROCHIP_LOOKUP_FA.md)

## ۱) ایده‌ی صفحه
در «ارتباط با ما» یک کارت/تب جدید **«جستجوی پت با میکروچیپ»** اضافه کنید (کنار فرم پیام فعلی؛ فرم فعلی دست نمی‌خورد). فلو:

1. کاربر کد میکروچیپ را وارد و «جستجو» می‌زند.
2. اگر پت پیدا شد ⇒ **پروفایل پت** (بدون هیچ اطلاعات مالک) نشان بده + دکمه‌ی **«درخواست پیگیری توسط پاستیل»**.
3. زدن دکمه ⇒ فرم کوچک (نام، موبایل، ایمیل اختیاری، پیام اختیاری) ⇒ ارسال ⇒ پیام موفقیت.
4. اگر پیدا نشد ⇒ پیام «پتی با این کد در پاستیل ثبت نشده است» (بدون دکمه‌ی پیگیری).

> مهم: **هرگز** نباید در UI وعده‌ی نشان‌دادن شماره یا اطلاعات مالک داده شود. متن پیشنهادی زیر دکمه: «برای حفظ حریم خصوصی، اطلاعات مالک نمایش داده نمی‌شود. با ثبت درخواست، همکاران پاستیل با مالک هماهنگ می‌کنند و نتیجه را به شما اطلاع می‌دهند.»

## ۲) جستجو

`POST /api/PetMicrochip/Search` — بدون نیاز به لاگین (اگر توکن دارید بفرستید؛ اجباری نیست).

```json
{ "microchipCode": "981 020-000123456" }
```
- ورودی را سمت کلاینت هم تمیز کنید (حذف فاصله/خط‌تیره، ارقام فارسی مجازند؛ بک همه را نرمال می‌کند). طول ۹ تا ۱۵ رقم؛ فقط رقم. `maxLength=20` برای فیلد کافی است.
- فیلد کیبورد: `numeric`؛ دکمه‌ی اسکن بارکد/NFC لازم نیست.

پاسخ پیدا شد:
```json
{
  "isSuccess": true,
  "messages": [],
  "data": {
    "found": true,
    "microchipCode": "981020000123456",
    "token": "9f2c...32 کاراکتر",
    "tokenExpireDate": "2026-10-05T10:30:00",
    "pet": {
      "name": "لولو", "petName": "سگ", "breedName": "شیتزو", "breed2Name": null,
      "isMixBreed": false, "isMale": true, "isSterile": false,
      "ageMonths": 26, "size": "کوچک", "weight": "6",
      "picture": { "id": 1, "baseUrl": "...", "url": "https://.../x.jpg", "extension": ".jpg" },
      "pictures": [ { "id": 2, "url": "https://.../y.jpg" } ]
    }
  }
}
```
پیدا نشد: `isSuccess:true` و `data: { "found": false, "microchipCode": "...", "token": null, "pet": null }`.

خطای ورودی (کد نامعتبر): `isSuccess:false` + پیام «کد میکروچیپ معتبر نیست؛ کد باید بین ۹ تا ۱۵ رقم باشد.»

**نمایش پروفایل:** عکس اصلی (`pet.picture.url`؛ اگر null آیکن پیش‌فرض) و گالری کوچک `pictures`؛ نام، نوع و نژاد (اگر `isMixBreed` و `breed2Name` ⇒ «نژاد / نژاد دوم»)، جنسیت (`isMale`)، «عقیم‌شده» اگر `isSterile`، سن از `ageMonths` (≥۱۲ ⇒ «X سال و Y ماه»، وگرنه «Y ماه»؛ null ⇒ نمایش ندهید)، سایز/وزن اگر خالی نبود. **فیلد دیگری وجود ندارد و نباید حدس زده شود.**

`token` را فقط در حافظه‌ی همان صفحه نگه دارید (ذخیره‌ی ماندگار لازم نیست). ۲۴ ساعت اعتبار دارد؛ پس از انقضا باید دوباره جستجو کرد.

## ۳) درخواست پیگیری

`POST /api/PetMicrochip/FollowUp`
```json
{
  "token": "9f2c...",
  "fullName": "مهران رضایی",
  "mobile": "09121234567",
  "email": "a@b.com",
  "message": "این سگ را در خیابان پیدا کرده‌ام."
}
```
- `token` الزامی (از پاسخ جستجو). 
- **کاربر لاگین‌شده:** فرم را از پروفایل خودش پر کنید (قابل ویرایش)؛ بک هم اگر نام/موبایل خالی بود از حساب کاربر پر می‌کند. **مهمان:** نام و موبایل اجباری‌اند.
- موبایل: `09xxxxxxxxx`؛ `+98`/ارقام فارسی را بک نرمال می‌کند. ایمیل و پیام اختیاری (پیام تا ۱۰۰۰ کاراکتر).

موفق: `isSuccess:true`، `messages[0].item1` = «درخواست پیگیری ثبت شد؛ همکاران پاستیل در اولین فرصت با شما تماس می‌گیرند.»، `data: { requestId, followUpDate }`. بعد از موفقیت دکمه را غیرفعال و پیام تأیید نشان دهید (ارسال دوباره با همان توکن خطا می‌دهد).

خطاهای محتمل (`isSuccess:false`، متن را عیناً نشان دهید):
| حالت | پیام |
| --- | --- |
| توکن نامعتبر/منقضی | درخواست پیگیری معتبر نیست یا مهلت آن (۲۴ ساعت) تمام شده است؛ لطفاً دوباره جستجو کنید. ⇒ کاربر را به مرحله‌ی جستجو برگردانید |
| قبلاً ثبت شده | درخواست پیگیری برای این جستجو قبلاً ثبت شده است. |
| نام خالی | نام و نام‌خانوادگی را وارد کنید. |
| موبایل بد | شماره موبایل معتبر نیست. |
| سقف روزانه | تعداد درخواست‌های پیگیری شما در ۲۴ ساعت گذشته به سقف مجاز رسیده است. |

## ۴) محدودیت نرخ (HTTP 429)
هر دو endpoint: **حداکثر ۱۰ درخواست در ۱۰ دقیقه برای هر IP**. با 429 بدنه‌ی JSON ندارید؛ پیام ثابت نشان دهید: «تعداد درخواست‌ها زیاد است؛ چند دقیقه‌ی دیگر دوباره تلاش کنید.» و دکمه را موقتاً غیرفعال کنید. دسته‌ای/خودکار جستجو نکنید (فقط با زدن دکمه).

## ۵) سناریوهای تست
۱. کد معتبر یک پت ثبت‌شده ⇒ پروفایل + دکمه؛ در پاسخ شبکه هیچ‌چیز از مالک نیست.
۲. کد با ارقام فارسی و فاصله ⇒ همان نتیجه.
۳. کد ۸ رقمی یا حرف‌دار ⇒ پیام خطا.
۴. کد ناموجود ⇒ «ثبت نشده» بدون دکمه.
۵. پیگیری مهمان با موبایل غلط ⇒ خطای موبایل؛ با درست ⇒ موفق؛ بار دوم همان توکن ⇒ «قبلاً ثبت شده».
۶. لاگین‌شده با فرم خالی ⇒ از پروفایل پر می‌شود.
۷. بیش از ۱۰ جستجو در ۱۰ دقیقه ⇒ 429.
۸. ادمین در پنل (`/admin/petmicrochiprequest`) درخواست را با مشخصات مالک می‌بیند و وضعیت را تغییر می‌دهد.

## ۶) چک‌لیست
**اپ فلاتر (امیرمحسن):**
- [ ] کارت «جستجوی پت با میکروچیپ» در صفحه‌ی ارتباط با ما
- [ ] فیلد عددی + اعتبارسنجی سمت کلاینت (۹–۱۵ رقم) و فراخوانی Search
- [ ] نمایش پروفایل بدون هیچ فیلد مالک؛ مدیریت `found=false`
- [ ] دکمه‌ی «درخواست پیگیری توسط پاستیل» + فرم (پرکردن خودکار برای لاگین‌شده) + FollowUp
- [ ] نمایش خطاهای فارسی از `messages` و پیام ثابت 429
- [ ] نگه‌داشتن `token` فقط در حافظه‌ی صفحه؛ بازگشت به جستجو هنگام انقضا
- [ ] متن حریم خصوصی زیر دکمه

**سایت/وب‌اپ (آرمان):** همان فلو در `/contact-us` (یا صفحه‌ی ارتباط با ما)؛ endpointها بدون احراز هویت و CORS-ready مثل فرم تماس فعلی؛ SEO لازم نیست (`noindex` برای نتیجه).
