راهنمای ورود ربات تولید محتوا و ثبت مقاله

این مستند برای رباتی نوشته شده که قراره خودکار وارد پنل بشه، عکس کاور آپلود کنه و مقاله (Post) ثبت کنه. هر قدم با آدرس دقیق، بدنه‌ی درخواست و نمونه‌ی پاسخ واقعی نوشته شده.

سرویس اصلی API
https://api.pastil.pet
سرویس فایل (آپلود عکس)
https://file.pastil.pet

همه‌ی پاسخ‌های API با همین ساختار برمی‌گردن — همیشه HTTP 200، موفقیت واقعی رو از isSuccess بخون، نه status code:

{
  "isSuccess": true,
  "code": 0,
  "messages": [],
  "data": { ... }
}

پیش‌نیاز — ساخت اکانت ربات

قبل از هرچیز، یک نفر از تیم بک‌اند این مراحل رو یک‌بار انجام می‌ده (کار خود ربات نیست، فقط برای اطلاعت):

  1. یک نقش (Role) جدید مثلاً «تولیدکننده محتوا» ساخته می‌شه — نه نقش Admin، دسترسی محدود می‌مونه.
  2. به این نقش فقط دسترسی «ثبت مقاله» و «ویرایش مقاله» داده می‌شه.
  3. یک کاربر با موبایل و رمز عبور مشخص، با این نقش ساخته می‌شه و کد یک‌بارمصرف (OTP) روی اکانتش غیرفعال می‌مونه — یعنی ربات فقط با موبایل و رمز عبور وارد می‌شه.

بعد از این مرحله، موبایل و رمز عبور همین اکانت رو بهت می‌دن.

۱

ورود و گرفتن توکن

POST /api/Account/signin
بدنه‌ی درخواست 
{
  "mobile": "09120000000",
  "password": "رمز عبور اکانت ربات",
  "isAdmin": true,
  "rememberMe": true
}
مهم: فیلد isAdmin حتماً باید true باشه، وگرنه ورود به پنل رد می‌شه.
پاسخ موفق 
{
  "isSuccess": true,
  "code": 0,
  "messages": [],
  "data": {
    "token": "eyJhbGciOiJIUzI1NiIs...",
    "refreshToken": "b3f1b0a2-....",
    "tokenExp": "2026-08-28T10:00:00",
    "refreshTokenExp": "2026-09-04T10:00:00",
    "userId": 123
  }
}

مقدار data.token همون توکنیه که باید توی همه‌ی درخواست‌های بعدی بفرستی. اسمش دقیقاً token هست، نه accessToken.

فرستادن توکن در درخواست‌های بعدی — توی هدر هر درخواست (چه به api چه به file) این هدر رو اضافه کن:

Authorization: Bearer eyJhbGciOiJIUzI1NiIs...

وقتی توکن منقضی شد — به‌جای لاگین دوباره از این استفاده کن:

POST /api/Account/refreshtoken 
{ "refreshToken": "b3f1b0a2-...." }

پاسخش دقیقاً همون ساختار توکن جدیده.

۲

آپلود عکس و ویدیو (اختیاری)

قبل از ثبت مقاله، اگه می‌خوای عکس کاور (یا هر عکس/ویدیوی دیگه‌ای داخل متن) داشته باشه، اول باید فایل رو آپلود کنی و شناسه‌اش رو بگیری. آپلود عکس و ویدیو دقیقاً از یک endpoint یکسان انجام می‌شه.

POST https://file.pastil.pet/api/PictureUpload

بدنه از نوع multipart/form-data

PictureFile فایل عکس یا ویدیو — حداکثر ۵ مگابایت
عکسویدیو
پسوندهای مجازjpg / jpeg / png / webpmp4 / webm / ogg
تبدیل فرمتهمیشه به webp تبدیل می‌شهفرمت اصلی حفظ می‌شه
سایزهای مختلف۳ نسخه‌ی sm/md/lg خودکار ساخته می‌شهفقط یک نسخه (بدون تغییر سایز)
پاسخ موفق (برای هر دو نوع یکسانه) 
{
  "isSuccess": true,
  "data": {
    "id": 4521,
    "guidName": "a1b2c3d4e5f6...",
    "extension": ".webp"
  }
}

مقدار data.id رو نگه دار — همین رو به‌عنوان pictureId توی قدم ثبت مقاله می‌فرستی.

اگه مقاله عکس کاور نداشته باشه، فیلد pictureId رو خالی بذار یا اصلاً نفرست. برای عکس/ویدیوی اضافه (غیر از کاور) از فیلد postPicturesList استفاده کن، یا برای نمایش ویدیو داخل متن، تگ <video> رو مستقیم توی HTML فیلد description بنویس.

فرمول آدرس نهایی فایل 
{baseUrl}/{guidName}-{size}{extension}   # عکس (size ∈ sm/md/lg)
{baseUrl}/{guidName}{extension}          # ویدیو (بدون size)
۳

پیدا کردن شناسه‌ی دسته‌بندی (اختیاری)

مقاله‌ها می‌تونن به یک یا چند دسته‌بندی وصل بشن. برای پیدا کردن شناسه‌ی هر دسته‌بندی:

GET https://api.pastil.pet/api/Admin/Category?ParentId=31&PageSize=50

ParentId=31 یعنی «فقط زیردسته‌های دسته‌بندی مادرِ مقالات (شناسه‌ی ۳۱)» — همیشه این پارامتر رو بفرست، وگرنه همه‌ی دسته‌بندی‌های سایت (نه فقط مقاله) برمی‌گرده.

پاسخ موفق 
{
  "isSuccess": true,
  "data": {
    "list": [
      { "id": 45, "name": "سگ", "parentId": 31 },
      { "id": 46, "name": "گربه", "parentId": 31 }
    ],
    "totalCount": 8
  }
}

برای رفتن به عمق بعدی (مثلاً زیردسته‌های «سگ» مثل «تغذیه»، «سلامت و بیماری»)، همین درخواست رو با ParentId=45 دوباره بزن. از هر آیتم فقط id لازمه — همون رو توی categoryId/categoryIds بفرست.

توضیح فیلدها

فیلداجباری؟توضیح
nameبلهعنوان مقاله (فارسی)
labelبلهفقط حروف/عدد انگلیسی، فاصله، - و _. سرور از روی همین، slug نهایی رو خودکار می‌سازه (کوچک، خط‌تیره‌جدا) — خودت slug نفرست
descriptionعملاً همیشه لازممتن کامل مقاله، به‌صورت HTML (نه Markdown، نه متن ساده)
summaryخیرخلاصه‌ی مقاله
subNewsخیرزیرعنوان کوتاه برای کارت‌های لیست بلاگ
pictureIdخیرشناسه‌ی عکس کاور (از قدم ۲)
postPicturesListخیرآرایه‌ای از {"pictureId": شناسه} برای عکس/ویدیوی اضافه (غیر از کاور)
activeبلهاگه true باشه مقاله منتشر می‌شه، اگه false باشه پیش‌نویس می‌مونه
publishDateبلهتاریخ انتشار — اگه گذشته بفرستی، سرور با همین لحظه جایگزینش می‌کنه
categoryIdخیرشناسه‌ی دسته‌بندی اصلی (از قدم ۳)
categoryIdsخیرلیست همه‌ی دسته‌بندی‌ها (می‌تونه چند دسته باشه)
hashTagListخیرلیست هشتگ‌ها (رشته‌ی متنی)

چیزهایی که نباید نگرانشون باشی: id رو نفرست (برای مقاله‌ی جدید سرور خودش می‌سازه)، نویسنده خودکار همون اکانت ربات ثبت می‌شه.

فیلدهای سئو (همه اختیاری، ولی پیشنهاد می‌شه پر بشن)

فیلدمحدودیتتوضیح
seoH1—تگ H1 صفحه‌ی مقاله (می‌تونه با name فرق داشته باشه)
seoTitle~۶۰ کاراکترعنوانی که توی نتیجه‌ی گوگل نمایش داده می‌شه
seoMinDescription~۱۶۰ کاراکترخلاصه‌ی کوتاه زیر عنوان توی نتیجه‌ی گوگل
seoDescription—توضیحات کامل‌تر سئو (متا توضیحات)
seoPictureAlt—متن جایگزین (alt) عکس کاور
seoUrlText—معمولاً همون مقدار label/slug رو بفرست
seoCanonical—فقط وقتی لازمه که همین محتوا جای دیگه هم منتشر شده — معمولاً خالی بذار
seoNoIndextrue/falseاگه true، به گوگل می‌گه این صفحه ایندکس نشه
seoNoFollowtrue/falseاگه true، لینک‌های داخل صفحه دنبال نشن

محدودیت‌های طول (۶۰ و ۱۶۰) توی خودِ API اجباری نیستن، فقط توصیه‌ی استاندارد سئوی گوگلن — همون‌هایی که توی پنل مدیریت هم نشون داده می‌شن.

ویرایش یک مقاله‌ی موجود

PUT https://api.pastil.pet/api/Admin/Post

دقیقاً همون endpoint، فقط این‌بار باید id مقاله‌ی موجود رو هم توی بدنه بفرستی.

پاسخ موفق (هر دو حالت) 
{
  "isSuccess": true,
  "data": { "id": 1032, "name": "..." }
}

خلاصه‌ی کل مسیر

POST /api/Account/signin با موبایل و رمز → گرفتن token
(اختیاری) POST /api/PictureUpload روی file.pastil.pet (عکس یا ویدیو) → گرفتن pictureId
(اختیاری) GET /api/Admin/Category?ParentId=31 روی api.pastil.pet → گرفتن categoryId
POST /api/Admin/Post روی api.pastil.pet با توکن در هدر → ثبت مقاله
هر جا توکن منقضی شد → POST /api/Account/refreshtoken
