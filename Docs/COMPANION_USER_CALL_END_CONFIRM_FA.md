# پایان تماس/ویدیوکال در اپ نماینده (CompanionUser) — با تأیید کاربر

> مخاطب: توسعه‌دهنده‌ی اپ نماینده (Flutter) · بک‌اند/هاب سیگنالینگ از قبل پیاده و فعال است.

## ۱) خلاصه

نماینده (پزشک/تیم کلینیک) هنگام تماس صوتی یا ویدیویی درون‌برنامه‌ای با کاربر، باید بتواند تماس را پایان بدهد. **قبل از پایان دادن واقعی، اپ باید یک دیالوگ تأیید نشان بدهد** («آیا از پایان تماس مطمئن هستید؟» + دو دکمه‌ی «بله، پایان بده» / «انصراف») و فقط بعد از تأیید کاربر، درخواست پایان تماس را به سرور بفرستد.

این تماس روی یک هاب SignalR (نه REST) کار می‌کند؛ همان هابی که وب‌اپ مشتری هم از آن استفاده می‌کند (`webapp/app/components/call/CallScreen.vue`، `useCallSignaling`)، پس منطق سمت سرور از قبل تست‌شده و پایدار است.

## ۲) اتصال به هاب تماس

| مورد | مقدار |
| --- | --- |
| آدرس هاب | `wss://api.pastil.pet/hubs/call` |
| احراز هویت | JWT دسترسی به‌صورت **query string**، نه هدر: `?access_token=<accessToken>` |
| پروتکل | SignalR (روی WebSocket) |

> نکته: چون SignalR روی هندشیک اولیه‌ی WebSocket نمی‌تواند هدر دلخواه ست کند، توکن حتماً در query string فرستاده می‌شود. اگر `access_token` معتبر نباشد، اتصال با خطای ۴۰۱ رد می‌شود.

## ۳) متدهایی که کلاینت صدا می‌زند

| متد | پارامتر | کاربرد |
| --- | --- | --- |
| `JoinCall` | `reserveId` (long) | ورود به تماس مربوط به یک رزرو (خدمت آنلاین با نماینده) |
| `JoinSessionCall` | `sessionId` (long) | ورود به تماس یک «جلسه‌ی آنلاین» مستقل از رزرو |
| `SendSignal` | `reserveId/hubKey`, `type` (`offer`/`answer`/`ice`), `payload` (رشته‌ی JSON، حداکثر ۳۲ کیلوبایت) | رد و بدل کردن سیگنال‌های WebRTC |
| `EndCall` | **بدون پارامتر** | پایان تماس فعلی |

نکته‌ی مهم درباره‌ی `EndCall`: سرور از روی `ConnectionId` خودش می‌فهمد کاربر در کدام تماس است (نیازی به فرستادن دوباره‌ی `reserveId`/`sessionId` نیست). یعنی سمت اپ کافی است بعد از تأیید کاربر فقط `EndCall()` را صدا بزنید (یا حتی فقط اتصال SignalR را ببندید — سرور در `OnDisconnectedAsync` هم دقیقاً همان رفتار `EndCall` را انجام می‌دهد، ولی صدا زدن صریح `EndCall()` قبل از قطع اتصال ترجیح داده می‌شود چون تمیزتر و سریع‌تر برای طرف مقابل است).

## ۴) رویدادهایی که کلاینت گوش می‌دهد

| رویداد | معنی | اکشن پیشنهادی در UI |
| --- | --- | --- |
| `waitingForPeer` | شما اولین نفری هستید که وارد شده؛ منتظر طرف مقابل | نمایش «در حال زنگ خوردن…» |
| `callConnected(shouldOffer: bool)` | هر دو طرف وصل شدند، مذاکره‌ی WebRTC شروع می‌شود | نمایش تایمر تماس، فعال کردن دکمه‌های میوت/بلندگو |
| `signal(type, payload)` | پیام WebRTC از طرف مقابل | پردازش offer/answer/ice |
| `callEnded` | **طرف مقابل** (کاربر یا اپراتور دیگر) تماس را پایان داد یا قطع شد | تماس را همان لحظه ببندید، toast «تماس توسط طرف مقابل پایان یافت»، خروج از صفحه‌ی تماس — **دیگر نیازی به دیالوگ تأیید نیست چون خودِ شما اقدام نکرده‌اید** |
| `callError(message)` | خطای سرور (رزرو نامعتبر/لغوشده/غیرمجاز و…) | نمایش پیام خطا و بازگشت |

## ۵) جریان پیشنهادی «پایان تماس با تأیید کاربر»

1. کاربر (نماینده) روی دکمه‌ی قرمز «پایان تماس» می‌زند.
2. اپ یک `AlertDialog`/`showModalBottomSheet` نشان می‌دهد:
   - عنوان: «پایان تماس»
   - متن: «آیا از پایان دادن به این تماس مطمئن هستید؟»
   - دکمه‌ی اصلی (قرمز): «بله، پایان بده»
   - دکمه‌ی ثانویه: «انصراف»
3. اگر «انصراف» زده شد: هیچ کاری نکنید، تماس ادامه دارد.
4. اگر «بله» زده شد:
   ```dart
   await hubConnection.invoke('EndCall');
   // سپس بستن مدیا لوکال (میکروفون/دوربین) و خروج از صفحه‌ی تماس
   ```
5. توجه: اگر رویداد `callEnded` از سرور برسد (یعنی طرف مقابل پایان داده)، دیالوگ تأیید نباید نمایش داده شود — این حالت فقط برای اقدام خودِ کاربر لازم است، نه وقتی طرف مقابل قطع کرده.

همین الگو (دیالوگ تأیید قبل از هر اکشن مخرب/برگشت‌ناپذیر) برای قطع دوربین/میکروفون لازم نیست، فقط برای **پایان کامل تماس**.

## ۶) نکته‌ی مهم درباره‌ی «چت» (بدون تماس)

اگر منظور از «پایان چت» بستن یک مکالمه‌ی متنی (بدون تماس صوتی/ویدیویی فعال) است: **در حال حاضر چنین endpoint یا متد هابی در بک‌اند وجود ندارد.** جست‌وجوی کامل روی `Api/Hubs` و `Api/Areas` هیچ چیزی شبیه `EndChat`/`CloseSession`/`FinishSession` پیدا نکرد؛ تنها چیزی که «پایان» دارد همین تماس (`CallHub.EndCall`) است، که `CompanionReserve.CallEndDate` را ست می‌کند (برای رزروهای آنلاین) — برای «جلسه‌ی آنلاین» مستقل (`OnlineSession`) حتی همین‌قدر هم امکان ثبت پایان توسط کلاینت وجود ندارد (فقط یک Job دوره‌ای در بک‌اند، `ConsultationSessionService.CompleteExpiredAsync`، جلسات منقضی‌شده را می‌بندد).

اگر اپ نماینده واقعاً نیاز به «پایان دستی چت» (نه فقط تماس) دارد، این باید به‌عنوان یک قابلیت جدید از تیم بک‌اند خواسته شود — فعلاً فقط پایان **تماس** (صوتی/ویدیویی) پیاده‌سازی‌شده و مستند بالا برای همان است.
