# مشاوره‌ی آنلاین کلینیک و مربی در اپ نماینده — پاسخ به سؤال «خدمت ۱۵» و «قیمت جدا برای هر کانال»

**مخاطب:** توسعه‌دهنده‌ی اپ نماینده (ویزارد کلینیک/مربی، صفحه‌ی «بسته‌های مشاوره‌ی آنلاین»)
**وضعیت بک‌اند (۱۴۰۵/۰۸/۰۲ ≈ 2026-10-24):** کد و تست آماده است، ولی **مایگریشن `VenueConsultationOwners` اجرا شده، Api و Payment جدید دیپلوی شده و اسکریپت انتقال اجرا شده است** (تأیید مالک پروژه، ۱۴۰۵/۰۸/۰۲). اندپوینت‌های زیر روی سرور فعال‌اند و می‌توان روی دستگاه تست کرد. ترتیب دیپلوی: `CONSULTATION_VENUE_OWNERS_FA.md`.

## ۱) خلاصه‌ی مشکل
گزارش اپ دو برداشت دارد و هر دو با بک‌اند فعلی نمی‌خواند:

1. **«مربی قیمت جدا برای چت/صوت/تصویر ندارد و مستند آن را پیاده‌نشده می‌داند.»** این درست نیست. در مستندات فعلی چنین جمله‌ای نیست و کد هم کانال را دارد (جزئیات بند ۳). احتمالاً نسخه‌ی قدیمی مستند یا ساختار قبلی (مشاوره‌ی مربی روی Companion لنگر پنهان) خوانده شده. چیزی که پیاده‌نشده است «قیمت‌گذاری مشاوره روی پکیج‌های رزرو نوبتی مربی (`CoachService` / Mode=۳۷)» است، نه این سامانه.
2. **«در ویزارد باید خدمت شناسه‌ی ۱۵ انتخاب شود.»** این مرحله دیگر لازم نیست. بسته‌ی مشاوره‌ی کلینیک/مربی به هیچ خدمت کاتالوگ (`Assistance`) وصل نیست؛ جدول `ConsultationPackage` اصلاً ستون `AssistanceId` ندارد. شناسه‌ی ۱۵ فقط ثابتی برای نمایندگی قدیمی (Companion) است. پس نیازی نیست برای کلینیک/مربی خدمتی «اضافه شود» یا «قبلاً اضافه شده» نمایش داده شود.

## ۲) تصمیم برای اپ
- مرحله‌ی «انتخاب خدمت» را برای مشاوره‌ی آنلاین کلینیک/مربی **حذف کنید**. «مشاوره‌ی آنلاین» یک بخش مستقل است که مستقیم به صفحه‌ی بسته‌ها می‌رود.
- پکیج را با `clinicId` یا `coachId` بسازید، نه با `companionId` و نه با خدمت.
- «من آنلاینم» و «برنامه‌ی رزرو» هم روی همین شناسه‌ها کار می‌کنند (بند ۴).
- کلینیک/مربی تکی که هنوز Companion ندارد دیگر Companion «لنگر» نمی‌گیرد؛ چیزی برای ساخت وجود ندارد.

## ۳) قیمت جدا برای هر کانال — همین الان وجود دارد
هر پکیج یک ردیف مستقل با **کانال + مدت + قیمت + نام** است؛ پس قیمت هر کانال با ساخت یک پکیج جدا برای همان کانال تعیین می‌شود.

مقادیر مجاز:
- `channelId`: ۱ چت، ۲ تماس درون‌برنامه، ۳ تماس تصویری، ۴ تماس تلفنی
- `durationMinutes`: یکی از ۱۵، ۳۰، ۴۵، ۶۰، ۹۰ (مقدار دیگر خطای مدت نامعتبر می‌دهد)
- `name` الزامی ۲ تا ۱۰۰ کاراکتر؛ `description` اختیاری تا ۵۰۰؛ `price` ≥ ۰ (تومان)
- پکیج **فعال** فقط با `price > 0` ذخیره می‌شود؛ غیرفعال می‌تواند قیمت ۰ داشته باشد.
- نام پکیج زیر یک کانال نباید تکراری باشد (اعتبارسنجی سرور).
- `bookable` (اختیاری): `true` یعنی کاربر موقع خرید ساعت انتخاب می‌کند (نیازمند برنامه‌ی رزرو، بند ۴).

مثال: «چت ۳۰ دقیقه ۲۰۰ هزار» و «تصویری ۳۰ دقیقه ۴۰۰ هزار» دو `POST` جدا هستند.

### اندپوینت‌ها (کلینیک: `ClinicConsultationPackage` + `clinicId`؛ مربی: `CoachConsultationPackage` + `coachId`)
| متد | مسیر | توضیح |
|---|---|---|
| GET | `/api/Companion/CoachConsultationPackage?coachId=` | همه‌ی پکیج‌ها، فعال و غیرفعال |
| POST | `/api/Companion/CoachConsultationPackage?coachId=` | ساخت (بدنه: `channelId, durationMinutes, price, active, name, description, pictureId, bookable`) |
| PUT | همان | ویرایش؛ `id` الزامی؛ فعال/غیرفعال هم همین‌جا |
| DELETE | `/api/Companion/CoachConsultationPackage?coachId=&id=` | حذف نرم |

دسترسی: مالک یا عضو فعال و تأییدشده‌ی همان مرکز؛ نوشتن فقط برای مرکز فعال و تأییدشده. در غیر این‌صورت `IsSuccess=false` با پیام دسترسی/عدم‌تأیید (طبق قاعده‌ی پروژه HTTP همیشه ۲۰۰ است؛ `IsSuccess` را بخوانید).

نکته: درصد کارمزد پاستیل روی پکیج را فقط ادمین از پنل تنظیم می‌کند و در این بدنه نیست.

## ۴) بقیه‌ی اندپوینت‌های همین بخش
- **آنلاینم:** `GET /api/Companion/{Clinic|Coach}ConsultationOnline?{clinic|coach}Id=` و `PUT` با بدنه `{clinicId|coachId, online}`.
- **برنامه‌ی رزرو** (برای پکیج‌های `bookable`): `GET/PUT /api/Companion/{Clinic|Coach}ConsultationAvailability?{clinic|coach}Id=` با همان بدنه‌ی قدیمی `ConsultationAvailability`.
- **صف جلسه‌ها** (`/api/Companion/ConsultationSession…`): بدون تغییر مسیر؛ مشاوره‌های همه‌ی مرکزهایی که کاربر مالک/عضو آن است خودکار می‌آیند و آیتم‌ها `clinicId`/`coachId` دارند (`companionId` ممکن است `null` باشد؛ nullable بخوانید).
- **سمت مشتری** (برای نمایش پیش‌نمایش): `GET /api/Coach/{id}/ConsultationPackages`، `GET /api/Clinic/{id}/ConsultationPackages`.

## ۵) تغییر مهم در مدل‌های پاسخ
در پاسخ‌های بسته/خرید/جلسه: `companionId` **nullable** شد و `clinicId` و `coachId` اضافه شدند؛ دقیقاً یکی از سه پر است. `companionName` همچنان نام مرکز را دارد. کد اپ نباید فرض کند `companionId` همیشه مقدار دارد.

## ۶) آنچه مستند قدیمی/اپ را باید اصلاح کرد
1. حذف مرحله‌ی «انتخاب خدمت ۱۵» و پیام «قبلاً اضافه شده» برای مشاوره‌ی کلینیک/مربی.
2. حذف هر کد که برای کلینیک/مربی `CompanionAssistance` یا خدمت ۱۵ می‌سازد.
3. استفاده از `coachId`/`clinicId` در همه‌ی فراخوانی‌های این بخش، به‌جای `companionId`.
4. فرم قیمت‌گذاری مربی هم می‌تواند همان فرم کلینیک باشد (فهرست پکیج‌ها گروه‌بندی‌شده بر اساس `channelId`، با افزودن/ویرایش/فعال‌سازی). نیازی به تغییر بک‌اند نیست.

## ۷) هنوز مشخص نیست / نیاز به تصمیم
- Permission Sync و آپلود پنل (مرتبط با ادمین، نه اپ) اگر هنوز انجام نشده باید انجام شود.
- اگر منظور تیم محصول «قیمت جدا برای چت/صوت/تصویر **در رزرو نوبتی عادی مربی** (`CoachService`)» بوده باشد، آن واقعاً وجود ندارد و باید جداگانه طراحی شود؛ لطفاً تأیید کنید کدام مدنظر است.
