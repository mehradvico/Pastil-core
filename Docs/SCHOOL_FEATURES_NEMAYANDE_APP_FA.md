# مدرسه — ویژگی‌های جدید برای «اپ نماینده» (اپ ارائه‌دهنده)

**مخاطب:** توسعه‌دهنده‌ی اپ نماینده (Flutter)، بخش «مدرسه‌ی من».
**تاریخ:** ۱۴۰۵/۰۸/۰۶ (2026-10-28)
**وضعیت بک‌اند:**
- مایگریشن روی دیتابیس **اجرا شده** است.
- کد Api **هنوز دیپلوی نشده** است. تا اعلام دیپلوی، اندپوینت‌های این مستند جواب ۴۰۴ می‌دهند.

**مستند هم‌زاد:** بخش مشتری در `SCHOOL_FEATURES_WEBAPP_FA.md` است (وب‌اپ).

---

## ۰) قواعد عمومی (حتماً بخوانید)
- **پایه‌ی آدرس‌ها:** همه‌ی مسیرها با `https://api.pastil.pet` شروع می‌شوند.
- **توکن:** همه‌ی اندپوینت‌ها توکن کاربر را می‌خواهند: `Authorization: Bearer …`.
- **شکل پاسخ:** همیشه HTTP 200 با `{ "isSuccess": bool, "code": int, "messages": [{ "item1": "متن", "item2": "" }], "data": … }` است. موفق بودن را از `isSuccess` تشخیص دهید، نه از کد HTTP. اگر `false` بود، `messages[0].item1` را **همان‌طور** به کاربر نشان دهید.
- **«مالک» و «مدرس» در این مستند:**
  - **مالک** = کاربرِ ارائه‌دهنده‌ای که مدرسه به او وصل است (یا مالک نمایندگیِ مدرسه‌های قدیمی).
  - **مدرس** = مالک، یا کاربری که مالک او را مدرس یک دوره کرده است (بند ۴).
- **عدم دسترسی:** جواب «شما به این بخش دسترسی ندارید» با `isSuccess=false` است، نه ۴۰۳.
- **فرمت‌ها:**
  - تاریخ: `2026-11-01` یا `2026-11-01T00:00:00`.
  - ساعت: رشته‌ی `HH:mm`، مثلاً `"10:00"`.
  - مبلغ: تومان، عدد اعشاری (`double`).

## ۱) روزهای دوره: «این دوره n جلسه است، روزهایش را انتخاب کن»

### جریان در اپ
1. در فرم ساخت یا ویرایش دوره، فیلد **«تعداد جلسات»** (`sessionCount`) مثل قبل است. مثلاً ۴.
2. بعد از ذخیره‌ی دوره، دکمه‌ی **«تعیین روزهای دوره»** را نشان دهید.
3. صفحه‌ی انتخاب روز:
   - یک تقویم شمسی که کاربر **دقیقاً `sessionCount` روز** را انتخاب کند. تا وقتی تعداد درست نشده، دکمه‌ی ذخیره غیرفعال بماند و شمارنده‌ای مثل «۳ از ۴ روز انتخاب شده» نشان دهید.
   - روزهای گذشته و امروزِ ساعت‌گذشته قابل انتخاب نباشند.
   - برای هر روز انتخاب‌شده یک ردیف با **ساعت شروع** و **ساعت پایان** بگذارید. پیش‌فرض ساعت روز اول، و ساعت پایان = شروع + `sessionDurationMinutes`. هر روز جداگانه قابل تغییر است.
   - یک گزینه‌ی «همه‌ی روزها همین ساعت» برای راحتی بگذارید.
4. **ذخیره** همه را یک‌جا می‌فرستد.

### اندپوینت
```
PUT /api/Companion/SchoolCourseSession/Schedule
{
  "schoolCourseId": 12,
  "sessions": [
    { "sessionDate": "2026-11-01", "startTime": "10:00", "endTime": "11:30" },
    { "sessionDate": "2026-11-03", "startTime": "10:00", "endTime": "11:30" },
    { "sessionDate": "2026-11-05", "startTime": "17:00", "endTime": "18:30" },
    { "sessionDate": "2026-11-08", "startTime": "10:00", "endTime": "11:30" }
  ]
}
```
پاسخ موفق: `data` لیست **همه‌ی** جلسه‌های دوره است، مرتب بر اساس زمان:
```json
[ { "id": 501, "schoolCourseId": 12, "sessionDate": "2026-11-01T00:00:00", "startTime": "10:00", "endTime": "11:30", "meetingUrl": null, "active": true }, … ]
```

### قواعد سرور و پیام‌ها
| وضعیت | پیام |
|---|---|
| تعداد روزها درست نیست | «این دوره ۴ جلسه است؛ باید دقیقاً ۳ روز جدید انتخاب کنید.» (عددها واقعی‌اند) |
| روزی در گذشته | «تاریخ و ساعت جلسه باید در آینده باشد.» |
| ساعت پایان قبل از شروع | پیام ساعت نامعتبر (`ToTimeMustBeBiggerThanFromTime`) |
| دو جلسه هم‌پوشانی دارند | «زمان دو جلسه با هم تداخل دارد.» |
| دوره مال این کاربر نیست | «شما به این بخش دسترسی ندارید» |

**جلسه‌های قبلی:**
- ذخیره‌ی دوباره، همه‌ی جلسه‌های **آینده** را حذف و لیست جدید را جایگزین می‌کند. جلسه اضافه نمی‌شود.
- جلسه‌هایی که **گذشته‌اند**، یا برایشان **حضور و غیاب** ثبت شده، یا **کلاس زنده** داشته‌اند، دست نمی‌خورند و **جزو شمارش‌اند**.
- مثال: دوره‌ی ۴ جلسه‌ای که جلسه‌ی اولش برگزار شده → فقط ۳ روز جدید بفرستید.
- **پیشنهاد UI:** این جلسه‌های قفل‌شده را در تقویم با رنگ دیگر و غیرقابل‌انتخاب نشان دهید، و شمارنده را «۱ برگزار شده + ۳ از ۳ روز» بنویسید.

**ویرایش یک جلسه** (جابه‌جایی یا تغییر لینک): مسیر قبلی `PUT /api/Companion/SchoolCourseSession` (تک‌جلسه) بدون تغییر کار می‌کند.

## ۲) تنظیمات جدید دوره (فرم ساخت/ویرایش دوره)
مسیرها همان قبلی‌اند: `POST /api/Companion/SchoolCourse` و `PUT /api/Companion/SchoolCourse`. این فیلدها به بدنه اضافه شده‌اند:

| فیلد | نوع | اگر نفرستید | کنترل پیشنهادی در فرم | معنی |
|---|---|---|---|---|
| `level` | int | ۰ | منوی کشویی | سطح: ۰ نامشخص، ۱ مقدماتی، ۲ متوسط، ۳ پیشرفته |
| `prerequisiteCourseId` | long یا null | null | منوی کشویی «بدون پیش‌نیاز» + دوره‌های **همین مدرسه** به‌جز خود دوره | همان پت باید این دوره را «کامل‌شده» داشته باشد تا ثبت‌نام کند |
| `lateEnrollmentMode` | int | ۰ | سه گزینه‌ی رادیویی | ثبت‌نام بعد از شروع جلسه‌ی اول: ۰ بسته، ۱ باز با قیمت کامل، ۲ باز با قیمت جلسه‌های باقی‌مانده. حالت ۱ و ۲ تا شروع جلسه‌ی **آخر** باز است |
| `fullRefundHoursBeforeStart` | int یا null | ۲۴ (فقط در ساخت؛ در ویرایش مقدار قبلی می‌ماند) | فیلد عددی «ساعت» | اگر مشتری تا این چند ساعت قبل از جلسه‌ی اول لغو کند، **کل** مبلغ برمی‌گردد (۰ تا ۷۲۰) |
| `lateCancelRefundPercent` | int یا null | ۵۰ (مثل بالا) | فیلد عددی «٪» | لغو دیرتر ولی قبل از شروع: این درصد برمی‌گردد (۰ تا ۱۰۰). بعد از شروع لغو ممکن نیست |
| `certificateEnabled` | bool | false | کلید روشن/خاموش | صدور خودکار گواهی پایان دوره (بند ۷) |

**متن راهنمای پیشنهادی زیر هر فیلد:**
- ثبت‌نام دیرهنگام، حالت ۲: «مثلاً دوره‌ی ۸ جلسه‌ای ۸۰۰ هزار تومانی، بعد از جلسه‌ی سوم ۵۰۰ هزار تومان.»
- سیاست لغو: «تا ۲۴ ساعت قبل از شروع: بازگشت کامل. دیرتر: ۵۰٪. بعد از شروع: امکان لغو ندارد.» عددها از فیلدها بیایند.

**خطاهای جدید:** اگر سطح یا حالت نامعتبر باشد، یا ساعت/درصد خارج از بازه، پیام داده‌ی نامعتبر (`InvalidData`) می‌آید. اگر پیش‌نیاز در این مدرسه نباشد، «موردی یافت نشد».

**فیلدهای جدید در پاسخ GET دوره** (`GET /api/Companion/SchoolCourse/{id}` و لیست):

| فیلد | نمایش در اپ |
|---|---|
| همه‌ی فیلدهای بالا | برای پر کردن فرم ویرایش |
| `prerequisiteCourseName` | «پیش‌نیاز: …» روی کارت دوره |
| `rateAvg`، `rateCount` | ستاره و تعداد نظر روی کارت دوره |
| `enrollPrice`، `remainingSessions` | قیمت ثبت‌نامِ همین الان (برای اطلاع ارائه‌دهنده) |

## ۴) مدرس‌ها
هر دوره یک **مدرس اصلی** و هر تعداد **کمک‌مدرس** دارد. مدرس یک کاربرِ پاستیل است (باید قبلاً در اپ ثبت‌نام کرده باشد) و با **موبایل** اضافه می‌شود.

| کار | متد و مسیر | دسترسی | بدنه / پارامتر |
|---|---|---|---|
| لیست مدرس‌ها | `GET /api/Companion/SchoolTeaching/Instructors?courseId=12` | مالک یا مدرس | — |
| افزودن | `POST /api/Companion/SchoolTeaching/Instructors` | فقط مالک | `{ "schoolCourseId": 12, "mobile": "09121234567", "isLead": false }` |
| حذف | `DELETE /api/Companion/SchoolTeaching/Instructors?courseId=12&id=4` | فقط مالک | — |
| دوره‌هایی که من مدرسشان هستم | `GET /api/Companion/SchoolTeaching/MyCourses` | هر کاربر | خروجی: لیست شناسه‌ی دوره |

پاسخ لیست:
```json
[ { "id": 4, "schoolCourseId": 12, "userId": 900, "fullName": "سارا محمدی", "mobile": "0912…", "isLead": true } ]
```
- فقط **یک** مدرس اصلی وجود دارد. افزودن مدرس اصلی جدید، قبلی را خودکار کمک‌مدرس می‌کند.
- **خطاها:**
  - «کاربری با این شماره موبایل در پاستیل پیدا نشد.» → به کاربر بگویید آن شخص اول در پاستیل ثبت‌نام کند.
  - «این کاربر قبلاً مدرس همین دوره است.»

**مدرس چه کارهایی می‌تواند بکند؟**
- حضور و غیاب، مهارت‌ها و نمره، کارنامه، و صدور گواهی **همان دوره** (بندهای ۵ تا ۷).
- مدیریت مدرس‌ها، لیست انتظار و داشبورد فقط برای **مالک** است.
- کلاس زنده در این نسخه هنوز فقط برای مالک است.

**بخش «کلاس‌های من» برای مدرسی که مالک نیست:**
1. هنگام ورود، `MyCourses` را بزنید. اگر خالی نبود، بخش «کلاس‌های من» را نشان دهید.
2. جزئیات هر دوره را با `GET /api/Companion/SchoolCourse/{id}` بگیرید.
3. از آن‌جا جلسه‌ها ← حضور و غیاب، و ثبت‌نام‌ها ← کارنامه.

## ۵) حضور و غیاب
**ورود:** در لیست جلسه‌های دوره، روی هر جلسه دکمه‌ی **«حضور و غیاب»** بگذارید.

**گرفتن لیست:**
```
GET /api/Companion/SchoolTeaching/Roster?sessionId=88
→ [ { "schoolReserveId": 301, "reserveCode": "SC-…", "userPetId": 55, "petName": "رکس",
      "ownerFullName": "علی رضایی", "present": null, "note": null }, … ]
```
- `present: null` یعنی هنوز ثبت نشده، `true` حاضر، `false` غایب.
- لیست فقط ثبت‌نام‌های **پرداخت‌شده یا کامل‌شده** را دارد، نه لغوشده‌ها.

**ذخیره:**
```
PUT /api/Companion/SchoolTeaching/Attendance
{ "schoolCourseSessionId": 88,
  "items": [ { "schoolReserveId": 301, "present": true },
             { "schoolReserveId": 302, "present": false, "note": "اطلاع داد بیمار است" } ] }
```
- ذخیره‌ی دوباره همان را ویرایش می‌کند.
- یادداشت حداکثر ۵۰۰ نویسه.
- همه‌ی ثبت‌نام‌های ارسالی باید متعلق به همان دوره باشند، وگرنه کل درخواست با پیام داده‌ی نامعتبر (`InvalidData`) رد می‌شود.
- به هر **غایب**، برای هر جلسه یک بار، پوش «جلسه را از دست دادید» می‌رود. اپ نماینده کاری لازم ندارد.

**پیشنهاد UI:**
- لیست پت‌ها، هر ردیف با دو دکمه‌ی ✓ و ✗ و یک آیکن یادداشت.
- بالای لیست: «همه حاضر».
- پایین صفحه: «ذخیره».

## ۶) مهارت‌ها و کارنامه‌ی پیشرفت پت

### ۶-۱) تعریف مهارت‌های دوره
در جزئیات دوره، یک بخش «مهارت‌ها». مثال‌ها: «نشستن با فرمان»، «ماندن»، «آمدن با صدا زدن»، «راه رفتن با قلاده».
```
GET    /api/Companion/SchoolTeaching/Skills?courseId=12
POST   /api/Companion/SchoolTeaching/Skills       { "id": 0, "schoolCourseId": 12, "name": "نشستن", "sortOrder": 1 }
POST   /api/Companion/SchoolTeaching/Skills       { "id": 7, "schoolCourseId": 12, "name": "نشستن با فرمان", "sortOrder": 1 }   ← ویرایش
DELETE /api/Companion/SchoolTeaching/Skills?courseId=12&id=7
```
نام مهارت الزامی است و حداکثر ۱۰۰ نویسه.

### ۶-۲) ثبت نمره
بعد از هر جلسه (یا هر زمان)، برای هر پت به هر مهارت نمره‌ی **۱ تا ۵** بدهید:
```
POST /api/Companion/SchoolTeaching/Progress
{ "schoolReserveId": 301,
  "schoolCourseSessionId": 88,           ← اختیاری: نمره مربوط به کدام جلسه
  "items": [ { "schoolCourseSkillId": 7, "score": 4, "note": "خیلی بهتر شد" },
             { "schoolCourseSkillId": 8, "score": 2 } ] }
```
- هر ارسال یک ردیف **تاریخچه** می‌سازد. «آخرین نمره» همیشه آخرین ثبت است.
- نمره‌ی خارج از ۱ تا ۵ این پیام را می‌دهد: «نمره باید بین ۱ تا ۵ باشد.»

**پیشنهاد UI:** بعد از ذخیره‌ی حضور و غیاب، دکمه‌ی «نمره‌دهی این جلسه». یک صفحه با لیست پت‌های حاضر و برای هر پت ستاره‌های ۱ تا ۵ برای هر مهارت.

## ۷) گواهی پایان دوره
- **شرط:** دوره `certificateEnabled = true` داشته باشد و ثبت‌نام **«کامل‌شده»** باشد.
- **صدور خودکار:** وقتی ارائه‌دهنده ثبت‌نام را «کامل‌شده» می‌کند (همان مسیر قبلی `PUT /api/Companion/SchoolReserve/{id}/Complete`)، گواهی خودکار صادر می‌شود و برای مالک پت پوش می‌رود.
- **صدور دستی یا دوباره** (مثلاً برای ثبت‌نام‌هایی که قبل از روشن کردن گواهی کامل شده‌اند):
```
POST /api/Companion/SchoolTeaching/Certificate?reserveId=301
→ { "code": "PSC-7KQ2MX9A", "issueDate": "...", "courseName": "تربیت پایه", "courseLevel": 1,
    "schoolName": "...", "petName": "رکس", "ownerFullName": "علی رضایی", "sessionCount": 4, "attendedCount": 4 }
```
- تکرار، همان گواهی را برمی‌گرداند و گواهی جدید نمی‌سازد.
- **خطا:** «گواهی فقط برای ثبت‌نام «کامل‌شده» در دوره‌ی دارای گواهی صادر می‌شود.»

**پیشنهاد UI:**
- در لیست ثبت‌نام‌ها، کنار ثبت‌نام کامل‌شده نشان «گواهی صادر شد» (از `certificate` در کارنامه).
- برای کامل‌شده‌های بدون گواهی، دکمه‌ی «صدور گواهی».

## ۱۰) تغییرهای رفتاری که باید بدانید
1. **لغو توسط مشتری:** قبلاً همیشه ۱۰۰٪ برمی‌گشت. حالا طبق سیاست لغو دوره است (بند ۲). سهم شما از بخش نگه‌داشته‌شده در **تسویه‌ی مدرسه** می‌آید.
2. **ثبت‌نام بعد از شروع:** اگر `lateEnrollmentMode` را ۱ یا ۲ بگذارید، بعد از شروع هم ثبت‌نام جدید می‌آید. در حضور و غیاب، پت‌هایی را خواهید دید که از وسط دوره آمده‌اند.
3. **پیش‌نیاز:** ثبت‌نام پتی که پیش‌نیاز را کامل نکرده، سمت سرور رد می‌شود.
4. **یادآوری:** مشتری‌ها حالا حدود ۲۴ ساعت قبل از هر جلسه (حضوری و زنده) پوش «فردا کلاس دارید» می‌گیرند.

## ۱۱) چک‌لیست تست (بعد از اعلام دیپلوی Api)
1. ساخت دوره‌ی ۴ جلسه‌ای با سطح «مقدماتی»، سیاست لغو ۲۴ ساعت / ۵۰٪، و گواهی روشن ← ذخیره ← GET دوره همین مقادیر را برگرداند.
2. «تعیین روزها»: انتخاب ۳ روز ← پیام تعداد؛ انتخاب ۴ روز ← ذخیره ← ۴ جلسه.
3. دوباره «تعیین روزها» با روزهای دیگر ← هنوز ۴ جلسه، با روزهای جدید.
4. دو جلسه‌ی هم‌پوشان در یک روز ← پیام تداخل.
5. دوره‌ی دوم با پیش‌نیاز = دوره‌ی اول ← در وب‌اپ با پت بدون پیش‌نیاز ثبت‌نام ← رد شود.
6. افزودن کمک‌مدرس با موبایل یک کاربر دیگر ← آن کاربر وارد اپ شود ← `MyCourses` همان دوره را بدهد.
7. همان مدرس ← حضور و غیاب یک جلسه ← یک غایب ← مالک آن پت پوش «جلسه را از دست دادید» بگیرد.
8. تعریف ۳ مهارت ← نمره‌دهی ← کارنامه همان نمره‌ها را نشان دهد.
9. «کامل‌شده» کردن یک ثبت‌نام ← گواهی خودکار صادر شود ← در کارنامه `certificate` پر باشد.
10. صدور دستی دوباره ← همان کد برگردد.
11. پر کردن ظرفیت ← مشتری دیگر در صف ← در اپ «لیست انتظار: ۱ نفر».
12. داشبورد ← ثبت‌نام، صف، درآمد و درصد حضور با واقعیت بخواند.
13. کاربر غیرمالک: افزودن مدرس یا دیدن داشبورد ← «شما به این بخش دسترسی ندارید».
