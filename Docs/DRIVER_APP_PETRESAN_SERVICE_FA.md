# سرویس هفتگی پت‌رسان در اپ راننده (قرارداد بک‌اند)

مخاطب: اپ‌نویس راننده. همه‌ی موردها از روی کد بک‌اند نوشته شده.

## ۱) سرویس هفتگی چیست و کِی به راننده می‌رسد؟
- کاربر یک **برنامه‌ی هفتگی** ثبت می‌کند (روزها و ساعت‌های رفت و اختیاری برگشت). ثبت برنامه Trip نمی‌سازد.
- هر روز ساعت **۲۰:۰۰ تهران** یک job برای **فردا** از هر ردیف برنامه یک Trip می‌سازد («نوبت»). ردیف با ساعت برگشت، دو نوبت یک‌طرفه می‌سازد (رفت، و برگشت با `isReturnLeg = true`).
- اگر سرویس **بعد از ۲۰:۰۰** ثبت شود، نوبت‌های فردایش همان لحظه‌ی ثبت ساخته می‌شود.
- هزینه‌ی هر نوبت همان لحظه از کیف پول کاربر کسر می‌شود. **اگر موجودی کم باشد نوبت لغو می‌شود و هرگز به راننده نمی‌رسد.**
- بعد از ساخت نوبت‌ها یک **پوش تجمیعی** به همه‌ی رانندگان فعال می‌رود: `PushTripServiceOccurrencesAvailable` (۱۱۳) — «N سفر جدید سرویس هفتگی برای فردا در دسترس است»، لینک `/driverProfile/suggestedTrips`. با دریافت آن لیست را تازه کنید.

## ۲) نوبت در API چه شکلی است؟
نوبت یک Trip عادی است که در `GET api/Driver/TripAvailable` می‌آید (نه `TripUpcoming`)، و فقط بعد از قبول راننده در `TripUpcoming` ظاهر می‌شود.

| فیلد | مقدار در نوبت سرویس |
|---|---|
| **`petResanServiceScheduleId`** | **≠ null** — **تنها نشانه‌ی قطعی «سرویس دوره‌ای»** (فیلد جدید؛ بعد از دیپلوی بک‌اند می‌آید) |
| `tripStatusId` | ۷۵ (درخواست‌شده) تا قبول، سپس ۷۶ |
| `driverId` | `null` تا قبول |
| `tripStartDateTime` | زمان حرکت نوبت (ساعت تهران، بدون offset) |
| `scheduledDepartureAt` | **`null`** — سرویس این را پر نمی‌کند؛ زمان را از `tripStartDateTime` بخوانید |
| `companionReserveId` / `pansionReserveId` / `schoolReserveId` | `null` |
| `isReturnLeg` | `true` برای نوبت برگشت |
| `roundTrip` | `true` فقط برای ردیف بدون ساعت برگشت (یک سفر رفت‌وبرگشت) |

تشخیص نوع سفر:
```
سرویس دوره‌ای : petResanServiceScheduleId != null
رزرو متصل     : companionReserveId / pansionReserveId / schoolReserveId != null
رزروی مستقل    : scheduledDepartureAt != null
سفر فوری      : هیچ‌کدام
```
تشخیص موقتی از روی شکل سفر (بیش از یک ساعت بعد، بدون رزرو) تا زمان دیپلوی قابل قبول است، ولی بعد از آن باید کنار گذاشته شود.

## ۳) قبول، اجرا، لغو
| کار | Endpoint |
|---|---|
| قبول | `PUT api/Driver/UpdateTripDriverStatus` با `{ id, driverStatusId }` (DriverStatus «پذیرفته‌شده») |
| در مسیر مبدأ ← رسیدن به مبدأ | `PUT api/Driver/TripArrivedOrigin/{id}` |
| پت سوار شد | `PUT api/Driver/TripPetPickedUp/{id}` |
| رسیدن به مقصد | `PUT api/Driver/TripArrivedDestination/{id}` |
| لغو توسط راننده | `PUT api/Driver/TripDriverCancel` با `{ id, cancelReasonCodeId, cancelDetail }` |
| سفر جاری | `GET api/Driver/TripCurrent` |
| سفرهای پیش‌رو | `GET api/Driver/TripUpcoming` |

- قبول **اتمیک** است: اگر چند راننده هم‌زمان بزنند فقط اولی برنده است؛ بقیه خطای «این سفر برای راننده‌ی دیگری رزرو شد» می‌گیرند.
- بعد از قبول: `tripStatusId = 76` و `progressStageId = 1`. «پذیرفته‌شده» را فقط با `tripStatusId === 76` تشخیص دهید.
- راننده‌ای که یک سفر پذیرفته‌شده (رزروی یا سرویس) دارد که **کمتر از ۱ ساعت** تا حرکتش مانده، «مشغول» است: `TripAvailable` برایش **لیست خالی** برمی‌گرداند و قبول سفر جدید با خطای «سفر رزروی پیش‌رو دارید» رد می‌شود. نوبتی که هنوز ≥ ۱ ساعت مانده، مانع قبول چیز دیگر نیست.
- **لغو راننده** فقط قبل از «پت سوار شد» ممکن است؛ سفر `Canceled (۷۷)` می‌شود، راننده از آن نوبت مستثنا می‌شود و برای کاربر پوش می‌رود. دلیل لغو باید از گروه کدِ دلایل راننده باشد.
- ۳۰ دقیقه مانده به حرکتِ نوبت پذیرفته‌شده یک بار پوش یادآوری `PushTripDriverUpcomingReminder` می‌رسد («… تا ۳۰ دقیقه‌ی دیگر شروع می‌شود»).
- اگر تا ۱ ساعت مانده به حرکت هیچ راننده‌ای قبول نکند، به ادمین اطلاع داده می‌شود تا راننده را دستی انتخاب کند (fallback)؛ این روی اپ راننده اثر ندارد.

## ۴) نمایش در اپ راننده
- برچسب «سرویس دوره‌ای» و رنگ/متن دکمه‌ی قبول: از `petResanServiceScheduleId != null`.
- زمان نمایش: `tripStartDateTime` (بدون offset = ساعت تهران؛ با `Asia/Tehran` نمایش دهید).
- نوبت برگشت را با `isReturnLeg` مشخص کنید و مبدأ/مقصد را همان‌طور که در `origin`/`destination` آمده نمایش دهید (برای برگشت از قبل جابه‌جا شده‌اند).
- نوبت سرویس همیشه برای **فردا** است؛ نوبت‌های دورتر وجود ندارند.
- ساعت‌ها: زمان‌هایی که سرور می‌سازد (مثل `createDate`) از ۱۴۰۵/۰۷/۱۴ به وقت تهران است؛ قبلش UTC بود (۳:۳۰ عقب).

## ۵) چک‌لیست اپ راننده
1. نوع سفر را از `petResanServiceScheduleId` تشخیص دهید (و تشخیص موقتی از شکل سفر را بعد از دیپلوی بردارید).
2. روی پوش ۱۱۳ لیست `TripAvailable` را تازه کنید.
3. «پذیرفته‌شده» = `tripStatusId === 76`.
4. زمان نوبت از `tripStartDateTime`، نه `scheduledDepartureAt`.
5. لیست خالی `TripAvailable` برای راننده‌ای که < ۱ ساعت تا سفر پذیرفته‌شده‌اش مانده، خطا نیست؛ به‌جای «سفری نیست» پیام «برای سفر پیش‌روی خود آماده بمانید» نشان دهید.
