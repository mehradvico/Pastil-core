# چند سایز برای بسته‌ی خدمت (مربی، کلینیک، آرایشگاه) — ۱۴۰۵/۰۸/۱۴

قبلاً هر بسته فقط **یک** سایز داشت (یا «همه»). حالا بسته می‌تواند **چند سایز** داشته باشد، مثلاً «کوچک و متوسط». دیتابیس تغییری نکرده و migration لازم نیست.

## قاعده‌ی ذخیره
- سایزها `Small`، `Medium` و `Large` هستند.
- در `petSize` به‌صورت رشته‌ی جداشده با کاما و همیشه به همین ترتیب برمی‌گردند: `"Small,Medium"`.
- **هیچ سایز یا هر سه سایز = «همه»**: `petSize = null` و `petSizes = []`.
- پاسخ‌ها فیلد جدید `petSizes` (لیست) دارند. همان مقدار به‌صورت رشته در `petSize` هم هست.

## اپ نماینده (مربی، کلینیک، آرایشگاه)
افزودن و ویرایش بسته:
- `POST/PUT /api/Companion/CoachService/Package`
- `POST/PUT /api/Companion/ClinicService/Package`
- `POST/PUT /api/Companion/GroomerService/Package`

فیلد جدید ورودی:
```json
{ "petSizes": ["Small", "Medium"] }
```
- اگر `petSizes` پر باشد بر `petSize` مقدم است. نسخه‌های قدیمی که فقط `petSize` می‌فرستند (یک سایز یا `"Small,Medium"`) هم کار می‌کنند.
- سایز نامعتبر خطای فعلیِ «سایز نامعتبر» را می‌دهد. بزرگی و کوچکی حروف مهم نیست.

**UI:** چهار دکمه‌ی انتخابی به ترتیب «همه»، «کوچک»، «متوسط» و «بزرگ».
- زدن «همه» هر سه سایز را انتخاب می‌کند.
- با هر سه انتخاب، «همه» هم روشن است.
- زدن هر سایز آن را اضافه یا حذف می‌کند.
- اگر هیچ سایزی نماند، دوباره «همه» انتخاب می‌شود.
- پیش‌فرض بسته‌ی جدید: «همه».
- نمایش در لیست بسته‌ها: «سایز: کوچک، متوسط» یا «سایز: همه».

## اپ مشتری
- لیست خدمت‌ها با فیلتر سایز پت مثل قبل است، با یک پارامتر سایز (`petSize=Medium`). حالا بسته‌ای برمی‌گردد که سایز ندارد **یا** این سایز در سایزهایش هست.
- رزرو برای پتی پذیرفته می‌شود که سایزش در `petSizes` بسته باشد، یا بسته سایز نداشته باشد. پت بدون سایز فقط بسته‌های «همه» را می‌گیرد (مثل قبل).
- نمایش روی کارت بسته: از `petSizes` بخوانید؛ خالی = «همه‌ی سایزها»، وگرنه «مناسب: کوچک، متوسط».
- **اگر اپ سایز بسته را با `==` مقایسه می‌کند** (مثلاً برای مخفی کردن بسته‌های نامناسب)، به «`petSizes` خالی است یا سایز پت را دارد» تغییرش دهید. وگرنه بسته‌های چندسایزی نمایش داده نمی‌شوند.
