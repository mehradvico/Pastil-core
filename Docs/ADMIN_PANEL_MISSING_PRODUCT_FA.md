# صف «درخواست افزودن به کاتالوگ» (`MissingProduct`) — راهنمای پنل ادمین

فروشنده‌ها محصولی را که در کاتالوگ پاستیل پیدا نکرده‌اند ثبت می‌کنند و برای بررسی می‌فرستند
(راهنمای طرف فروشنده: `FLUTTER_MISSING_PRODUCT_FA.md`). این سند صفحه‌ای است که ادمین آن‌ها را بررسی می‌کند.

**نتیجهٔ «تأیید»:** یک `Product` واقعی در کاتالوگ ساخته می‌شود **و** همان محصول با همان قیمت/موجودیِ فروشنده
به فروشگاه او هم اضافه می‌شود. «رد» با دلیل متنی به فروشنده برمی‌گردد و او می‌تواند اصلاح و دوباره بفرستد.

Base URL: `https://api.pastil.pet` — همهٔ endpointها `Authorization: Bearer {accessToken}`.
پاسخ‌ها قالب استاندارد `{ isSuccess, code, messages, data }` و پیام خطا در `messages[0].item1` (فارسی، مستقیم قابل‌نمایش).

## دسترسی

این چهار endpoint با policy **`AdminOnly`** محافظت شده‌اند (توکنی که claim `RoleId` آن نقش «Admin» است).
فروشنده‌ها و سایر نقش‌ها `403` می‌گیرند. اگر می‌خواهید نقش‌های دیگر (مثلاً اپراتور) هم بتوانند، باید جدا هماهنگ شود.

## وضعیت‌ها

`draft` (پیش‌نویس خصوصی فروشنده) → `submitted` (در صف شما) → `approved` | `rejected`.
شما فقط `submitted`ها را تأیید/رد می‌کنید؛ هر عملی روی وضعیت دیگر خطای «فقط درخواست ارسال‌شده قابل بررسی است.» می‌دهد
(اگر دو ادمین هم‌زمان یک درخواست را تأیید کنند، فقط اولی موفق می‌شود و دومی همین پیام را می‌گیرد).

## ۱. فهرست صف

```http
GET /api/Admin/MissingProduct?status=submitted&storeId=&q=&pageNumber=1&pageSize=20
```

| پارامتر | توضیح |
|---|---|
| `status` | `submitted` \| `approved` \| `rejected` \| `draft`. **خالی = همه به‌جز پیش‌نویس‌ها** (پیش‌نویس خصوصی فروشنده است؛ فقط با `status=draft` صریح می‌آید). مقدار نامعتبر ← `code:1` |
| `storeId` | فیلتر یک فروشگاه |
| `q` | جست‌وجو در نام/برند |
| `pageNumber` / `pageSize` | پیش‌فرض ۱ / ۲۰؛ سقف `pageSize` = ۱۰۰ |

ترتیب: با `status=submitted` **قدیمی‌ترین ارسال‌شده اول** (صف FIFO)؛ بقیه جدیدترین اول.

```json
{
  "isSuccess": true, "code": 0, "messages": [],
  "data": {
    "items": [
      {
        "id": 12, "name": "شانه پلاستیکی سگ", "brand": "پت‌استایل", "packageSize": "بزرگ",
        "description": "جنس ABS", "price": 250000, "quantity": 12,
        "pictureUrl": "/Media/2026/9/19/abc.webp",
        "status": "submitted", "rejectionReason": null, "source": "shelf",
        "createdAtUtc": "2026-09-19T08:41:00Z", "productId": null,
        "storeId": 4, "storeName": "پت شاپ فرشته", "productItemId": null,
        "submittedAtUtc": "2026-09-19T09:02:10Z", "reviewedAtUtc": null,
        "similarProducts": null
      }
    ],
    "total": 17
  }
}
```

در فهرست `similarProducts` همیشه `null` است (برای سرعت)؛ فقط در جزئیات پر می‌شود.
`pictureUrl` مسیر نسبی است و با آدرس پایهٔ فایل (`https://file.pastil.pet`) کامل نمایش داده می‌شود.

## ۲. جزئیات یک درخواست + «محصولات مشابه در کاتالوگ»

```http
GET /api/Admin/MissingProduct/{id}
```

همان شکل بالا، با `similarProducts` (تا ۵ مورد) برای تشخیص سریع تکراری‌بودن:

```json
"similarProducts": [
  { "productId": 3120, "name": "شانه سگ پلاستیکی", "brandName": "پت‌استایل", "pictureUrl": "/Media/2025/3/2/x.webp" }
]
```

جست‌وجوی مشابه‌ها فقط کمک‌بررسی است؛ اگر خطا بدهد `[]` برمی‌گردد و خود درخواست نمایش داده می‌شود.
**تشخیص تکراری‌بودن نهایی با شماست** (مثلاً دو سایز یک محصول را سیستم خودکار تکراری حساب نمی‌کند). اگر تکراری بود،
«رد» کنید و در دلیل بنویسید کدام محصول موجود است.

پیشنهاد صفحه: تصویر بزرگ فروشنده؛ نام/برند/سایز/توضیحات؛ قیمت/موجودی پیشنهادی؛ نام فروشگاه؛ ردیف کارت‌های «مشابه در کاتالوگ» با لینک به محصول؛ دو دکمهٔ «تأیید» و «رد».

## ۳. تأیید

```http
POST /api/Admin/MissingProduct/approve
Content-Type: application/json
```

```json
{
  "id": 12,
  "name": "شانه پلاستیکی سگ پت‌استایل (بزرگ)",
  "productLabel": "dog-plastic-comb-petstyle",
  "categoryId": 87,
  "brandId": 21,
  "secondName": null,
  "summary": null,
  "description": null
}
```

| فیلد | الزام | توضیح |
|---|---|---|
| `id` | ✅ | شناسهٔ درخواست |
| `productLabel` | ✅ | **فقط حروف انگلیسی و اعداد** (فاصله/نقطه‌گذاری به `-` تبدیل می‌شود)؛ مبنای Slug/URL محصول است و **باید یکتا** باشد. حرف فارسی ← خطای «Label فقط می‌تواند شامل حروف انگلیسی و اعداد باشد.»؛ Slug تکراری ← «Slug ساخته‌شده تکراری است. مقدار Label را تغییر دهید.» (همان قواعد Label سایر محصولات) |
| `categoryId` | ✅ | دسته‌بندی کاتالوگ (از همان انتخابگر دستهٔ صفحهٔ محصولات). نامعتبر ← «دسته‌بندی انتخاب‌شده معتبر نیست.» |
| `brandId` | ❌ | برند کاتالوگ؛ اگر نامعتبر بود ← «برند انتخاب‌شده معتبر نیست.» |
| `name` | ❌ | نام رسمی؛ خالی = همان نام فروشنده (حداکثر ۲۰۰) |
| `secondName` / `summary` / `description` | ❌ | `description` خالی = توضیحات فروشنده |

**سرور موقع تأیید این کارها را می‌کند:**

1. درخواست را اتمیک «تأییدشده» می‌کند (از ساخت دوبارهٔ محصول جلوگیری می‌کند).
2. **محصول کاتالوگ** می‌سازد: وضعیت «موجود»، نوع «کالا»، فعال، با **تصویر همان فروشنده** به‌عنوان تصویر اصلی، بدون تنوع (Variety).
3. اگر فروشنده `price > 0` داده بود، **`ProductItem` همان فروشگاه** را با همان `price` (قیمت پایه) و `quantity` (پیش‌فرض ۰) می‌سازد (فعال).
4. اگر مرحلهٔ ۲ شکست بخورد، درخواست خودکار به `submitted` برمی‌گردد (چیزی نیمه‌کاره نمی‌ماند) و پیام خطا برمی‌گردد.

```json
{ "isSuccess": true, "code": 0, "messages": [],
  "data": { "productId": 5231, "storeItemCreated": true, "productItemId": 9812 } }
```

- `storeItemCreated:false` (بدون خطا) یعنی محصول کاتالوگ ساخته شد ولی آیتم فروشگاه نه: یا قیمت داده نشده بود، یا ساخت آیتم شکست خورد. در هر دو حالت محصول در کاتالوگ هست و فروشنده می‌تواند مثل هر محصول دیگری خودش قیمت/موجودی ثبت کند. به ادمین این را نشان بدهید.
- بعد از تأیید، جزئیات بیشتر (تنوع/ویژگی‌ها/تصاویر بیشتر/ابعاد ارسال/SEO) را از صفحهٔ معمول ویرایش محصول (`/api/Admin/Product`) تکمیل کنید؛ همان `productId` را باز کنید.

## ۴. رد

```http
POST /api/Admin/MissingProduct/reject
Content-Type: application/json
```

```json
{ "id": 12, "reason": "این محصول با «شانه سگ پلاستیکی» (کد 3120) تکراری است." }
```

`reason` الزامی و حداکثر ۵۰۰ کاراکتر است (فروشنده عیناً می‌بیند)؛ خالی ← «دلیل رد لازم است (حداکثر ۵۰۰ کاراکتر).». پاسخ: رکورد کامل با `status:"rejected"`.
فروشنده می‌تواند آن را اصلاح کند و دوباره بفرستد؛ دوباره در صف شما ظاهر می‌شود.

## کدهای خطا

| `code` | معنی |
|---:|---|
| 0 | موفق |
| 1 | ورودی/وضعیت نامعتبر (پیام فارسی روشن) |
| 3 | درخواست یافت نشد |

## نکات

- اعلان Push به فروشنده هنوز نیست؛ فروشنده وضعیت را با باز کردن صفحهٔ «محصولات ثبت‌نشده» می‌بیند.
- تأییدشده‌ها را می‌توان با `status=approved` مرور کرد؛ ستون `productId` لینک به محصول کاتالوگ است.
- `createdAtUtc`/`submittedAtUtc`/`reviewedAtUtc` همه UTC با `Z`اند؛ برای نمایش به تاریخ شمسی/منطقهٔ زمانی محلی تبدیل کنید.
